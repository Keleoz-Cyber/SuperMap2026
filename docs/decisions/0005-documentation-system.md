# ADR-0005 文档体系：单一事实归属与测试治理

- 状态：已接受
- 日期：2026-08-15
- 取代：单一 project-guide.md 集中式说明（e22a716 引入）

## 背景

项目曾把 3,368 行历史文档合并为 `docs/project-guide.md`（唯一权威）+ `docs/项目特色与技术全景.md`（知识底稿）双文档结构。2026-08-15 审计发现：两份文档双份维护同一事实已产生实际错误（瓦斯内置源文件名在两处均写错、首版便携包版本归属前后不一、屏幕适配边界停留在旧版本），且 `docs/data|decisions|status/` 留下未跟踪空目录。教训是"集中"不等于"防漂移"——同一事实只要存在两份拷贝，就必然漂移。

## 决策

- 文档体系改为四层：权威文档（根 README、CHANGELOG 与 docs 下五份核心文档）/ 技术决策记录（decisions/，只增不改）/ 过程档案（superpowers/）/ 验收证据（evidence/，只增不改）。规范与索引见 [docs/README.md](../README.md)。
- **单一事实归属**：每个事实只在一份权威文档记载，其他文档只链接。归属表：版本演进->CHANGELOG；案例指标与操作->product-guide；架构/算法/验证/渲染合同->architecture；命令与环境变量->api-reference；运行/发布/排障->operations；演示与提交->contest。
- **文档受测试治理**：文档结构、关键合同关键词、相对链接可达、禁本机路径由合同测试锁定（`tests/test_demo_docs.py` 及各版本合同测试），改文档必须跑测试。
- **目录即合同**：有非显而易见约定的目录必须带 README。
- 本次重构：project-guide.md 拆解为 product/architecture/operations/contest 四份与 api-reference；全景文档拆解吸收后删除；decisions/ 复活为 ADR；错误事实（瓦斯文件名 `瓦斯含量_合格样品.csv`、首版便携包 v0.9.1、屏幕适配现状）随重构修正。

## 后果

- 正面：事实单点维护，漂移在结构上被抑制；合同测试防止结构腐化与泄密；受众分流（用户/开发者/评测各取所需）。
- 代价：文档数量增加，跨文档一致性依赖测试而非人工；新增事实必须先确定归属再落笔。
- 复盘义务：发现事实性偏差立即修正权威文档并同步测试，不允许"下次一起改"。
