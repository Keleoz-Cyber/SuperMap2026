# v0.8.0 第三批：瓦斯预置案例与案例数据内置化设计

## 目标

将瓦斯含量作为第三个可演示的 `builtin_preset` 案例接入统一平台链路，并把微震、电阻率、瓦斯三个官方案例的规范化源文件统一放到项目内 `example_data/`。第三批只解决数据来源、案例链路、差异化基础分析和真实体渲染验收，不接入 AI/iServer，也不重做 v0.9.0 的分析中心视觉。

## 产品入口与身份

瓦斯从首页开始与微震、电阻率共用卡片和工作台：

```text
首页 → 瓦斯含量案例 → 案例工作台 → 数据版本 → 新建实验/官方成果 → 结果工作台
```

瓦斯卡片必须是 `source_kind=builtin_preset`、`workspace_kind=builtin_preset`、只读官方预置；不出现 DAT 导入、legacy、iServer、暂缓或点云回退文案。数据文件只在构建/seed 侧使用，浏览器响应不得泄露绝对路径。

## 后端架构

1. 新增与 `microseismic_preset.py`、`resistivity_preset.py` 对齐的 `gas_preset.py`，负责源合同校验、标准化数据物化、幂等 seed、官方成果登记和失败补偿。
2. 抽取或复用项目根目录解析器，使三个预置源都从 `example_data/` 解析；环境变量或测试 fixture 可以覆盖路径，但公共 DTO 只输出逻辑来源和哈希。
3. 瓦斯使用 `analysis_profile=gas_content`，在 `analysis/profiles.py` 中声明属性名、单位、通用模块和瓦斯专属模块。
4. 插值候选先跑 IDW 与普通克里金；DSI-like 只有在有限公共有效集、交叉验证指标和规则网格物化均通过时才发布为候选。任何失败均 fail-closed，不创建伪成功成果。
5. 官方基线由真实数据和确定性空间折分计算后冻结为 JSON 指纹；不得手工插入 grid、NetCDF、candidate 或 FormalSelection 行冒充 seed。

## 瓦斯差异化分析

第三批只增加后端真实载荷和必要的现有面板接线，0.9 再做完整视觉重构。瓦斯 profile 至少提供：

- 含量分布、分位数和有效样本质量；
- Z 方向分层统计（层内均值、p75/p95、样本数）；
- XY 高/低含量区域（默认使用非空单元均值 p25/p75，明确为探索性分位口径）；
- 空间梯度与采样覆盖；
- 已有候选模型的有限指标对比。

结论只使用“高值区域/低值区域/样本稀疏/交叉验证误差”等可计算表述；除非另有权威阈值来源，不输出“瓦斯危险/安全”等规范判断。

## 渲染与交互

- 结果必须进入现有 NetCDF 原生体渲染链，不能回退到点云作为体渲染替代。
- 规则网格范围必须由瓦斯数据 bounds 和网格合同推导，Volume 包围盒与 X/Y/Z Slice 共用同一 bounds；Slice 只在切片模式显示。
- 必须验收 Volume、X/Y/Z Slice、Contour、光照/渐变透明度、色带、透明度、普通刷新和 warm-cache。
- 稀疏 58 点数据若某模式无法稳定渲染，必须显示类型化失败原因并保留数据分析结果；禁止把空白 iframe 标记为 rendered。

## 不在本批范围

- AI 预测、iServer 机器学习 REST；
- 真实 CRS 配准、跨案例空间叠加；
- 0.9 分析中心视觉重做、结论看板和答辩布局；
- iServer/S3M 自动发布；
- 物理删除旧资产。

## 验收门

### 数据与后端

- 三个 `example_data` 文件存在、哈希和行数合同通过；外部旧路径不再作为默认源；
- 瓦斯案例卡、workspace、analysis-summary、analysis-export 均返回 `gas_content` 和 `ml/g`；
- seed 幂等、并发、失败补偿和只读正式选择保护通过；
- IDW/Kriging 候选至少一条成功并可物化；DSI-like 只能在真实门通过时出现。

### 前端与真实 SDK

- 首页三案例统一入口；无 DAT/legacy/暂缓文案；
- Mock E2E 覆盖首页→工作台→成果/分析；
- 真实 GPU live 门覆盖瓦斯 Volume、X/Y/Z Slice、Contour 和缓存升级；
- 桌面 1440×900 与移动 390×844 无横向溢出、无黑屏、无协议超时；
- 证据 JSON 的 `git_commit` 指向测试代码祖先，证据提交只包含 `docs/evidence/`。
