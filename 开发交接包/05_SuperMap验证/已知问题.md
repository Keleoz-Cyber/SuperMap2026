## 1. 当前结论

SuperMap 已经能够完成本项目的三维点导入、普通克里金体元构建、验证点预测导出、完整体元显示、水平切片和阈值异常过滤。其能力足以承担 MVP 的空间数据管理和三维表达。

当前不能宣布“完整三维成果链全部通过”：原生剖切显示存在空白现象，原生等值面提取连续失败，且正式体元 X 向只有 7 个单元。系统必须将这些限制明确显示，而不是用截图掩盖。

选型解释：

- `Kriging 20m/40点` 的 MAE、中位绝对误差和平均相对误差最佳，作为默认展示模型；

- 10m 加密没有提高验证精度，不作为正式候选；

## 5. 已知问题明细

### SM-01：RHO 字段可能被导入为文本

**现象**：分段表达式中只有 `SmID`、`SmUserID`，没有 RHO；更新列表达式使用字段别名“电阻率数值”时报 `no such column: 电阻率数值`。

**原因**：CSV 导入时 RHO 没有作为数据集数值字段保留，或后续 SQL 使用了字段别名而不是真实字段名。

**当前处理**：重新按空间数据导入 X/Y/Z；必要时增加双精度字段 `RHO_NUM`，使用真实字段 `RHO` 转换赋值。

**产品要求**：代码读取数据集结构并保存真实字段名与别名映射；禁止把显示别名拼入 SQL。

### SM-02：预测结果存在 241 个共同 NoData

**现象**：五个模型的验证点导出均有 241 个 `Attribute=-9999`，公共有效点为 1,481。

**分布**：240 个无值集中在四根完全无覆盖空间柱，另有一根空间柱包含 1 个无值点。

**当前处理**：保留 NoData 掩膜，在公共有效点上比较模型。

**禁止处理**：不得将 `-9999` 纳入误差统计、颜色分级或再次插值，也不得为提高覆盖率而静默填值。

### SM-03：原生“剖切显示”出现空白

**现象**：启用体元图层原生剖切后，场景可能只显示外框或没有有效体元内容。

**当前规避**：使用“显示范围”的归一化 X/Y/Z 最小值与最大值控制薄切片。水平薄切片已经验证，垂直方向仍需形成可重复参数记录。

**状态**：规避方案可用，但不能据此宣称原生剖切控件完全正常。

### SM-04：原生等值面提取失败

**尝试一**：最小值 77、最大值 133.146，输出 `RHO_ISO_HIGH_P95_K40`。

**尝试二**：最小值 77、最大值 77，输出 `RHO_ISO_77_K40`。

**共同结果**：工具报错：

```text
Failed to extract continuous surface, please check IsoValue.
```

日志同时出现对象为空相关提示。两个输出数据集为空，打开后无对象，不能作为成果。

**当前推断**：`RHO >= 77` 高值区在画面上接触体元顶部、底部或侧边界，可能无法形成工具需要的连续封闭表面；正式体元 X 向只有 7 个单元也降低了几何表达能力。这是根据当前画面和一致错误得到的推断，不是已确认的产品内部规则。

**下一验证路线**：

1. 在六个外表面增加 1—2 层低于 77 的边界体元，生成新模型 `RHO_KRIG_FINAL_20M_40_PAD1`；
2. 保持原始模型不变，在补边模型上重新测试 77 单值等值面；
3. 若仍失败，导出规则三维数组并使用 Python marching cubes 生成独立网格；
4. 将外部网格作为派生展示成果，并保留阈值、网格间距、补边规则和输入哈希。

上述路线均为待验证方案，当前状态不是“已解决”。

### SM-05：体元 X 向分辨能力有限

**现象**：正式体元只有 7 行，异常体在 X 方向呈块状或贴边。

**影响**：可用于证明三维链路和展示大体趋势，不足以解释为精确异常边界或地质界面。

**当前处理**：保留 20m/40点作为验证选出的主模型，不因视觉需求改用精度更差的 10m/40点。

### SM-06：失败输出数据集容易混入成果列表

**现象**：即使提取等值面失败，数据源中仍可能留下同名空数据集外壳。

**当前处理**：`RHO_ISO_HIGH_P95_K40` 和 `RHO_ISO_77_K40` 标记为失败/空结果。

**产品要求**：成果登记时检查运行状态、对象数和可打开性；空对象必须为 `failed`，不得进入默认场景或导出清单的正式成果部分。

## 7. 开发接入建议

- 第一版代码通过配置登记 SuperMap 数据源和数据集，不尝试直接自动点击所有 iDesktopX 控件。
- 优先开发 CSV/JSON 校验、任务状态、质量指标和成果索引；这些能力不依赖 SuperMap UI 自动化。
- 与 SuperMap 的深度集成可以按能力逐步增加：先读写标准交换文件，再评估 iObjects/GPA/Python 环境。
- 所有 UI 自动化步骤都必须有失败检测和对象完整性检查，不能以“按钮已点击”作为任务成功条件。
