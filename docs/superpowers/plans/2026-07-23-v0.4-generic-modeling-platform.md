# GeoModelingPlatform v0.4 Generic Modeling Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏 v0.3.1 电阻率答辩演示的前提下，实现“创建案例 → 上传 CSV/XLSX → 字段映射与质量门禁 → 2D/3D IDW/普通 Kriging 调参与空间验证 → 排行榜 → 正式选择 → 完整场与水平/X/Y 切片 → 成果包与可选 iServer 发布”的 v0.4.0 通用建模闭环。

**Architecture:** 保持 FastAPI + Vue 3 的模块化单体。新案例使用 SQLite 保存业务状态、受控目录保存不可变原始文件与结果工件；单进程后台 Worker 执行有限候选任务。算法、API、Worker 和前端共用同一组 Pydantic/TypeScript 契约。现有电阻率 API 与三维页面作为只读兼容适配器保留，新流程稳定后再考虑迁移历史数据。

**Tech Stack:** Python 3.12、FastAPI、Pydantic 2、SQLAlchemy 2、SQLite、pandas、NumPy、SciPy、PyArrow、openpyxl、Vue 3、TypeScript、Element Plus、ECharts、SuperMap iServer/iClient3D、pytest、Vitest。

## Execution rules

- 每一任务都先写失败测试，再写最小实现，再运行任务级测试，最后提交；不要把多个任务压成一个巨型提交。
- Portable CI 不读取真实资料、UDBX、S3M 缓存或本机 iServer。真实数据回归和 live iServer 验证继续使用独立标记。
- `var/geomodeling/` 是默认运行目录并加入 `.gitignore`；测试只能使用 `tmp_path`/临时目录。
- 原始上传只写一次；字段映射、标准化、建模和导出都生成新工件，不覆盖原文件。
- 任何警告确认、正式模型选择、发布尝试和失败候选都必须保留证据。
- API 错误统一返回 `{"error":{"code","message","details"}}`，`details` 不包含本机绝对路径。
- FastAPI v0.4 仅支持单进程部署；启动两个 Uvicorn worker 会造成内存任务队列重复，运行手册必须明确 `--workers 1`。

    TWO_D = "2d"

    QUEUED = "queued"
    RUNNING = "running"
    SUCCEEDED = "succeeded"
