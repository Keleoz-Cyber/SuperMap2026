## 1. 一句话认识项目

GeoModelingPlatform 是一个面向地质空间属性数据的浏览器建模平台：用户可以选择内置案例或上传 CSV、Excel、微震 DAT 数据，经过字段映射、质量校验、算法调参、空间交叉验证和模型比较，生成可追溯的二维或三维属性场，并在 SuperMap 三维环境中查看完整体、等值面与 X/Y/Z 切片，最后导出模型、统计和证据材料。

它不是单独的“插值脚本”，也不是只播放预制模型的“三维展示网页”。项目真正解决的是：

```text
原始数据是否可信
  → 数据是否适合某种算法
  → 参数如何调整
  → 模型是否经过公平验证
  → 结果如何形成三维成果
  → 结论如何解释
  → 整个过程如何复核与追溯
```

## 2. 项目要解决的实际问题

传统地质空间建模往往分散在多个环节中：研究人员手动整理表格，在不同软件里试验插值，再截图展示结果。这个流程容易出现几类问题：

1. 原始数据、清洗数据和建模数据混在一起，来源无法追溯；
2. 坐标系、单位、深度方向不明确时仍被强行建模；
3. 只看“图像是否平滑”，没有独立验证数据和误差指标；
4. 不同算法使用了不同有效点，却直接比较 RMSE；
5. 同一 XY 柱的不同深度样本被随机分到训练集和验证集，形成空间泄漏；
6. 算法能运行就被当成适用，没有检查样本量和独立空间组；
7. 三维显示、切片、统计和模型数据不是同一成果；
8. 软件运行失败时静默回退成点云或空图，容易造成错误结论；
9. 最终报告只有截图，缺少数据哈希、参数、指标和导出证据。

GeoModelingPlatform 将这些环节统一到一套明确的数据合同和证据链中，使“结果看起来合理”进一步变成“结果的来源、过程、限制和可信程度都能说明”。

## 6. 数据生命周期与可追溯设计

### 6.1 生命周期

```text
原始文件
  → SourceManifest：文件名、大小、SHA-256、来源
  → DatasetVersion：字段、单位、坐标、版本
  → 质量门禁
  → Experiment：建模目的
  → Run：不可变参数快照
  → CandidateResult：折外预测、指标、网格、工件
  → FormalSelection：正式选择和理由
  → Materialized Result / RenderAsset
  → Export / PublicationEvidence
```

### 6.2 关键原则

1. **原始资料只读**：派生数据不会覆盖源文件；
2. **来源可核验**：源文件、关键工件、网格和证据都有 SHA-256；
3. **参数不可变**：运行创建后，参数快照不可被悄悄修改；
4. **无证据不猜测**：不知道 EPSG、单位或 Z 方向时显式标记未知；
5. **NoData 不等于 0**：无效 token、缺失值和真实零值分别处理；
6. **读取时复核**：候选比较、正式选择和导出前再次核对文件大小与哈希；
7. **补偿事务**：数据库写入和文件落盘任一步骤失败，都清理本次残留，同时保留最初业务错误；
8. **敏感信息不外泄**：公开 API、日志、SQLite、ZIP 和错误消息不保存本机绝对路径或 API Key；
9. **失败关闭**：证据不完整或身份不一致时拒绝输出，而不是带病继续。

### 6.3 特殊数据约定

- 历史 SuperMap 电阻率导出中的 `Attribute=-9999` 仅在适配层转换为 `null + is_nodata=true`；
- 微震 `1.#QNAN0` 保留原 token、源文件和源行，不改成 0；
- 重复 XYZ 只有在明确的领域规则下才聚合，并保留组内完整来源；
- 私有论文、未授权数据、UDBX、运行数据库、许可证和密钥不进入公开仓库。

## 7. 插值与预测算法

### 7.1 IDW 反距离加权

IDW 的基本思想是“距离预测位置越近的样本，权重越高”：

\[
\hat z(x_0)=\frac{\sum_i w_i z_i}{\sum_i w_i},\qquad
w_i=\frac{1}{d(x_0,x_i)^p}
\]

平台支持：

- 二维和三维距离；
- 幂次 `power`；
- 邻域点数；
- Z 轴缩放 `z_scale`；
- 经过人工确认的各向异性旋转邻域；
- 规则输出网格和 NoData 管理。

优点是原理直观、速度较快、参数易理解；局限是容易出现样本点周围的“靶心效应”，不能像克里金一样直接提供地统计估计方差。

### 7.2 普通克里金

普通克里金使用样本间的空间相关结构求权重：

\[
\hat z(x_0)=\sum_i\lambda_i z(x_i),\qquad \sum_i\lambda_i=1
\]

权重不是只由距离倒数决定，而是由经验半变异函数及其拟合模型共同求解。平台支持：

- 球状模型（spherical）；
- 指数模型（exponential）；
- 高斯模型（Gaussian）；
- 自动拟合候选；
- 人工输入块金值 `nugget`、基台值 `sill`、变程 `range`；
- 邻域点数、旋转邻域和各向异性；
- 克里金估计标准差。

克里金能够利用空间自相关信息，但“变异函数拟合 SSE 最小”不等于“空间验证误差最小”。因此平台把变异函数拟合与空间交叉验证分开，最终仍以独立折外预测评价候选。

### 7.3 DSI-like 离散平滑插值

项目实现的是 `DSI-like`，不是商业 GOCAD/SKUA 的完整 DSI。其工程路线是：

1. 先用 IDW 生成规则网格初始场；
2. 在离散邻域上迭代平滑；
3. 每轮恢复原始观测节点的硬约束值；
4. 达到迭代次数或收敛条件后输出结果；
5. 任一步失败都明确报错，不改用 IDW 冒充 DSI-like 成功。

它的价值是提供区别于纯距离加权和概率地统计模型的平滑约束路线，同时可以直观演示迭代次数、平滑强度、邻域和硬约束的影响。

必须使用 `DSI-like` 或“离散平滑近似”这个名称。只有在同一数据、同一网格、同一约束和盲测集上与 GOCAD 结果进行实测比较后，才可讨论两者的数值接近程度。

### 7.4 随机森林空间回归

平台将坐标和可用的空间派生特征输入随机森林回归器，通过多棵树的集成预测空间属性。实现包括：

- 确定性随机种子；
- 与其他算法共用空间折分；
- 折外预测和公共有效集指标；
- 完整规则网格预测；
- 树模型分歧形成 `model_dispersion` 辅助字段；
- 样本数、独立空间组和折数适用性门。

`model_dispersion` 表示树之间的预测分歧，不是概率置信区间，也不能直接解释为风险概率。

### 7.5 克里金残差随机森林

该方法先用普通克里金描述主要空间趋势，再使用随机森林学习克里金残差：

\[
\hat z_{final}=\hat z_{kriging}+\hat r_{RF}
\]

为了防止泄漏，随机森林训练使用的是内部折外克里金残差，而不是让验证样本参与形成自己的残差基线。成果可以包含：

- `prediction`：最终预测；
- `kriging_baseline`：克里金基线；
- `residual_correction`：残差校正量；
- `model_dispersion`：树模型分歧。

这种融合不保证一定优于普通克里金。真实电阻率验收中，残差校正结果反而变差，系统会如实显示“未优于普通克里金”，不会为了突出机器学习而强行推荐。

## 8. 空间验证与模型评价

### 8.1 为什么不用普通随机拆分

三维地质数据常在相同 XY 位置沿 Z 方向密集采样。若逐行随机拆分，同一柱中的相邻深度点可能同时出现在训练集和验证集，模型相当于提前看到了验证位置附近的信息。

平台按完整 XY 柱或明确空间组进行折分，使同一柱只能进入训练侧或验证侧，从而降低空间泄漏。

### 8.2 公共有效集

不同算法可能因邻域、NoData 或数值问题产生不同有效预测点。若每个模型各用自己的有效点计算指标，结果不可直接比较。

平台先求所有候选共同有效的记录集合，再在同一集合上复算指标，这就是 `common-valid mask`。同时保存数据版本、折分指纹和验证目标，跨实验比较不兼容时直接拒绝。

### 8.3 指标解释

| 指标 | 含义 | 趋势 |
|---|---|---|
| RMSE | 均方根误差，对较大误差更敏感 | 越低越好 |
| MAE | 平均绝对误差，直观表示平均偏差幅度 | 越低越好 |
| R² | 对目标变化的解释程度，可能为负 | 越高越好 |
| Bias | 平均有符号误差，反映整体高估或低估 | 越接近 0 越好 |
| Median ARE | 绝对相对误差的中位数 | 越低越好，真值接近 0 时谨慎 |
| Coverage | 验证点中成功产生预测的比例 | 越高越好 |
| Valid / NoData | 有效预测数与缺失预测数 | 用于解释指标样本口径 |

模型排名不是只看一个数值。系统同时检查：

- 数据和验证合同是否一致；
- 公共有效点是否足够；
- 覆盖率是否可接受；
- 模型是否通过适用性门；
- 专业诊断是否支持当前参数；
- 结果是否稳定、可解释；
- 复杂模型是否真正优于简单基线。

## 9. 专业地统计特色

### 9.1 方向半变异函数

平台既计算全向经验半变异函数，也能按方位角和倾角检查不同方向的空间变化。方位角在 XY 平面中由 +X 指向 +Y，范围为 `[0°, 180°)`；倾角范围为 `[-90°, 90°]`。

点对超过 50,000 时，不是随意截断，而是按距离层和方向层进行确定性抽样。抽样种子由数据 SHA-256 和配置派生，并在证据中披露采样率。

### 9.2 各向异性确认

系统可以根据方向变异函数给出各向异性候选，但不会直接将建议当成地质事实。用户必须人工确认，确认后形成不可变参数快照。

坐标变换使用：

\[
x'=S R^T x
\]

其中 `R` 表示旋转，`S` 表示各轴尺度。确认后的变换可同时用于邻域搜索和插值距离计算。

### 9.3 不确定性与经验误差

- 克里金标准差来自克里金系统：`σ² = λᵀγ₀ + μ`；
- 经验误差尺度由折外残差在显式邻域中的距离加权局部 RMSE 得到；
- 两者描述的含义不同，均不能直接写成“发生灾害的概率”。

### 9.4 异常连通区域

系统使用明确阈值提取异常单元，并按二维 4 邻接或三维 6 邻接形成连通区域。它适合表达“满足阈值且空间相连的模型区域”，但不能直接等同于真实危险区、矿体边界或储量。

| 微震波速 | 2,006 源记录 → 1,925 黄金候选 → 1,911 节点 | Vx，km/s | 领域清洗、局部几何、插值与实验性 RF | 仅 22 个 XY 组，无绝对 CRS/方位角 |
| 瓦斯含量 | 58 个样品、28 个 XY、58 个 XYZ | CH4_content，ml/g | 稀疏样本适用性门与谨慎解释 | R² 为负，ML 被拒绝，不适合高置信结论 |

### 10.1 地下电阻率案例

内置文件为 `地下电阻率节点_标准化.csv`，字段为 `X,Y,Z,RHO`。坐标全部唯一且有限，RHO 范围约为 1.032113–149.984 Ω·m，Z 向下为负。

历史数据分层为：

- 训练集 15,827 行；
- 验证集 1,722 行；
- 训练/验证空间柱 264/29，重叠 0；
- 历史五模型公共有效 1,481；
- NoData 241；
- SuperMap 导出 XY mismatch 为 0。

冻结普通克里金基线为 exponential、neighbor=24，RMSE=6.454476；正式规则网格为 `7×23×42=6,762` 个单元，网格间距 20 m。

真实机器学习空间验证证据：

| 候选 | 公共有效点 | RMSE | MAE | R² | Bias | 结论 |
|---|---:|---:|---:|---:|---:|---|
| 随机森林 | 17,549 | 5.546855 | 2.464957 | 0.943222 | -0.079344 | 本轮优于同折普通克里金 |
| 同折普通克里金 | 17,549 | 6.468625 | — | — | — | 机器学习比较基线 |
| 克里金残差随机森林 | 17,549 | 7.326515 | 3.841685 | 0.900943 | -0.196885 | 比同折克里金 RMSE 变差 13.26%，不推荐 |

这组结果体现了平台的一个重要特点：机器学习可以纳入比较，但系统不会预设“机器学习一定更好”。

### 10.2 微震波速案例

微震正式来源为 22 个 DAT 文件：

- 2,006 条源记录；
- 2,005 条有限数值记录；
- `W8.dat` 中唯一的 `1.#QNAN0` 保留并排除；
- `depth_m = WL_half_km × 1000`；
- `z_local_m = -depth_m`；
- Vx 单位为 km/s；
- 全局一次 3σ，样本标准差 `ddof=1`；
- 剔除 80 条，其中深度异常 72、速度异常 8；
- 得到 1,925 条黄金候选；
- 相同 XYZ 算术平均聚合后得到 1,911 个唯一建模节点；
- 13 个冲突组、27 条组内记录、坍缩 14 条。

黄金候选和剔除表均有冻结哈希，任一不一致即停止导入。绝对原点、测线方位角和 CRS 没有可靠证据，因此这些坐标只能用于本案例局部建模，不能和电阻率或瓦斯直接叠加。

真实随机森林证据：公共有效 1,911，RMSE=0.250364、MAE=0.202911、R²=0.864338、Bias=0.047494。由于只有 22 个独立 XY 空间组，该结果始终标记为“实验性对照”，不能据此宣称稳定泛化。

### 10.3 瓦斯含量案例

内置数据为 `煤层瓦斯三维插值点_合格58.csv`：

- 58 条合格样品；
- 28 个 XY 采样位置；
- 58 个唯一 XYZ；
- 字段 `X,Y,Z,CH4_content`；
- 局部线性米制坐标，无 EPSG；
- 属性单位 ml/g。

冻结普通克里金基线为 spherical、neighbor=24，RMSE=8.298439、MAE=6.552100、R²=-0.109659、Bias=-0.068618。R² 为负说明该模型在当前空间验证下甚至没有表现出稳定的解释能力，因此平台只把三维场作为稀疏样本条件下的探索性表达，并拒绝机器学习建模。

历史上该数据在 iDesktopX 中加载 IDW 体元时曾触发原生闪退。这个现象只能说明特定数据、缓存、渲染或软件环境组合存在问题，不能反推插值数值一定错误，也不代表当前 NetCDF 浏览器渲染链不可用。

## 11. 三维成果与 SuperMap 技术路线

### 11.1 当前正式渲染链

```text
CandidateResult 规则网格
  → NetCDF classic/v3 RenderAsset
  → 隔离 iframe
  → SuperMap3D VoxelGridLayer3D
  → Volume / Contour / X Slice / Y Slice / Z Slice
```

RenderAsset 记录：成果 ID、数据版本、网格哈希、维度、X/Y/Z 坐标、变量、单位、值域、NoData 和显示锚点。这样能保证三维画面、切片、统计和导出引用的是同一份成果。

### 11.2 三维表达能力

- **Volume**：展示完整三维属性场；
- **Contour**：展示指定阈值附近的空间结构；
- **X/Y/Z Slice**：按真实模型坐标移动单轴切片；
- **色带与透明度**：调整属性值的视觉映射；
- **阈值过滤**：突出高值或异常范围；
- **相机和包围盒**：帮助理解局部坐标的方向、深度和尺度；
- **辅助点层**：显示观测节点或模型证据，但不冒充体场。

切片统计由后端权威 API 计算，合同为 `slice-analysis/v1`；标准差字段明确为总体标准差 `std_population`。前端图表 PNG 标记来源为 `client_echarts_canvas`。

### 11.3 父页面与渲染 iframe 协议

父页面使用 `gmp-supermap-volume/v2` 协议向 iframe 发送成果状态，状态带单调递增的 `revision`。iframe 拒绝旧状态，并回传：

- SDK 能力；
- 渲染成果身份；
- 当前模式和切片状态；
- 相机状态；
- 成功或失败诊断。

只有身份和渲染回执同时匹配，页面才能标记成果已加载。

### 11.4 no silent fallback

三维渲染失败时，系统必须显示具体诊断，不允许偷偷切换到点云、包围盒或静态图片再宣称“体渲染成功”。

历史 v0.3 路线曾将 iDesktopX 体元缓存解析成 7,056 个采样点，并用 `PointPrimitiveCollection` 显示；它解决了旧版 iClient3D 无法遍历瓦片的问题，但那是兼容降级点元表达，不是连续原生体渲染。当前正式路线已经转为 NetCDF RenderAsset 与 `VoxelGridLayer3D`。

为了避免夸大，可以表述为“基于 SuperMap3D VoxelGridLayer3D 的三维体元/体场表达”。不要表述成“在所有计算机上均已证明为原生 GPU 连续体渲染”，目标设备的 SDK、显卡和驱动仍需要现场验收。

### 11.5 iServer 的角色

iServer 是可选的服务发布与表达层，不是建模主链的强依赖：

- iServer 在线时，可以提供数据、地图、三维服务和发布证据；
- iServer 离线时，上传、质量校验、插值、空间验证、比较、NetCDF 和浏览器成果仍可运行；
- 通用成果自动发布目前默认 `manual_required`；
- 没有实时对象级证据时，不得把发布状态标记为成功。

官方文档：

- [SuperMap iServer 帮助](https://help.supermap.com/iServer/1201/zh/)
- [SuperMap iDesktopX 帮助](https://help.supermap.com/iDesktopX/zh/)

## 12. 成果分析、规则与 AI

### 12.1 成果级分析

成果工作台不仅显示模型，还能围绕正式成果生成：

- 基本统计与分位数；
- 直方图和分布；
- X/Y/Z 空间剖面；
- 观测与折外残差分析；
- 高值、低值和异常连通区域；
- 模型参数、指标和适用性；
- 来源数据、折分、公共有效集和工件哈希；
- JSON、CSV、图片、NetCDF 和 ZIP 证据。

三维场、切片和分析页面之间保留成果身份，避免对一个模型看图、却对另一个模型统计。

### 12.2 确定性规则优先

系统首先使用可复核的确定性规则生成结论。成果页的“地质研判”不再只罗列统计指标，而是把同一成果网格中的异常连通区组织为：

```text
数值事实 → 可能解释 → 潜在影响 → 建议核查
```

其中电阻率同时识别低阻与高阻异常，微震案例解释低速与高速介质结构，瓦斯案例优先展示高含量异常。研判卡与三维场共享稳定组件 ID，可直接定位；高值为暖色、低值为冷色。技术阈值、切片和模型验证细节默认折叠，但始终可追溯。

规则还包括：

- 数据是否通过质量门；
- R² 是否为负；
- 覆盖率和公共有效数是否充足；
- 复杂模型是否真正优于基线；
- 是否存在较大 Bias；
- 结果是否只允许实验性解释；
- 哪些结论因 CRS、样本稀疏或空间组不足而受限。

即使没有外部 AI，这部分仍能正常运行。

所有属性解释均受版本化规则和证据边界约束。当前高低异常来自完整成果网格 p25/p75，只能作探索性解释：低阻不能直接认定为含水区；速度异常不代表微震事件活跃度或已确认断层；高瓦斯含量分位不等于法定危险等级。自定义属性无法匹配受控规则时安全降级为通用数值分析。

### 12.3 DeepSeek 辅助研判

DeepSeek 只接收平台生成的结构化 `EvidencePacket`，用于把指标、质量、异常和限制整理为更容易阅读的解释。它不是插值算法，也不决定正式模型。

适配器特点：

- API Key 只从服务端环境变量读取；
- 使用 OpenAI-compatible Chat Completions；
- 请求 JSON 模式，温度为 0；
- 对未配置、超时、限流、HTTP 错误、空响应、截断和非法 JSON 返回类型化诊断；
- AI 失败不会破坏确定性分析、建模或成果导出；
- Key 不进入浏览器、日志、SQLite、导出包和 Git。

## 13. DeepSeek API 配置方法

本节适用于 Windows 免安装包。正式产品路径是在浏览器右上角打开“AI 设置”；命令行环境变量只保留给开发、CI 和管理员临时覆盖。

### 13.1 产品内配置（推荐）

1. 启动平台，在右上角点击“AI 设置”；
2. 输入自己的 DeepSeek API Key，模型默认选择 `deepseek-v4-flash`；
3. 点击“测试连接”，确认鉴权与网络可用；
4. 点击“保存配置”。保存后无需重启即可生成 AI 辅助研判；
5. Key 保存于当前 Windows 用户的 Generic Credential，页面只显示“已配置”，不会回显完整 Key。

平台只允许 DeepSeek 官方 HTTPS 服务地址。清除密钥可在同一弹窗完成。环境变量存在时，其优先级更高且页面配置为只读。

### 13.2 管理员临时启动（关闭窗口后配置失效）

1. 完整解压 `GeoModelingPlatform-1.0.0-win-x64.zip`；
2. 先运行 `停止平台.cmd`，确保旧进程已经关闭；
3. 在解压目录的地址栏输入 `cmd` 并回车；
4. 在打开的 **CMD** 窗口逐行执行：

```cmd
set "DEEPSEEK_API_KEY=在这里填写自己的APIKey"
set "DEEPSEEK_BASE_URL=https://api.deepseek.com"
set "DEEPSEEK_MODEL=deepseek-v4-flash"
set "DEEPSEEK_TIMEOUT_SEC=90"
set "DEEPSEEK_MAX_TOKENS=4096"
GeoModelingPlatform.exe start
```

只有 `DEEPSEEK_API_KEY` 是必填项，其余变量是当前源码默认值，可以省略：

```cmd
set "DEEPSEEK_API_KEY=在这里填写自己的APIKey"
GeoModelingPlatform.exe start
```

启动后打开成果分析或 AI 辅助研判功能验证。若页面显示 `DEEPSEEK_NOT_CONFIGURED`，通常表示环境变量没有传给当前运行进程，应先停止平台，再从同一个已设置变量的 CMD 窗口重新启动。

### 13.3 变量说明

| 环境变量 | 必填 | 当前默认值 | 作用 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | 是 | 无 | DeepSeek API 凭据 |
| `DEEPSEEK_BASE_URL` | 否 | `https://api.deepseek.com` | API 根地址 |
| `DEEPSEEK_MODEL` | 否 | `deepseek-v4-flash` | 请求模型 ID |
| `DEEPSEEK_TIMEOUT_SEC` | 否 | `90` | 请求超时秒数 |
| `DEEPSEEK_MAX_TOKENS` | 否 | `4096` | 最大输出 token |

如果账户或接口返回“模型不存在/不可用”，应将 `DEEPSEEK_MODEL` 改为该账户实际支持的模型 ID，不能只根据文档猜测。当前项目源码的默认值是 `deepseek-v4-flash`。

### 13.4 安全要求

- 不要把真实 Key 写进 Markdown、源码、`.env.example`、启动脚本或截图；
- 不要把团队自己的 Key 打进免安装包；每台评测机使用操作者自己的 Key；
- 不要将带 Key 的 CMD 窗口录进演示视频；
- 不要把 Key 发给评委或随 ZIP 分发；
- Key 泄露后立即到服务商后台撤销并重新生成；
- 没有 Key 时直接使用确定性规则分析，系统主链不会中断。

## 14. 项目可靠性与工程化特色

### 14.1 失败关闭而不是带病运行

平台在以下情况会拒绝继续：

- 数据合同或字段映射不满足要求；
- 来源哈希、黄金表或候选工件哈希不一致；
- 空间组不足或折分不可行；
- Run 或 CandidateResult 未成功却尝试正式选择；
- 候选数据版本、验证目标或折分不兼容；
- 三维资产身份、网格或值域不一致；
- S3M 历史兼容缓存不符合已固定合同；
- 外部服务身份与预期不符。

### 14.2 真实、Mock 和本机证据分层

- pytest 验证后端数据合同、算法和异常路径；
- Vitest 验证前端组件、类型和交互；
- Mock E2E 验证稳定的页面流程；
- Live E2E 使用真实 FastAPI、SQLite、Worker 和浏览器；
- SuperMap SDK/GPU 和 iServer 相关能力需要本机真实验收；
- 私有研究资料测试属于 `local_data`，并核对源文件前后哈希不变。

### 14.3 双速 CI

为减少普通提交等待时间：

- 普通 push/PR：运行快速 Python 合同、完整前端单元测试、类型检查和构建；
- `v*` 标签或人工触发：运行完整后端、Mock E2E 和真实 Live E2E。

测试代码是项目质量合同的一部分，应保留在源码仓库和比赛工程源代码中，但不会被打入给评委运行的免安装包。

### 14.4 Windows 开箱即用

v0.9.2 发布了 Windows x64 免安装包：

- 不要求用户安装 Python、Node.js、数据库或 Docker；
- 内置 FastAPI、Python 科学计算运行时、Vue 前端、SuperMap3D SDK、SQLite 和三个案例；
- 双击 `启动平台.cmd`，浏览器访问 `http://127.0.0.1:8000/`；
- 双击 `停止平台.cmd` 结束；
- `GeoModelingPlatform.exe doctor` 可检查包完整性、端口和运行状态；
- 首次启动从只读模板创建独立 `runtime`，用户数据只写入运行目录；
- `portable-manifest.json` 对发行文件进行 SHA-256 校验；
- 支持中文和空格路径的移动验收。

## 15. 可以提炼的项目特色与创新点

以下内容均有当前实现或证据支持，可以作为项目特色理解；具体表述仍需遵守边界。

### 15.1 从“插值工具”升级为“建模证据平台”

项目将数据接入、质量、算法、调参、验证、三维、分析、导出和发布状态连成一体。用户不仅得到一张图，还得到结果为什么可信、哪里不可信以及如何复现。

### 15.2 空间柱分组验证与公共有效集

针对三维地质样本沿深度成柱分布的特点，平台按 XY 柱进行空间折分，避免同柱泄漏；模型排名统一使用公共有效点，解决不同算法有效范围不同导致的不公平比较。

### 15.3 算法适用性门

系统不把“程序能运行”当成“模型适用”。它会根据有效样本数、独立空间组、折数和比较结果拒绝不可靠候选。瓦斯机器学习被拒绝、微震随机森林被标记为实验性，就是这种设计的实际体现。

### 15.4 多算法同一生命周期

IDW、普通克里金、DSI-like、随机森林和克里金残差随机森林共享数据版本、任务状态、空间折分、指标、成果和证据合同，使传统插值与机器学习能够在同一口径下比较。

### 15.5 防止机器学习验证泄漏

克里金残差随机森林使用内部折外克里金残差训练校正模型，而不是让验证样本参与自己的基线；复杂模型未提高精度时系统如实显示，不强行制造“AI 更优”的结论。

### 15.6 专业地统计参数证据化

变异函数、方向性、各向异性、旋转邻域和不确定性不只是后台参数，而是形成可查看、可确认、可追溯的专业证据。自动建议与人工确认分开，避免把数值候选当成真实地质方向。

### 15.7 SuperMap 三维与后端权威成果一致

三维 RenderAsset、后端切片、统计、异常和导出共享成果 ID、网格坐标、值域和哈希；父页面与 iframe 通过版本化协议同步状态，从而避免“展示模型”和“分析模型”不一致。

### 15.8 no silent fallback

三维加载、外部服务或证据校验失败时明确说明原因，不使用空图、点云或线框伪装正式体渲染。这个原则本身就是面向科研可信度的重要产品设计。

### 15.9 三类案例体现三种专业问题

- 电阻率：数据充足，适合多算法、三维成果和机器学习对比；
- 微震：体现领域数据派生、清洗、局部几何和黄金证据；
- 瓦斯：体现稀疏数据下的适用性拒绝和谨慎解释。

### 15.10 可选 AI，而非 AI 接管

确定性规则先完成地质属性研判，DeepSeek 只对结构化证据做补充解释。AI 不参与插值计算、异常阈值、专业规则或正式模型选择；没有密钥或接口失败时，平台仍完整可用。

### 15.11 结果从“属性图”落到“核查线索”

电阻率、微震速度和瓦斯含量不再停留在色带展示。平台把异常的空间位置、数值范围、支持节点、边界接触情况与专业多解性放在同一张卡片中，再给出可执行的钻孔、水文、岩性、测线覆盖、通风或抽采资料核查建议。它提供的是可追溯的现场复核入口，而不是越过证据直接生成灾害或安全结论。

### 15.12 开箱即用与可审计兼顾

Windows 免安装包降低评测门槛；源码仓库仍保留测试、CI、数据合同和证据。发行文件有完整性清单，运行数据与模板分离，既便于使用，也便于复核。

## 17. 当前边界与禁止夸大的内容

1. 三个案例使用独立局部坐标，没有共同控制点时不做跨案例空间融合；
2. 微震绝对 CRS、原点和方位角未知；
3. 瓦斯样本稀疏，不能表述为高置信度危险分区或灾害预警；
4. 当前没有时间维度，不进行未来时间预测；
5. 不实现普适克里金、协同克里金、指示克里金和任意斜切；
6. DSI-like 不等同 GOCAD DSI；
7. 各向异性候选只是诊断建议，需要人工确认；
8. Kriging 标准差、经验误差尺度和随机森林模型离散度都不是风险概率；
9. 异常连通区域不是已验证危险区，网格支持体积不是储量；
10. iServer 通用成果发布仍以 `manual_required` 为主；
11. 没有真实对象级回执时，不能宣称服务发布成功；
12. 历史 S3M 采样点表达不是原生连续体渲染；
13. DeepSeek 只做辅助解释，不能替代专业判断；
14. 当前网页在部分低高度笔记本屏幕上存在布局拥挤问题，浏览器缩放到 75% 是临时演示办法，不是最终适配方案；
15. 后续主流屏幕适配目标应覆盖 1920×1080、1536×864、1366×768 和 1280×720 在浏览器 100% 缩放下的关键流程；
16. 现场机器的浏览器、显卡、驱动和 SuperMap SDK 表现仍需发布前实机验收。

## 18. 术语解释

| 术语 | 通俗解释 |
|---|---|
| 属性场 | 某个指标在二维或三维空间中的连续估计结果 |
| 规则网格 | 按固定 X/Y/Z 间距排列的预测单元 |
| 空间柱 | X、Y 相同而 Z 不同的一组垂向样本 |
| 折外预测 OOF | 样本只由未包含它的训练折进行预测 |
| 公共有效集 | 所有候选都成功预测的同一批验证记录 |
| 半变异函数 | 描述样本差异随空间距离和方向变化的函数 |
| 块金值 nugget | 极短距离误差或微尺度变化的表现 |
| 基台值 sill | 半变异函数趋于稳定时的水平 |
| 变程 range | 样本仍表现空间相关性的典型距离范围 |
| 各向异性 | 不同方向上的空间变化速度不同 |
| NoData | 缺失或无法预测，不等于数值 0 |
| RenderAsset | 经身份、网格、变量和值域登记的正式渲染资产 |
| Volume | 完整三维属性场的体表达模式 |
| Contour | 指定属性阈值附近的等值结构表达 |
| Slice | 沿 X、Y 或 Z 方向截取的二维切片 |
| fail-closed | 条件或证据不满足时拒绝输出，而不是猜测或降级冒充 |
| 数据血统 | 从当前成果追溯到数据、参数、运行、模型和文件哈希的关系 |

## 19. 项目现状总结

截至 v1.0.0，GeoModelingPlatform 已形成一套可以独立运行、允许上传新数据、包含多算法调参、空间验证、模型比较、三维成果、切片分析、证据导出和可选 AI 解释的浏览器系统。三个案例分别覆盖数据充分、领域派生和稀疏样本三种典型情形。

项目最重要的价值不是“算法数量多”，而是把算法放进了严格的数据与证据生命周期：原始数据不被改写，空间验证避免泄漏，不兼容结果拒绝比较，复杂模型不一定被推荐，三维画面与后端成果身份一致，失败和能力边界明确展示。

目前最需要继续完善的是现场 GPU/浏览器兼容验收和比赛材料制作，而不是重新推翻建模主链。
