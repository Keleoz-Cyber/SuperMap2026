# v0.7.0 第一批：统一案例工作台与微震预置案例

**状态：设计已获用户确认，等待用户复核本文档后进入实施计划。**

## 1. 目标与范围

本批将电阻率内置案例、微震速度预置案例和用户上传案例收束到同一案例工作台，并把微震第二案例从 DAT 上传产品流程改为开箱可用的 CSV 预置案例。

用户打开微震案例时应能直接进入官方普通克里金成果；同时可以基于同一不可变数据版本创建自己的实验。官方成果和用户实验是两条不同的结果链，用户操作不能覆盖、替换或重标官方成果。

本批包含：

- 微震 1911 行 CSV 的受控预置、溯源、校验、官方普通克里金基线和 NetCDF 原生体渲染成果。
- 统一案例身份 DTO、统一工作台页面骨架与首页入口。
- 电阻率、微震和用户上传案例的一致工作台导航、标题、数据摘要、成果入口和新建实验入口。
- 移除所有用户可见的微震 DAT 导入入口。

本批不包含：

- X/Y/Z 三轴切片、仅切片模式显示的控制面、lighting 或 gradient-opacity 的运行时控制。
- 用户上传案例的删除及其 SQLite/文件/资产级联回收。
- 专业诊断入口从实验创建页解耦。
- iServer 发布流程、真实地理配准、渲染器回退或新的插值算法。

这些内容分别属于后续 v0.7 批次，不能混入本批的预置数据迁移。

## 2. 不变原则

1. 连续体显示仍只使用 SuperMap3D `VoxelGridLayer3D + NetCDF`。点只可作为辅助证据层，不能成为体渲染替代。
2. 微震 CSV 是受控产品输入，不是浏览器上传文件。产品运行时不得读取 `D:` 绝对路径。
3. 官方基线必须通过常规 `Case -> DatasetVersion -> Experiment -> Run -> CandidateResult -> FormalSelection` 结果链登记；禁止手工写 SQLite 行或把静态 NetCDF 绕过成果系统直接挂到页面。
4. 正式 HTTP `GET` 只查询，不计算、不生成资产、不修改状态。预计算由维护命令和既有显式资产创建流程完成。
5. 各案例可有不同数据形态、字段、单位和来源，但用户面对的案例级导航、状态和操作位置必须相同。
6. 现有电阻率权威网格不重算、不改写，也不伪装为通用上传数据。

## 3. 统一案例契约

### 3.1 公共身份

`GET /api/cases` 的公共案例卡扩展为工作台 DTO。它以以下身份区分来源：

| 字段 | 含义 |
| --- | --- |
| `workspace_kind` | `builtin_legacy`、`builtin_preset` 或 `user_upload` |
| `case_id` | 稳定案例身份；不得由显示名称派生 |
| `title` | 用户可读标题 |
| `capabilities` | `data_summary`、`experiments`、`official_result`、`native_volume` 等可用能力 |
| `primary_dataset` | 当前可供查看/建模的数据版本摘要；没有时为 `null` |
| `official_result` | 官方或正式主打成果的结果链接；没有时为 `null` |
| `provenance_summary` | 只含允许公开的来源说明、字段、坐标语义、单位和摘要指纹 |

原有 `source_kind` 允许作为短期兼容字段保留，但所有新页面只读取 `workspace_kind` 和 `capabilities`。这避免微震错误继承电阻率或上传案例的专有分支。

### 3.2 三类案例

| 类型 | 持久化/适配方式 | 不可变部分 | 用户可做的操作 |
| --- | --- | --- |
| `builtin_legacy` | 现有电阻率 adapter | 权威网格与来源登记 | 查看数据摘要、官方成果、创建该案例现有允许的后续流程 |
| `builtin_preset` | 常规 `Case`、`DatasetVersion` 与结果链 | 预置 CSV、已验证数据版本、官方正式选择 | 查看官方成果、以预置数据版本新建实验 |
| `user_upload` | 现有常规 `Case` 与数据版本 | 每个已验证数据版本 | 查看数据、创建实验、进入已有成果 |

`builtin_preset` 不能伪装为 `user_upload`：后续删除功能必须依身份禁止预置案例删除。它也不能使用 `builtin_legacy`，因为它的实验、数据集和普通克里金结果必须复用通用建模链。

## 4. 案例工作台

### 4.1 路由与兼容

- 新主入口为 `/#/cases/:caseId`，加载公共工作台 DTO。
- `/#/case/resistivity` 保留为兼容别名，并重定向到 `/#/cases/resistivity`。
- 现有 `/#/cases/:caseId/experiments/new` 和 `/#/results/:resultId` 保持有效；前者从工作台的“新建实验”按钮进入，后者作为统一成果详情页。
- 首页所有可进入案例卡只跳转工作台。卡片的官方成果按钮可直接跳转 `official_result.url`，但仍提供“进入案例工作台”。

### 4.2 共同界面

每种案例的工作台采用同一版式：

1. 页头：案例标题、来源标签、数据形态、单位、坐标状态和官方/用户来源状态。
2. 概览：数据摘要、当前主打成果状态、明确的“查看成果”和“新建实验”命令。
3. 数据：数据版本、字段映射、质量摘要和允许公开的溯源信息。
4. 实验：使用该案例的可用数据版本创建、查看和继续通用实验。
5. 成果：官方成果或主打成果列表，进入既有 `ResultWorkbenchView`，其中继续使用 NetCDF 原生体渲染面板。

工作台使用按能力显示的内容区，而不是按案例类型复制 Vue 页面。案例专有内容以小型只读信息面板注入：电阻率显示权威网格/iServer 状态；微震显示 CSV、Vx 和克里金基线摘要；上传案例显示用户上传映射和质量摘要。

专业诊断仍保持既有入口和路由，第一批不在工作台显示可操作的“专业诊断”入口，以免形成看似可用但仍要求先建实验的入口。

### 4.3 状态与错误

- DTO 读取失败：保留返回首页和重试操作，显示稳定后端错误码与用户可读信息。
- `official_result` 缺失或未物化：概览显示“官方成果准备异常”，不得伪造成功或改跳新建实验。
- 预置数据尚未 seed：工作台显示 `PRESET_NOT_INITIALIZED`，仅允许维护者执行文档化 seed 命令；普通用户界面不显示上传或修复入口。
- 原生体资产未就绪：沿用 v0.6.1 的显式创建、状态刷新和失败重试语义，不做点云或旧渲染器回退。

## 5. 微震 CSV 预置数据

### 5.1 受控输入

实施时将用户指定的文件纳入仓库的受控数据位置：

`data/presets/microseismic/microseismic-vx-1911.csv`

该文件来自：

`D:\study\Contest\Supermap\超图杯资料\标准化数据\微震局部三维点_3Sigma_去重均值_1911.csv`

导入时写入 `source_manifest.json`，至少包含原始文件名、SHA-256、字节数、行数、列名、有限数值检查、坐标范围、Vx 值域、单位 `km/s` 和坐标语义 `local_linear`。运行时和公共 API 绝不返回源文件绝对路径。

预置验证要求：

- 数据行数为 1911，XYZ 组合唯一。
- 字段映射为 `X_LOCAL_M`、`Y_LOCAL_M`、`Z_LOCAL_M`、`VX_KM_S`。
- 坐标和值均为有限数值；Vx 保持原单位 `km/s`，不静默转换为 `m/s`。
- 源清单 SHA 与受控 CSV 不一致时 seed 必须失败，且保留原有正式结果不变。

### 5.2 官方普通克里金基线

官方成果不是每次打开页面时计算。维护流程分为两个明确阶段：

1. `analyze-preset` 在受控 CSV 上执行预先固定的普通克里金候选矩阵，输出只读候选报告和空间验证指标。
2. 经评审后提交 `official-baseline.json`，其中含精确变异函数、邻域数、Z 距离缩放、验证合同、边界、网格分辨率、候选报告指纹和选择理由。
3. `seed-preset` 验证 CSV 与 baseline 指纹一致，通过常规任务链计算/物化官方候选并创建正式选择；已有同一身份、同一指纹的成果时只查询，不重复计算或改写。

候选矩阵继承现有预置的普通克里金候选空间：

- variogram：`spherical`、`exponential`、`gaussian`；
- neighbor count：12、24、36；
- `z_scale`：0.5、1、2；
- 验证：固定种子的 5 折空间交叉验证。

选择规则必须在 `official-baseline.json` 中编码并可复算：仅在有限共同验证集上比较，先最小 RMSE，再最小 MAE，再最大 R2，最后按规范化参数 JSON 的字节序打破平局。最终产品不依赖一次性人工编辑的 SQLite 数值。

网格边界从验证后的 CSV 坐标范围得到并在 baseline 中固定；网格分辨率也在 baseline 中固定，且乘积不超过当前通用建模单网格上限。不得照抄旧 DAT preset 的边界或估算单元数。

### 5.3 正式成果身份

seed 生成的每次产物必须保留并关联：

```text
CSV SHA-256
  -> source manifest SHA-256
  -> official baseline SHA-256
  -> dataset version fingerprint
  -> experiment/run/candidate IDs
  -> grid SHA-256
  -> NetCDF SHA-256
  -> render asset ID
```

首页和工作台只能展示该正式选择链接。用户从预置数据建立的实验拥有新的 experiment/run/candidate/result 身份，并且没有权限写入或替换上述正式选择。

### 5.4 DAT 产品路线退出

本批移除：

- 首页“导入微震 DAT”文案、按钮与跳转。
- 微震 DAT 创建向导和 `MicroseismicImportView` 的用户可达路由。
- `POST /api/cases/{case_id}/microseismic-imports` 的产品注册。

已有历史 DAT 结果若存在，仍可通过已有结果 URL 只读查看，直到单独的数据迁移/清理版本决定生命周期；本批不删除历史运行数据。DAT 派生报告不再是预置 CSV 的证据模型，CSV 采用独立 manifest 和 baseline 报告。

## 6. 后端与前端边界

### 后端

- 新增预置数据包验证、候选分析、idempotent seed 和公开工作台 DTO 的服务层；命令与 API 路由只编排服务，不直接写表。
- 对通用 `CaseRepository` 补充按稳定预置身份读取/创建的仓储操作，使用事务和唯一约束保护并发 seed。
- 官方结果继续通过既有 `ExperimentRepository`、`RunRepository`、`CandidateResult` 和 `FormalSelection` 生命周期产生。
- 预置 Case 的 `config_json` 必须声明 `workspace_kind=builtin_preset`、预置版本和只读保护；公开 DTO 不泄漏内部绝对路径。
- 渲染源沿用 candidate-result 到 `RenderGridSource` 的适配，不新增微震专用 NetCDF 导出器。

### 前端

- 提取 `CaseWorkspaceView` 和数据驱动的案例头部/能力导航；不复制电阻率、微震和上传三份页面布局。
- `HomeView` 从 DTO 决定标签、入口和命令，不以 `case_id === 'microseismic'` 或 `source_kind === 'upload'` 决定业务流程。
- `ResultWorkbenchView` 将微震图层显示条件从 `microseismic_dat_bundle` 收束为公开证据能力，而不是假定 DAT 派生文件存在。
- 继续将 SuperMap SDK 留在同源 iframe。工作台只调用既有 `NativeVolumePanel` API，不向 iframe 注入案例专有 JavaScript。

## 7. 验收与测试

### 后端测试

- CSV manifest：文件 SHA、1911 行、字段映射、有限值、单位和坐标范围不匹配时稳定失败。
- baseline：候选矩阵、空间验证、选择排序和输入/输出指纹确定；任何输入或 baseline 不匹配不得覆盖旧成果。
- seed：首建生成完整通用结果链；重复调用幂等；并发调用不生成双正式选择；失败无部分数据库行或半发布工件。
- official result：正式选择、grid、NetCDF 和 render asset 身份连通，且字段名/单位为 Vx/km/s 而非硬编码 `rho`。
- DAT：新导入入口不可达；历史读取在有历史数据时保持只读兼容。
- 电阻率：现有 legacy render-source 与 iServer 状态接口回归通过。

### 前端测试

- 首页三个身份卡片的文案、工作台跳转、官方成果直达和新建实验命令正确。
- `CaseWorkspaceView` 对电阻率、微震、用户上传的共同结构一致，专有摘要按 capability 显示。
- 微震不再出现 DAT 上传、DAT 向导或“导入 DAT”文案。
- 从预置数据创建实验带正确 dataset version；完成后不改变官方成果链接。
- 结果页只有在 NetCDF 原生 iframe 报告 `rendered` 后显示为“已渲染”。

### 集成与真实门

- 新建隔离 runtime 后 seed 预置微震，访问首页、工作台、官方成果和用户新实验路径。
- 为官方微震成果创建 NetCDF 资产，校验 grid/NetCDF/asset 身份一致。
- 在具备本机专有 SDK 的发布门运行真实浏览器：Volume、Slice、Contour 均须有各自的非背景像素响应，且没有协议或资源失败。
- 再运行电阻率 32³/64³ 与 legacy 产品页门，证明统一工作台没有回归既有 v0.6.1 正式体渲染。

## 8. 交付顺序

1. 先落受控 CSV、manifest 合同、baseline 分析与 seed 服务的测试。
2. 再实现官方普通克里金预置链并验证结果/NetCDF 身份。
3. 然后引入工作台 DTO、路由、首页和共用页面壳，保留电阻率兼容别名。
4. 最后移除 DAT 用户入口，完成全量回归、真实 SDK 门和证据。

每一步独立提交并保持可回归；不得在同一提交中手动修改运行时 SQLite 来制造“已 seed”状态。

## 9. 完成定义

第一批完成的可观察结果是：

- 用户无需上传任何 DAT，即可从首页进入“微震速度（第二案例）”工作台并查看官方普通克里金的 NetCDF 原生体渲染成果。
- 用户能从同一工作台以预置数据版本新建实验，且官方成果身份不变。
- 电阻率、微震和上传案例拥有一致的案例级入口和工作台骨架。
- 浏览器中不存在可触发微震 DAT 导入的产品入口。
- v0.6.1 的电阻率与原生体渲染回归门通过；本批不引入旧渲染器或静默降级。
