# v0.9.0 答辩级视觉产品与全流程体验重构设计

> 状态：2026-08-10 经用户逐段确认的产品设计。本文描述 v0.9.0 的目标形态和验收口径，不代表功能已经实现。当前实现事实以 [`docs/status/current-status.md`](../../status/current-status.md) 为准。

## 1. 背景与问题

GeoModelingPlatform v0.8.1 已具备三个官方案例、用户自定义数据接入、IDW/普通克里金/DSI-like、空间验证、模型比较、NetCDF 原生体渲染、X/Y/Z 切片、统计与空间分析以及证据导出等能力。

当前主要矛盾已经不是“有没有功能”，而是功能被分散在多个页面中，视觉层级、叙事顺序和交互联动不足，无法在答辩中快速表达平台价值：

- 首页仍像入口卡片目录，打开系统后看不到核心三维成果和关键结论；
- 调参、结果、模型评估和统计分析相互割裂，用户需要在多个页面中寻找下一步；
- 分析中心数据多、解释少，图表按模块分开，缺少“发现—证据—三维定位—限制”的完整链条；
- 三个案例共享过多相同视觉模板，地质属性差异不明显；
- 页面有大片无意义空白、卡片层级相近、操作重点不突出；
- 自定义数据入口存在，但产品表达不清，容易与三个内置官方案例混淆；
- 当前视觉不足以支撑超图杯现场演示的第一印象和讲解节奏。

v0.9.0 的任务是把现有真实能力组织成一个有视觉冲击力、专业解释力和完整操作路径的浏览器产品，而不是继续堆叠算法或只替换主题色。

## 2. 产品目标

### 2.1 一句话目标

将 GeoModelingPlatform 重构为一个面向超图杯答辩的“深地属性建模综合指挥舱”：打开系统即可看到案例、模型、三维成果和关键发现，并能从任一发现追溯到数据、参数、图表、空间位置和证据。

### 2.2 必须实现的体验结果

1. 首页从卡片目录升级为综合指挥舱，中央三维成果是第一视觉焦点。
2. 案例工作台成为唯一业务中枢，稳定承载数据概览、建模实验、成果分析和证据报告。
3. 成果页与分析中心融合为一张沉浸式工作台，三维、图表和结论双向联动。
4. 三个官方案例共享产品框架，但拥有可识别的视觉性格、分析重点和叙事结构。
5. 自定义数据拥有持续可见的一级入口，并通过“数据接入与准备”工作台进入统一建模链。
6. 调参实验室解释参数为什么这样设、模型为什么这样选，而不是只展示表单和排行榜。
7. 新增受控答辩模式，以固定讲解节点、镜头书签和降级路线串起完整演示。
8. UI 细节、动效、响应式、空态和失败态成为正式验收项，不再只做截图级 CSS 美化。

### 2.3 非目标

- 不新增没有数据证据的地质结论、危险等级、储量或预测结果；
- 不把三个局部坐标案例叠加成同一研究区，不宣传多源融合；
- 不实现新的插值算法、AI 地质解释、任意斜切或真实 CRS 配准；
- 不用装饰性粒子、持续闪烁或伪实时数字掩盖空数据和服务失败；
- 不以文档数量、测试数量或组件重命名代替真实浏览器视觉结果；
- 不改变 v0.8.1 已冻结的官方数据、正式结果身份和算法口径。

## 3. 已确认的设计方向

| 主题 | 决策 |
| --- | --- |
| 首页形态 | A：综合指挥舱，而不是案例卡片目录 |
| 视觉语言 | S1“深地极光”：墨绿黑、青色空间信息、少量核心金 |
| 分析结构 | A：结论优先，结论必须连接量化证据和三维位置 |
| 成果与分析 | 融合为一张工作台，不再作为两个互不相关的产品页面 |
| 案例差异 | 共用框架、差异化辅助色与专业叙事 |
| 自定义数据 | 顶部固定入口 + 项目列表入口；官方案例不显示上传步骤 |
| 数据准备 | 顶部阶段导航 + 同屏数据接入工作台，而非传统逐页向导 |
| 饼/环图 | 只用于有效/无效/NoData、异常区占比等部分—整体关系 |
| 动效 | 中等强度、克制但有冲击力，用于状态与空间联动 |
| 改造范围 | v0.9.0 内完成全页面重构，不把核心视觉效果延期到下一版本 |

## 4. 产品叙事与全局信息架构

### 4.1 答辩叙事

平台的核心叙事不是“我们有很多页面”，而是：

1. 三类独立地质属性数据能够进入同一套可复现建模平台；
2. 平台先校验数据，再进行可调参数插值和空间验证；
3. 候选模型通过公共有效集和专业证据比较后形成正式成果；
4. 正式成果能够连续体渲染、正交切片、定位异常并进行差异化分析；
5. 每个结论都能回到数据版本、参数、指标、空间位置和限制条件；
6. 用户也可以上传新的 CSV/XLSX，复用同一条建模链。

### 4.2 全局壳

所有主要页面共用稳定的应用壳：

- 左上：平台标识和当前页面层级；
- 中上：当前案例/项目选择器；
- 右上：`导入数据 / 新建建模`、答辩模式、服务状态和全局命令；
- 主内容：随业务阶段切换，不重复放置大标题和冗余面包屑；
- 状态层：统一呈现运行中、离线、降级、失败和未验证状态。

### 4.3 业务层级

案例工作台统一表现为四个业务阶段：

1. **数据概览**：数据身份、质量、空间覆盖、数据版本和准备状态；
2. **建模实验**：新建实验、参数配置、运行队列、候选排名和模型比较；
3. **成果分析**：连续体、切片、异常区、关键发现和统计证据；
4. **证据与报告**：数据血统、参数、指标、正式选择、导出和发布状态。

这些阶段是用户认知层，不强制删除现有路由。实现可以保留当前深链和后端合同，但必须通过统一壳、稳定导航和共享状态让用户感知为一个连续产品。

## 5. 首页：综合指挥舱

### 5.1 桌面布局

- **顶部全局栏**：平台身份、案例选择、自定义数据入口、答辩模式和服务状态；
- **左侧案例轨**：电阻率、微震速度、煤层瓦斯和用户项目，以紧凑缩略项展示变量、单位、规模和状态；
- **中央三维主舞台**：约占首屏一半，显示当前案例正式成果，可旋转、聚焦异常区和切换渲染模式；
- **右侧关键发现**：默认 3–5 条，每条包含结论、量化证据、可信状态、限制和“定位到三维”；
- **底部证据带**：质量组成环图、模型指标比较、异常区占比、数据/成果/发布状态摘要。

首页切换案例时，中央三维、右侧发现和底部证据整体联动；不得只替换标题而保留错误图表或旧单位。

### 5.2 首页主动作

- 官方案例：`进入案例分析`；
- 用户项目：`继续建模`或根据权威状态显示`继续数据准备`；
- 全局固定动作：`导入数据 / 新建建模`；
- 次要动作放入上下文菜单，不与主动作争夺视觉焦点。

### 5.3 首页数据口径

- 电阻率：`RHO`，`Ω·m`，局部线性米制；
- 微震速度：`Vx`，`km/s`，局部线性米制；
- 瓦斯含量：`CH4_content`，`ml/g`，局部线性米制；
- 三案例不得叠加，案例切换只替换当前场景和分析上下文；
- 未验证、服务离线或分析能力不可用时显示真实状态，不用假图补位。

## 6. 自定义数据：数据接入与准备

### 6.1 入口与边界

“数据接入与准备”只服务用户新建案例。三个内置官方案例直接加载冻结数据和官方成果，不出现上传步骤。

现有真实链路应继续保留：

`/cases/new` 新建案例 → 上传 CSV/XLSX → 字段映射与质量检查 → 建模确认 → 调参实验。

产品文案统一使用“数据接入与准备”，避免把整条流程笼统称为“上传向导”。

### 6.2 混合式同屏工作台

顶部显示四阶段：

`文件接入 → 字段映射 → 质量检查 → 建模确认`

主体不逐页跳转：

- **左侧数据区**：文件/工作表、编码、前若干行真实预览、字段类型和缺失概览；
- **中央空间预览**：二维/三维散点、范围、密度和疑似错位点；映射不足时显示解释性引导；
- **右侧映射诊断**：X/Y/可选 Z/建模值、单位、局部或地理坐标声明、类型纠正建议；
- **底部质量摘要**：有效/无效/缺失环图、字段质量条形图、空间范围、阻断项和警告项。

### 6.3 数据安全与降级

- 平台可建议字段，最终映射由用户确认；
- 坐标系未知时允许声明局部坐标，禁止自动编造 EPSG；
- 问题数据可定位到原始行并导出清单；
- 修正不覆盖原文件，保留源哈希和处理记录；
- 阻断项清零前禁止进入实验；
- 提供固定演示数据下载和一键载入，但必须明确标识演示数据；
- 恢复已有未完成数据版本时，不要求重新上传。

## 7. 调参实验室

### 7.1 布局

- **顶部上下文栏**：返回案例、实验名、数据版本、保存状态和唯一主动作`创建实验并运行`；
- **左侧参数区**：算法、快速预设、邻域、幂次、变异函数、各向异性、网格和空间验证；
- **中央实验画布**：测点空间预览、IDW 邻域/权重示意、Kriging 经验半变异函数和拟合证据；
- **右侧候选摘要**：预计网格、验证折数、公共有效点、参数风险和与基准的差异；
- **底部实验队列**：运行流水线、候选指标、失败信息和 2–4 个候选的比较入口。

### 7.2 交互原则

- 基础参数默认展开，专业参数按语义分组折叠；
- 参数变化先显示影响提示，不伪装为已完成结果；
- 运行状态用“校验→折分→插值→评估→物化”流水线表达；
- 运行完成后生成真实候选缩略图、代表切片和残差摘要；
- 公共有效集不同的候选禁止给出直接排名；
- 正式选择必须填写理由，官方案例正式选择只读；
- 返回案例不取消后台任务，刷新后恢复队列和状态；
- 所有失败状态保留类型化错误和可重试参数。

## 8. 成果与分析融合工作台

### 8.1 一张主工作台

- **中央主视图（约 60%）**：Volume、X/Y/Z Slice、Contour、测点和异常区；
- **左侧工具轨**：图层、模式、色带、标度、阈值、透明度、光照、切片、镜头和截图；
- **右侧发现栏**：核心结论、空间特征、异常区、模型精度、不确定性、数据质量和限制；
- **底部可展开证据带**：分布、箱线、模型指标、观测—预测、残差、环图和典型切片缩略图；
- **证据抽屉**：数据版本、源哈希、参数、模型选择理由、资产身份、服务状态和导出。

### 8.2 双向联动

- 图表区间选择必须更新三维过滤或定位；
- 三维异常区选择必须更新右侧解释和底部证据；
- 模型切换必须同时更新三维成果、指标、参数和结论；
- 切片移动后，切片统计与全局统计必须在标题和口径上明确区分；
- 从分析发现进入成果位置后，返回时保留筛选语义；
- 联动失败必须显示模块级错误，不能保留看似有效的旧图。

### 8.3 结论卡合同

每条关键发现必须包含：

1. `finding`：一句可读结论；
2. `evidence`：指标、阈值、样本数或空间范围；
3. `spatial_target`：可选的三维定位或切片位置；
4. `source`：数据版本、结果身份和计算口径；
5. `confidence_state`：已验证、探索性、证据不足或不可用；
6. `limitations`：单位、坐标、稀疏性、模型或专业边界。

结论由已有统计量、空间结果和模型指标组合，不允许前端根据颜色或案例名自由生成地质解释。

## 9. 图表体系

### 9.1 证据图组合

单一页面采用混合证据带，而不是“一张图一个页面”：

- 环图：有效/无效/NoData、异常/正常网格支持、覆盖组成；
- 柱状图：模型指标、分层统计、类别或区间比较；
- 折线/面积图：X/Y/Z 方向趋势、深度变化、梯度变化；
- 散点图：观测—预测、残差与空间位置；
- 箱线/分布图：数值分布、异常值和不确定性；
- 热力图/切片缩略图：二维空间证据和代表性剖面。

### 9.2 环图使用限制

环图只用于可加总的部分—整体关系。连续分布、时间/方向趋势和模型排名不得使用饼图。瓦斯页面的网格区占比必须标为“探索性网格支持占比”，不得命名为“储量”“危险体积”或“安全比例”。

### 9.3 图表共同要求

- 显示变量、单位、样本数、统计范围和阈值来源；
- 图例和色带与三维场景保持语义一致；
- tooltip 提供可追溯口径，不只显示一个数字；
- ECharts 实例在卸载时释放，切换案例不得残留旧数据；
- 图表空态、部分缺失和计算失败分别表达。

## 10. 三个案例的视觉与叙事差异

三个案例共用“深地极光”壳和布局规则，不做三套互不兼容的应用。

| 案例 | 辅助色 | 主视觉语言 | 分析重点 | 禁止表达 |
| --- | --- | --- | --- | --- |
| 电阻率 | 核心金 + 青绿 | 深层电性结构、阻性异常体 | 对数分布、深度分层、高低阻、梯度、模型差异 | 单位未支持时生成含水/成矿结论 |
| 微震速度 | 冰青 + 蓝紫 | 测线与速度场、方向变化 | 轴向趋势、速度梯度、空间异常、采样结构 | 震源能量、时间演化、已确认各向异性 |
| 瓦斯含量 | 翡翠绿 + 琥珀 | 钻孔样本、分层含量场 | 含量分布、Z 向变化、覆盖、梯度和稀疏性 | 危险/安全等级、储量、规范阈值结论 |

用户自定义数据默认使用中性青色，并根据实际变量和单位生成通用图表；不借用官方案例的专业结论文案。

## 11. 视觉系统：S1“深地极光”

### 11.1 色彩

- 背景：带轻微绿相的深墨黑，不使用纯黑大平面；
- 结构色：低饱和青色，用于空间坐标、连线、选中和运行状态；
- 核心色：少量金色，用于正式成果、关键结论和答辩焦点；
- 状态色：成功、警告、错误和未验证使用独立语义色，不与案例辅助色混用；
- 卡片：通过明度、透明度和层级区分，不用所有卡片同一厚边框。

具体 token 在实施计划中冻结，所有色彩必须通过对比度检查和真实三维截图验收。

### 11.2 排版与空间

- 标题、正文、指标、标签和辅助说明建立统一字号/行高层级；
- 关键数字使用等宽或稳定数字宽度，单位弱化但始终可见；
- 桌面页面采用紧凑高信息密度，保留必要呼吸空间，避免无意义大留白；
- 卡片内部不再多层套卡片；
- 主动作每页原则上只有一个，次要动作使用低强调按钮或菜单；
- 图标必须有文字或可访问名称，不使用无法理解的纯装饰图标。

### 11.3 三维舞台

- 三维舞台应有低对比度空间网格、坐标辅助、包围盒和场景标题；
- 背景与体渲染色带分离，不能导致低值区消失；
- 镜头切换、异常定位和切片移动保持空间连续性；
- 不用大面积粒子、光柱或无数据含义的地球模型充当主视觉。

## 12. 动效系统

### 12.1 动效用途

- 页面入场：关键指标、主图和发现卡按层级渐入；
- 案例切换：框架稳定，三维、标题、图表和辅助色平滑过渡；
- 图表联动：选择范围、强调证据和三维定位具有清楚反馈；
- 建模任务：通过流水线状态表达真实阶段；
- 答辩巡航：使用受控镜头动画连接讲解节点。

### 12.2 时长与限制

- 微交互：约 180–240 ms；
- 面板与图表切换：约 240–360 ms；
- 三维镜头和答辩章节：约 350–800 ms，根据场景距离调整；
- 禁止长期闪烁、无限呼吸、持续粒子和阻塞输入的开场动画；
- 支持 `prefers-reduced-motion`，关闭非必要动画；
- 动效不得改变数据完成状态，不得用计数动画伪造实时计算。

## 13. 答辩模式

### 13.1 进入方式

全局栏提供“答辩模式”。进入后全屏显示，隐藏编辑和危险操作，保留退出、上一节、下一节、章节目录和服务状态。

### 13.2 默认章节

1. 平台能力总览；
2. 电阻率：数据—模型—三维成果—关键发现；
3. 微震速度：测线结构—空间验证—速度场—关键发现；
4. 瓦斯含量：稀疏数据—解释性建模—分层与覆盖—限制；
5. 自定义数据：载入固定演示文件并走通准备/实验/结果；
6. 创新点、证据链和已知边界。

章节使用镜头书签和受控高亮，不自动持续播放。讲解者可随时进入普通交互。

### 13.3 降级路线

- iServer 离线：明确标识服务不可用，继续展示平台内已验证的 NetCDF/分析链；
- WebGL2 或原生渲染失败：显示类型化失败和已验证截图/证据入口，不回退点云伪装体渲染；
- 数据/模型不可用：跳过对应章节并说明原因；
- 降级状态必须进入答辩彩排和截图证据。

## 14. 响应式与可访问性

### 14.1 布局策略

- 大屏/答辩屏：三维主舞台 + 双侧面板 + 底部证据带；
- 普通笔记本：折叠一侧面板，保留三维和关键发现；
- 平板：三维在上、发现与证据在下，工具轨改为抽屉；
- 手机：案例摘要、关键发现和核心图表优先，三维进入独立全屏；不强塞桌面三栏。

### 14.2 可访问性

- 键盘可访问全局导航、案例切换、答辩章节和主要控制；
- 焦点态不能仅依赖颜色；
- 图表关键结论提供文本摘要；
- 色带兼顾色觉缺陷并提供数值 tooltip；
- 所有图标按钮具有可访问名称；
- 支持减少动效和合理对比度。

## 15. 状态、错误与证据真实性

### 15.1 统一状态组件

全站统一：加载、空数据、部分可用、未验证、任务排队、运行、取消、失败、服务离线、缓存失效、NoData 和权限不足。

每个状态至少回答：

1. 发生了什么；
2. 哪些能力受影响；
3. 已有结果是否仍可使用；
4. 用户下一步可以做什么。

### 15.2 fail-closed 原则

- 单位、坐标、结果身份或公共有效集不一致时，不显示误导性结论；
- 新请求失败后不保留旧案例图表冒充新结果；
- 服务成功与浏览器真实渲染成功继续分开登记；
- 所有关键发现能追溯到数据版本、结果身份和计算口径；
- 探索性统计必须在页面和导出中保持探索性标签。

## 16. 前端结构建议

实现阶段应先建立共享产品壳和设计 token，再改页面，避免每个页面独立硬编码。

建议的概念组件边界：

- `AppShell`：全局栏、案例上下文、服务状态和答辩模式；
- `CaseRail`：官方案例与用户项目列表；
- `SceneStage`：三维主舞台和通用覆盖层；
- `FindingPanel` / `FindingCard`：结论、证据、定位和限制；
- `EvidenceDock`：混合图表和切片缩略图；
- `DataIntakeWorkbench`：上传、预览、映射和质量；
- `ExperimentLab`：参数、空间证据、队列和候选；
- `ResultAnalysisWorkbench`：现有成果、分析、模型评估和证据的组合器；
- `PresentationController`：章节、镜头书签和降级路线；
- `AsyncState` / `CapabilityNotice`：统一状态和能力降级。

现有 `HomeView`、`CaseWorkspaceView`、`DatasetWizardView`、`ExperimentView`、`ResultWorkbenchView`、`ProfessionalAnalysisView` 和 `AnalysisCenterView` 可以逐步接入共享壳；是否合并物理路由由实现阶段通过测试和深链兼容性决定，不在设计阶段强制大规模删路由。

## 17. 验收标准

### 17.1 首页与导航

- 首屏无需滚动即可识别平台定位、当前案例、三维成果、关键发现和自定义数据入口；
- 三案例切换后变量、单位、色彩、三维、发现和图表全部一致更新；
- 官方案例不出现上传步骤；用户项目可从全局入口和项目列表进入数据准备；
- 每个主要页面只有一个明确主动作，返回路径无死路。

### 17.2 数据接入

- CSV/XLSX 能在同屏完成预览、映射、质量和空间检查；
- 缺失/无效/重复/坐标错误可定位到原始行；
- 未知 CRS 可声明局部坐标，不产生伪 EPSG；
- 阻断项和警告项视觉上明确区分；
- 质量通过后直接进入实验，刷新后能恢复进度。

### 17.3 调参与模型选择

- IDW 和普通 Kriging 的关键参数、空间证据和运行状态可理解；
- 至少两个候选能在公共有效集口径下并排比较；
- 参数、指标、残差、缩略成果和正式选择理由处于同一上下文；
- 后台任务在返回或刷新后继续，并如实恢复状态。

### 17.4 成果与分析

- Volume、X/Y/Z Slice 和 Contour 保持已有能力；
- 图表选择能驱动三维过滤/定位，三维选择能更新发现与证据；
- 每个官方案例至少有三条数据支持的关键发现和一条限制说明；
- 环图、柱状图、趋势图、残差/验证图和切片形成混合证据带；
- 切片统计与全局统计口径不会混淆；
- 自定义 `generic_3d` 缺少专业字段时显示明确降级，不套用官方案例结论。

### 17.5 视觉与动效

- 页面不出现大片无意义空白、重复厚边框、文字溢出和卡片套卡片；
- 三维是首页和成果页第一视觉焦点，图表和控制不遮挡主体；
- 案例色彩有差异但系统保持统一；
- 动画流畅、可关闭、无长期闪烁，不阻塞操作；
- 加载、空态、失败、离线、NoData 和降级均有专门设计。

### 17.6 真实浏览器门

不得仅以单元测试、Mock E2E 或构建通过宣布视觉完成。发布候选必须使用三个仓库内置官方案例和固定自定义演示数据完成真实浏览器验收：

- 桌面答辩视口和手机视口各至少一组；
- 首页三案例切换；
- 自定义数据准备全链；
- 调参、候选比较和正式选择；
- Volume、X/Y/Z Slice、Contour；
- 图表—三维双向联动；
- 答辩模式完整章节；
- iServer/渲染离线降级；
- 零未处理控制台错误、零横向溢出、零黑屏或空白图表假绿；
- 截图、像素变化、网络、控制台、数据身份和运行时环境形成证据包。

## 19. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 大面积 UI 重写破坏已有深链 | 保留路由兼容；先建立共享壳，再逐页迁移；增加真实导航回归 |
| 三维、ECharts 和动效同时运行导致卡顿 | 懒加载非活动图表、释放实例、限制动画并做真实帧率/内存观察 |
| 视觉稿很好看但没有真实数据 | 所有页面用三官方案例和固定演示数据验收，禁止静态假数据截图 |
| 结论看板产生无证据描述 | 结论卡强制 source/confidence/limitations；后端或受控映射生成 |
| 三案例差异化演变成三套代码 | 共用组件和 token，只在 profile、辅助色、图表模块与文案上差异化 |
| 环图或异常色造成专业误导 | 限制使用场景；阈值来源和探索性标签始终可见 |
| 动效影响答辩稳定性 | 支持减少动效；答辩模式使用预设镜头；保留无动画稳定路径 |
| iServer/SDK 现场不可用 | 彩排离线降级；状态如实；不回退到点云伪装原生体渲染 |

## 20. 最终设计原则

1. **三维优先，但三维必须由证据解释。**
2. **结论优先，但结论必须可追溯。**
3. **同一产品框架，案例表达必须有差异。**
4. **自定义数据是一等能力，不是隐藏附属入口。**
5. **动效服务状态和空间理解，不服务炫技。**
6. **视觉完成必须由真实数据、真实浏览器和完整演示路径证明。**
7. **任何美化都不能覆盖单位、坐标、不确定性和已知边界。**
