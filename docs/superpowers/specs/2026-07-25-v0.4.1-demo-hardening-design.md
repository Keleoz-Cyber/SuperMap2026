# GeoModelingPlatform v0.4.1 答辩演示加固设计

> 状态：书面设计已获用户确认，进入实施计划。
> 目标版本：v0.4.1。
> 基线：已发布的 `v0.4.0`，合并提交 `b95f12b02b97bda93bd75fa35c5f09f6ae3fa652`。

## 1. 目标

v0.4.1 是一次**演示可靠性版本**，不是视觉重构版本。它解决现场答辩中最容易造成流程中断的问题：

1. 页面之间存在导航死路，尤其是调参实验室无法返回首页；
2. 启动前缺少统一环境检查，容易到演示现场才发现前端未构建、端口被占用或目录不可写；
3. 现有浏览器冒烟主要使用 Mock API，没有覆盖真实 FastAPI、SQLite、上传和建模任务；
4. 演示数据、讲解顺序、离线降级和备用证据没有集中为一份可执行手册；
5. 部分状态文档仍保留 v0.4 开发分支、旧测试数和“功能未实现”等过时描述。

完成后，应能在一台已安装依赖的 Windows 答辩机上，用一套固定步骤稳定演示：

```text
启动前检查
→ 启动平台
→ 通用三维数据上传与建模
→ 排行榜与三维切片
→ 正式选择与导出
→ 返回首页
→ 内置电阻率 SuperMap 成果与证据链
```

## 2. 方案选择

### 2.1 未采用：只修返回按钮

优点是改动最少；缺点是没有降低启动、真实前后端联调和演示资料方面的风险，不能称为完整的答辩加固。

### 2.2 采用：演示可靠性加固

在不重做视觉布局的前提下，补齐导航、预检、启动脚本、固定样例、真实浏览器验收、运行手册和状态文档。这些改动范围明确，能够直接降低现场失败概率。

### 2.3 未采用：提前重做 UI 与三维渲染

页面布局、组件位置、主题和渲染表现将在答辩前另设视觉版本统一处理。现在重做会扩大回归面，也可能因后续案例和讲解内容变化再次返工。

## 3. 范围

### 3.1 v0.4.1 必做

- 数据准备、调参实验、实验详情和成果工作台的连续导航；
- 加载失败页面的安全返回入口；
- 固定、便携、无私有数据的三维演示样例；
- 可测试的 `geomodeling demo-check` 启动前检查；
- Windows 单机演示启动脚本；
- 真实 FastAPI + 临时 SQLite + 浏览器的端到端验收；
- 通用建模与内置电阻率双演示路径；
- 答辩运行手册、故障降级方案和演示证据；
- README、当前状态、产品蓝图和版本号同步；
- v0.4.0 全部回归能力保持不变。

### 3.2 明确不做

- 首页、卡片、表单、排行榜和成果页的整体视觉重构；
- 新的主题、动画、响应式布局体系或设计系统；
- Cesium/SuperMap 渲染效果重写；
- 微震 3σ 派生流程代码化和第二案例接入；
- 瓦斯体元崩溃排查；
- 新插值算法、任意斜切面或原生等值面；
- iServer 工作空间全自动发布；
- 账户、云部署、多人协作或生产级任务队列。

## 4. 导航设计

### 4.1 原则

- 所有主要页面都必须有离开当前页面的明确入口；
- “返回首页”固定进入命名路由 `home`，不调用浏览器 `history.back()`；
- 从深链接直接打开页面时，导航仍然可用；
- 离开实验详情不会取消后台任务，任务继续按 SQLite 持久化状态运行；
- 本版本只增加小型导航组件，不引入全局 AppShell 或重排页面。

### 4.2 页面行为

| 页面/状态 | 顶部导航 | 行为 |
|---|---|---|
| 新建案例 | 返回首页 | 已有行为保留并纳入统一测试 |
| 数据准备向导 | 返回首页 | 直接进入 `home`；不删除已上传数据 |
| 调参实验室：新建 | 返回首页 | 直接进入 `home`；未提交表单不持久化 |
| 调参实验室：实验详情/排行榜 | 返回首页、新建实验 | 返回首页不取消任务；新建实验沿用当前案例 |
| 成果工作台 | 返回实验、返回首页 | 返回实验进入所属实验详情；返回首页进入 `home` |
| 任一加载失败状态 | 返回首页 | 不要求故障对象成功加载后才显示 |

实现上允许增加一个轻量 `PageNavigation` 组件，接收 `home`、`backToExperiment`、`newExperiment` 等有限动作。组件只统一交互和可访问名称，不决定整个页面布局。

### 4.3 可访问性与测试定位

- 使用带文字的按钮或链接，不使用只有箭头、没有可访问名称的图标；
- 键盘可以聚焦和触发；
- 统一提供 `data-test`，至少包含 `nav-home`、`nav-experiment`；
- 不使用动态拼接的外部 URL。

## 5. 双演示路径

### 5.1 路线 A：通用建模现场闭环

标准讲解顺序：

1. 首页新建案例；
2. 上传固定三维演示 CSV；
3. 映射 `X/Y/Z/value`，声明局部线性坐标和属性单位；
4. 展示质量门禁和有效行数；
5. 创建一组 IDW 实验并运行；
6. 运行或展示一组普通 Kriging 实验；
7. 解释空间折分、公共有效集合、覆盖率和排行榜；
8. 打开正式候选成果；
9. 查看完整三维场以及 X/Y/Z 三方向切片；
10. 填写选择理由，登记正式模型；
11. 导出证据 ZIP；
12. 返回首页。

实时演示以可在 5–7 分钟完成为目标，但不在 CI 中设置容易受机器性能影响的严格秒数门槛。

### 5.2 路线 B：内置电阻率成果

从首页进入只读电阻率案例，展示：

- 五模型排行榜和正式成果身份；
- 实测点云、S3M 体元格点和叠加切换；
- 阈值过滤、颜色表和 Z 夸张；
- iServer 服务探测与六级发布证据链；
- iServer 离线时“未验证但建模证据不丢失”的降级语义。

路线 B 是 SuperMap 技术链路展示，也是路线 A 遇到临时计算或浏览器问题时的答辩兜底，不替代路线 A 的通用上传能力。

## 6. 固定演示数据

### 6.1 数据要求

仓库增加一份明确标记为**人工演示样例**的三维 CSV：

- 不来自原始论文、私有资料或真实矿区；
- 行数足以通过 3D 质量门禁并快速完成 IDW/Kriging；
- 坐标和值域可生成容易辨认的三维梯度与切片；
- 字段名、单位、坐标类型和推荐映射写入同目录说明；
- 保存固定 SHA-256，防止演示数据被静默替换。

建议路径：

```text
demo/
  platform_demo_3d.csv
  README.md
```

`demo/platform_demo_3d.csv` 是唯一权威演示文件。需要同一数据的测试直接读取该文件，不再维护第二份同内容 CSV；专门的契约测试固定其 SHA-256。

### 6.2 浏览器入口

首页“新建建模案例”附近增加低权重的“下载演示数据”入口。它调用
`GET /api/demo/datasets/platform-demo-3d` 下载 CSV，不自动创建案例、不跳过上传、不预写结果，以证明现场确实执行了通用流程。

下载由平台自身提供稳定资源，不暴露本机路径。资源缺失或哈希不符时，启动前检查必须阻断演示启动。

## 7. 启动前检查与 Windows 启动脚本

### 7.1 `geomodeling demo-check`

新增只读检查命令：

```powershell
geomodeling demo-check
geomodeling demo-check --json
geomodeling demo-check --host 127.0.0.1 --port 8000
```

检查项分为两级：

**阻断项（任一失败返回退出码 1）**

- Python 包和配置能够加载；
- `web/dist/index.html` 存在；
- 演示 CSV 存在且 SHA-256 匹配；
- `GEOMODELING_DATA_DIR` 可创建、可写；
- SQLite 可以初始化并关闭；
- 指定的 API 端口（默认 `127.0.0.1:8000`）没有被不明进程占用；
- 必要的模型与 API 路由可以导入。

**可选警告（仅警告，整体仍返回 0）**

- iServer 未启动或服务不可用；
- S3M 缓存服务不可访问；
- 没有配置 iServer 管理凭据。

输出必须区分 `passed`、`warning`、`blocked`，不得把 iServer 离线误报为通用建模不可用。`--json` 使用固定契约，便于自动测试和启动脚本消费。

### 7.2 `scripts/start_demo.ps1`

脚本职责：

1. 设置或接受独立的 `GEOMODELING_DATA_DIR`，默认 `var/demo_v041`；
2. 调用 `geomodeling demo-check`；
3. 阻断项失败时停止并打印修复命令；
4. 以单进程启动 FastAPI；
5. 默认打开 `http://127.0.0.1:8000/`，支持 `-NoBrowser`；
6. 不安装依赖、不删除数据、不杀死未知进程、不写入凭据。

脚本必须在前台保留后端日志，方便现场诊断。若端口上已经是当前平台健康实例，应提示复用，而不是当作不明占用或强制结束进程。

## 8. 真实浏览器端到端验收

### 8.1 保留现有 Mock 冒烟

现有 Playwright Mock API 流程继续用于快速验证页面契约和导航，不因新增真实流程而删除。

### 8.2 新增 Live E2E

CI 新增真实链路：

```text
临时 GEOMODELING_DATA_DIR
→ 启动单进程 FastAPI
→ Chromium 打开真实前端
→ 创建案例并上传演示 CSV
→ 字段映射和质量校验
→ 运行一组 IDW
→ 轮询至成功
→ 打开排行榜和成果
→ 验证完整场与 X/Y/Z 切片入口
→ 正式选择
→ 下载导出包
→ 返回首页
```

要求：

- 不使用相邻只读资料、iServer、管理员凭据或本机绝对路径；
- 使用唯一临时数据目录和端口；
- 测试结束后关闭服务，不残留后台进程；
- 测试失败时保留 Playwright trace、截图和服务日志作为 CI 工件；
- 对任务完成使用有界轮询，不使用固定长时间 `sleep`；
- CI 只跑一组轻量 IDW，Kriging 由后端测试和人工完整演示覆盖，避免浏览器 CI 过慢或抖动。

## 9. 故障降级与现场恢复

答辩手册必须明确以下场景：

| 场景 | 预期表现 | 现场处理 |
|---|---|---|
| iServer 离线 | 通用建模可用；内置电阻率服务状态为不可用/未知 | 继续路线 A，使用已保存截图讲解发布链 |
| 浏览器刷新 | 当前案例、实验、任务和成果由路由 ID 与 SQLite 恢复 | 重新进入原 URL 或从首页案例卡进入 |
| 任务失败 | 失败候选和错误码保留，可修改参数或重试 | 不删除失败证据 |
| 任务仍在运行时返回首页 | 后台继续运行 | 再次进入案例或实验查看状态 |
| 演示 CSV 被修改 | `demo-check` 哈希阻断 | 恢复仓库版本，不静默继续 |
| API 端口被占用 | 检查阻断并给出诊断 | 不自动结束未知进程 |
| 现场无法实时计算 | 不伪造实时成功 | 使用预先验证截图和导出包，说明它们是备用证据 |

## 12. 测试策略

### 12.1 前端单元测试

- 新建实验和实验详情均显示 `nav-home`；
- 数据准备向导和成果工作台显示正确导航；
- 点击返回首页进入命名路由 `home`；
- 返回实验携带正确 `experimentId`；
- 加载失败时仍能返回首页；
- 返回首页不调用取消任务 API。

### 12.2 后端测试

- `demo-check` 全通过、可选警告和阻断三种结果；
- `--json` 契约稳定；
- 演示数据哈希、缺失和被修改；
- 数据目录不可写或 SQLite 初始化失败；
- 端口为空、当前平台已运行和未知进程占用；
- 演示样例下载不包含绝对路径或私有数据。

### 12.3 浏览器测试

- 现有 Mock Playwright 流程继续通过；
- 新增真实 FastAPI Live E2E；
- Live E2E 产物在失败时上传 CI。

### 12.4 回归

- v0.4.0 后端全量测试不得减少；
- `local_data` 继续保持只读和哈希不变；
- 前端 unit、type-check、build 全通过；
- v0.3.1 电阻率路线和 S3M fail-closed 契约不变；
- `git diff --check` 和危险文件扫描通过。

测试数量只作为结果记录，不写死为验收条件；验收条件是既有测试不删除、所有适用测试成功。

## 13. 验收标准

v0.4.1 只有同时满足以下条件才可发布：

1. 所有主要页面和加载失败页面均无导航死路；
2. 正在运行的任务返回首页后仍能恢复查看；
3. `demo-check` 能准确区分阻断项和 iServer 可选警告；
4. Windows 启动脚本不删除数据、不安装依赖、不结束未知进程；
5. 固定演示 CSV 可下载、哈希固定、来源明确；
6. 通用三维路线在全新临时数据目录中完整走通；
7. 内置电阻率路线在 iServer 在线时可演示，离线时正确降级；
8. Mock E2E 与 Live E2E 均通过；
9. 运行手册、状态文档和实际代码一致；
10. 不含私有资料、管理员凭据、本机绝对路径、UDBX、S3M 缓存或运行产物；
11. PR 审查和 CI 完成后再合并；
12. 合并后 main CI 成功，再创建 annotated `v0.4.1` 标签和正式 Release。

8. 当前状态、README、蓝图、架构和验收文档同步；

10. 真实 Windows 浏览器彩排、PR 审查、合并与发布。

## 15. 风险与控制

| 风险 | 控制 |
|---|---|
| Live E2E 增加 CI 时间和偶发性 | 只跑轻量 IDW；有界轮询；独立端口和临时目录；失败上传 trace |
| 启动脚本误伤本机环境 | 不安装、不删除、不杀进程；默认独立数据目录 |
| 演示样例与测试样例漂移 | 指定权威文件并校验 SHA-256 |
| iServer 现场不稳定 | 设为可选警告；保留通用路线和筛选后的备用证据 |
| 小修演变成 UI 重构 | 将布局、主题、动画和渲染改造明确列为非目标 |
| 文档再次过期 | 当前状态只写已验证事实；版本号和文档链接进入自动检查 |

## 16. 发布边界

开发必须从 `v0.4.0` 的 `main` 建立 `feat/v0.4.1-demo-hardening` 分支，通过 PR 交付。未经用户明确批准不得：

- 直接合并 PR；
- 创建 `v0.4.1` 标签或 Release；
- 删除功能分支；
- 开始 v0.5、微震接入或视觉重构。
