# 分析文案口语化设计

## 目标

让非专业评委先读懂“哪里有异常、可能说明什么、接下来做什么”，不再被“口径、证据边界、探索性支持”等汇报式措辞打断。

## 范围

- 修改首页、成果分析、分析中心、模型评估和 AI 辅助区的用户可见文案。
- 优先处理地质研判卡、关键发现、异常占比、模型指标说明和限制提醒。
- 不修改算法、阈值、计算结果、API 字段、错误码、数据契约和内部注释。

## 文案结构

不使用“结论 / 原因 / 影响 / 下一步”四段式模板。每张卡采用自然叙述：

- 标题直接指出异常类型和区域。
- 正文用两三句话连贯说明位置、异常程度、常见成因和实际意义；不同属性使用不同说法，不套同一语序。
- 卡片底部只保留一个具体动作，例如“对照钻孔与水文记录”或“检查测线覆盖与岩性资料”。
- 真正影响判断的限制以一句“注意”呈现；数值来源和算法细节放入可展开的“计算说明”。

## 用词规则

- “验证口径”改为“比较条件”或“计算方式”。
- “证据边界”改为“注意”。
- “探索性”徽标改为“建议复核”；必要时在注意事项中说明尚未现场确认。
- “网格支持体积/面积”改为“模型覆盖范围”；技术单位放入折叠的计算说明。
- “不构成……”改为“不能只凭这项结果判断……”。
- 技术名词 RMSE、R²、p25/p75 可保留，但旁边补一句自然语言解释。
- 不在界面中显示“事实 / 可能解释 / 潜在影响 / 建议核查”固定栏目名。

## 验收

- 专业案例仍显示正确的属性类型、异常方向和数值。
- 首页和成果页主阅读区不再出现“证据边界”“验证口径”“探索性网格支持口径”。
- 必要限制仍在，且不会把异常区写成已经确认的含水区、断层、危险区或安全区。
- 相关后端、前端单元测试和成果页浏览器测试通过。
