## 4. 探索路线与教训

### 4.1 成果页点云

现象：浏览器能看到彩色散点，调色、阈值和抽稀都有效，但点之间没有体积遮挡、连续采样或切片。

结论：

- 插值成果是规则网格，不等于当前渲染方式是体渲染；
- `PointPrimitiveCollection`、点精灵或稀疏方块不能作为连续体成功判据；
- 后续验收必须检查真实渲染器类型和参数变化的像素响应。

### 4.2 S3M 模型缓存叠加 `.vol`

人工操作曾生成并发布：

```text
cache name:
VOL_OVERLAY_35348bb3be03_54c313c9328f

example .vol:
D:\Supermap\Project\supermap-volume\carrier-cache\batchModelCache\
  Tile_-0005_-0001_0000\Tile_-0005_-0001_0000_VOL_OVERLAY_35348bb3be03_54c313c9328f.vol

iServer realspace:
http://127.0.0.1:8090/iserver/services/3D-local3DCache-batchModelCache/rest/realspace
```

已确认 `.vol` 内确实包含 11³ 数值和值域，但最终画面只有灰色载体。关键诊断：

- S3M config 使用 `crs=epsg:0`、`position.unit=Meter`；
- 模型局部范围和 `.vol` 范围采用局部米制坐标；
- SuperMap3D 12.1 的体元采样路径会把相应位置按地理坐标路径计算，再和 `.vol` X/Y 范围比较；
- 当前坐标契约不能得到有效采样坐标；
- 部分 LOD 子 `.s3mb` 没有对应子 `.vol`，请求出现 404；
- 修改 ColorTable、透明度、混色方式或升级旧 Cesium 不能把错误的数据/坐标契约变成连续体。

教训：S3M 是发布和性能容器，不是首个体渲染真伪判据。必须先用更短链路证明数据能被原生体采样，再考虑缓存生产化。

### 4.3 GeoTIFF 切片和 `DatasetVolume`

本轮生成了 11 张带 WGS84 显示锚点的 GeoTIFF，并在 iDesktopX 中完成过导入、载体模型和服务探索。代码现已包含：

```text
src/geomodeling/platform/supermap_volume.py
tests/test_supermap_volume_export.py
```

这条路线的价值：

- 保留了 iDesktopX/`DatasetVolume` 动态体数据集的可能性；
- 固化了局部工程米制坐标到 WGS84 显示锚点的转换；
- 固化了切片顺序、像元中心、Y 翻转、NoData、值域和 SHA-256 契约。

局限：

- 人工操作步骤多；
- iDesktopX 2026 的菜单和文档名称不稳定；
- `DatasetVolume`、载体、发布服务和浏览器 Volume API 会同时引入多个排障变量；
- 当前 `display_anchor_only` 只是显示位置，不是真实地理配准。

因此它不再是 v0.6.1 的首个最小验证路线，但相关导出器仍被 NetCDF 路线复用。

### 4.4 `/volume-demo` WebGL2 光线步进

远端 PR #10 已完成：

```text
/volume-demo
WebGL2 3D texture + ray marching
```

它和 `VoxelGridLayer3D` 的区别：

| 项目 | `/volume-demo` | `VoxelGridLayer3D + NetCDF` |
| --- | --- | --- |
| 核心渲染器 | 项目自研 WebGL2 shader | SuperMap3D 原生体素图层 |
| 输入 | 项目编码后的 3D texture | NetCDF v3 文件 |

两者都已经有价值。不要再问“只能二选一”；正式设计可以把 SuperMap 原生路线作为主展示，把 `/volume-demo` 作为对照、兼容性后备或性能基准，但 UI 必须明确当前使用哪种渲染器。

### 4.5 `VoxelGridLayer3D + NetCDF`

最终成功链路：

```text
grid.npz
  -> deterministic NetCDF classic/v3
  -> FastAPI .nc endpoint
  -> SuperMap3D 12.1 scene.addVoxelGridLayer()
  -> startRender({ variableName, xDimName, yDimName, zDimName })
  -> VolumeRendering / Slice / ContourValue
```

它成功的关键是把格式、坐标、相机和渲染参数分阶段验证，而不是在一个页面里同时修改所有变量。

### 7.1 六条重要实测事实

1. `startRender` 前要等图层首帧写入 `_frameState`，否则内部读取 `mode` 会报错。
2. 当前构建包的 `layerBounds` 要用裸角度 `new SuperMap3D.Rectangle(w,s,e,n)`；内部还会执行 `fromDegrees`。直接使用 `Rectangle.fromDegrees` 会双重换算。
3. 相机需要 `lookAt` 体数据中心；只设置相机位置但没有正确指向目标会产生黑屏假阴性。
4. 当前构建包的 `opaqueRate` 不进入着色器 uniform，实测是 no-op；透明度要通过 `opacityTransferFunction` 控制。
5. `ColorTransferFunction.addRGBPoint` 的 RGB 分量使用 0 到 1 浮点，不是 0 到 255。
6. `minFiltration/maxFiltration` 可以实时更新并产生像素响应，不需要重建图层。

### 7.2 文档参数名错误

本机生成的 `VoxelGridLayer3D.html` 将变量名参数错误显示为 `options.setDataBounds`。实际构建包要求：

```js
layer.startRender({
  variableName: "rho",
  xDimName: "x",
  yDimName: "y",
  zDimName: "z",
});
```

不能把 `variableName` 改回 `setDataBounds`。

两个名字是私有函数。整合时应将通用坐标和哈希逻辑移到稳定共享模块，或明确升级为公共 API，避免 GeoTIFF 模块重构时破坏 NetCDF。

### 11.4 SciPy mmap 测试警告

目标测试通过但出现 8 条 `netcdf_file` mmap 关闭警告。测试读文件时使用 `mmap=False`，或在关闭前复制所有引用数组，保持测试输出干净。

### 11.5 能力边界

当前仍未验证：

- 大于 11³ 的实际性能、内存和完整文件下载成本；
- 32³、64³、128³ 等分辨率的浏览器上限；
- WebGPU `contextType=3`；
- 真实 EPSG/控制点地理配准；
- iServer 或 S3M 生产发布；
- 移动端和集成显卡兼容性；
- POC 页面接入正式成果页、权限和成果状态机。
