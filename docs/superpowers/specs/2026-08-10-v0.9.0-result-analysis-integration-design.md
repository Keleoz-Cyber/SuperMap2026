# v0.9.0 成果级分析与三维异常联动设计

日期：2026-08-10
状态：待用户复审
目标分支：`feat/v0.9.0-visual-product`

## 1. 背景与问题

正式系统已经具备连续体、单轴切片、等值面、传递函数和专业异常提取，但成果页的关键发现仍读取数据集级 `analysis-summary`。这会把插值前样本的空间统计与插值后规则网格混在同一成果语境中。

独立视觉原型展示了高值体元占比、重点深度层段、A/B 连通区、当前切片高值占比和模型研判，但其中具体数字与结论是写死的。正式产品必须用可追溯计算替换这些内容。

## 2. 目标

1. 为已物化的 2D/3D 成果提供只读、确定性、可追溯的成果级分析。
2. 从正式规则网格计算值域、分位阈值、高/正常/低值组成、深度分层和连通区预览。
3. 将连通区的真实质心、包围盒、峰值和支持量接入三维场景。
4. 让“分析研判”和“分析证据”共享同一结果身份、阈值和计算版本。
5. 保留数据集级质量/分布证据，但明确标记为“输入样本证据”。

## 3. 非目标

- 不修改 IDW、Kriging、DSI-like 或正式模型选择逻辑。
- 不用生成式模型编写地质结论；研判文案只来自确定性模板。
- 不把网格支持量命名为储量、危险体积或真实地质体积。
- 不在 GET 页面加载时创建数据库记录或不可变专业工件。
- 不承诺连续体与切片双图层同时渲染；现有三种渲染模式仍保持互斥。
- 不实现任意斜切、真实地理配准或跨案例叠加。

## 4. 方案比较

### 方案 A：前端拼接现有接口

前端同时请求数据集分析、切片分析和专业分析，再自行生成统计与结论。

优点是后端改动少；缺点是统计口径分散、成果身份难锁定、前端容易把样本比例当体元比例。拒绝采用。

### 方案 B：所有分析都保存为不可变任务工件

用户先显式运行分析任务，成功后成果页读取工件。

证据最强，但首次打开没有内容、交互阈值成本高，也会增加数据库迁移和任务状态。保留给专业异常提取，不作为成果页基础分析。

### 方案 C：确定性只读成果摘要 + 显式专业保存

新增只读成果分析接口，从已物化网格即时计算并以网格哈希缓存；专业异常保存继续复用既有 POST 任务。

该方案兼顾打开即看、结果真实性和现有证据合同，作为本次实现方案。

## 5. 后端设计

### 5.1 成果分析服务

新增独立模块 `geomodeling.platform.result_analysis`，职责仅包括：

- 加载已物化规则网格；
- 校验轴、形状、NoData 和有限值；
- 计算完整场统计；
- 计算统一阈值和组成；
- 计算 Z 向分层；
- 调用现有连通区内核生成有界预览；
- 生成受控的结构化发现。

模块不得访问 HTTP，不得写数据库，不得自行物化结果。

### 5.2 API

新增：

```text
GET /api/results/{result_id}/analysis-summary
```

查询参数：

- `depth_bins`：默认 8，范围 2–32；2D 结果忽略并明确返回 `not_applicable`；
- `component_limit`：默认 8，范围 1–20；
- `min_support_nodes`：默认 2，范围 1–10000。

响应主要字段：

```text
identity
  result_id, grid_sha256, analysis_version, dimension, coordinate_type
variable
  name, unit
grid
  shape, valid_count, nodata_count, min, max, mean, median, p25, p75
thresholds
  low, high, source, method
composition
  low/normal/high count and ratio
depth_profile
  status, bins[] {z_lower, z_upper, valid_count, mean, high_count, high_ratio}
components_preview
  threshold, connectivity_rule, total, returned,
  rows[] {rank, label, support_node_count, support_measure, support_unit,
          bounds, centroid, value_min, value_max, value_mean,
          touches_grid_boundary, uncertainty summaries}
model_evidence
  algorithm, metrics, common_valid_count, formal_selection
findings[]
  id, kind, title, statement, evidence[], confidence, limitations[], spatial_target
provenance
  grid_sha256, calculation_version, threshold_method
```

### 5.3 统计口径

- 有效体元：`is_nodata == false` 且值有限。
- 默认低/高阈值：完整成果有效体元的 p25/p75，NumPy linear 分位法。
- 组成：按有效规则网格节点计数，必须称“体元节点占比”或“网格支持占比”。
- 深度分层：按 Z 轴坐标范围等距分箱；每个网格节点只进入一个层段；最后一箱包含上界。
- 高值连通区：`value >= p75`，规则 3D 网格使用既有六邻接；2D 使用四邻接。
- 连通区排序：先按 `support_measure` 降序，再按 `value_max` 降序，再按原始 component_id，保证稳定。
- 标签：前 26 个按 A–Z，仅作为当前摘要中的稳定显示标签，不写回专业工件。
- 支持量沿用 `volume_coordinate_unit3`/`area_coordinate_unit2`，页面不得换名为“真实体积/面积”。

### 5.4 切片统计

扩展现有 slice-analysis 响应，增加完整场统一阈值及当前切片：

- `low_count`、`normal_count`、`high_count`；
- `low_ratio`、`normal_ratio`、`high_ratio`；
- `thresholds` 与成果摘要完全同口径。

现有 count/min/max/mean/std/p10/p50/p90 字段保持兼容。

### 5.5 缓存与失败语义

- 进程内有界 LRU，以 `grid_sha256 + analysis_version + query parameters` 为键；不持久化。
- 结果未物化、网格哈希不符、轴非递增、形状不符、无有效体元时 fail-closed。
- 不返回部分旧摘要；错误使用平台统一错误封套。

## 6. 三维协议与场景

### 6.1 异常覆盖层

在 iframe v2 完整状态中增加可选 `annotations`：

```text
annotations[]
  id, label, local_position[x,y,z], bounds, value_max,
  support_measure, support_unit, color, visible
focused_annotation_id
```

iframe 使用现有 display-anchor 坐标变换，将真实局部坐标映射到 SuperMap3D 场景。标注由点、短引线和文字组成，随相机旋转，不使用父页面固定像素定位。

### 6.2 双向联动

- 点击研判中的连通区：三维聚焦该质心并高亮对应标注。
- 点击三维标注：向父页面回报组件 ID，右侧切换到对应组件详情。
- 切片变化：证据区读取权威 slice-analysis，更新当前切片比例。
- 切换成果或网格哈希：立即清空旧标注和旧发现，禁止跨结果残留。

### 6.3 场景辅助

- 保留现有包围盒；
- 增加可开关的 XYZ 轴向和 Z 深度刻度；
- 增加等轴、俯视 XY、正视 XZ、正视 YZ 四个相机预设；
- 标注与辅助元素不得遮挡体渲染主体，组件过多时仅显示排序前 N 个。

## 7. 成果页设计

### 7.1 显示工具

继续使用真实的 Volume/Slice/Contour、色带、标度、过滤、透明度、光照、渐变透明度、包围盒和辅助点能力。相机预设与异常标注开关进入同一工具区。

### 7.2 研判区

研判区改为四类真实信息：

1. **成果概览**：完整场组成、重点层段、正式模型、主要限制；
2. **异常区域**：A/B/C 连通区列表，显示峰值、网格支持量、中心、边界接触和不确定性；
3. **当前切片**：坐标、有效体元、均值、高/正常/低值占比，与完整场差值；
4. **模型与不确定性**：公共有效指标、不确定性层是否存在、边界说明。

不再使用“结论链”“行动链”等生硬命名。没有对应证据的模块显示明确空态。

### 7.3 分析证据

同一证据区提供：

- 成果组成环图；
- 深度趋势与分层表；
- 连通区支持量/峰值比较；
- 当前切片热力图与统计；
- 模型指标和残差；
- 输入样本质量/分布；
- 成果与数据溯源。

所有图表必须标注“输入样本”或“成果网格”，不能混用。

## 8. 结构化研判规则

后端只生成下列受控发现：

- `dominant_depth_interval`：高值占比最高且有效体元大于零的层段；
- `largest_high_component`：网格支持量最大的高值连通区；
- `boundary_contact`：主要连通区是否接触网格边界；
- `formal_model`：显式正式模型及公共有效指标；
- `uncertainty_availability`：不确定性证据存在、缺失或不适用。

每条发现必须包含数值依据、结果身份、计算版本、可信状态和限制。不得自动生成含水性、危险性、储量或成矿解释。

## 9. 测试策略

### 9.1 后端

- 合成 2D/3D 网格统计与分位阈值；
- NoData/NaN/Inf 不参与统计；
- 分层边界不重复不遗漏；
- 连通区稳定排序、A/B 标签、边界接触；
- 结果未物化、网格损坏、零有效值 fail-closed；
- slice-analysis 新旧字段兼容；
- 同 grid hash 响应确定性一致。

### 9.2 前端

- 新 DTO 严格解析；
- 结果切换清空旧分析；
- 研判点击发送真实组件定位；
- 三维点击反向选择组件；
- 数据集级与成果级标签明确；
- 缺少组件、不确定性或 2D 深度信息时显示真实空态；
- iframe 异常标注协议拒绝非法坐标和过期 revision。

### 9.3 浏览器验收

- 真实电阻率成果可看到体渲染、真实 A/B 标注和真实成果统计；
- Volume/Slice/Contour 三模式均保持像素门；
- 切换切片后切片统计更新；
- 点击连通区后相机或高亮发生可验证变化；
- 控制台错误、pageerror 和未解释网络失败为零；
- 1920×1080 首屏无溢出，普通笔记本布局不遮挡三维主体。

## 10. 验收条件

1. 页面不再包含原型中写死的 25.6%、44.0%、127.28、8.4% 等业务值。
2. 每个成果分析数字都能追溯到 `result_id + grid_sha256 + calculation_version`。
3. 连通区表格与三维标注来自同一响应，组件 ID 和统计一致。
4. 当前切片高值比例由服务端真实切片值计算，不由前端估算。
5. 输入样本分析与成果网格分析在标题、DTO 和导出中均明确区分。
6. 专业异常提取的显式保存合同、现有 NetCDF 资产和插值流程不回归。

## 11. 实施边界

本设计可分为后端合同、三维协议、成果页集成和真实验收四个连续阶段，但作为同一功能批次交付。任何阶段失败都不得用静态原型或模拟数值回退。
