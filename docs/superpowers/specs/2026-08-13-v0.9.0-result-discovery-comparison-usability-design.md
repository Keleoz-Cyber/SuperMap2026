# v0.9.0 成果发现、模型比较与首页三维可用性整改设计

## 1. 背景与目标

本设计处理 v0.9.0 机器学习分支真实页面验收发现的四项问题：

1. 电阻率单位在部分历史成果与页面中仍显示为“RHO 单位待来源确认”，而权威单位已经确定为 `Ω·m`；
2. 用户实验成果缺少案例内的直接入口，用户被迫进入模型比较页寻找成果；
3. 首页三维主舞台的渲染控制区位置拥挤，渲染窗口下方存在无意义空白；
4. 模型比较把“并排了解成果”和“使用统一口径排名”绑定在一起，导致大量真实成果无法比较。

目标是改善成果发现和对照流程，同时保留空间验证的科学约束。此次整改不修改 ML 算法、插值算法、NetCDF 或 SuperMap 渲染协议，也不增加新的平行工作台。

## 2. 产品原则

- 案例工作台是案例内数据、实验和成果的主目录；模型比较只是成果分析工具，不承担成果入口职责。
- “可以并排查看”不等于“可以统一排名”。验证口径不同时允许对照，但不得生成最佳结论。
- 单位来自案例和数据版本的权威配置，不由页面自行硬编码或从历史说明文案猜测。
- 首页三维舞台优先保证可观察面积和控制效率，不用装饰内容填补空白。
- 所有视觉结论必须在当前 8000 演示服务的真实页面中验收，不以静态预览代替。

## 3. 电阻率单位全链归一化

### 3.1 权威来源

电阻率预置配置 `config/presets/resistivity.json` 中的 `value_unit: "Ω·m"` 是唯一权威单位。案例摘要、数据版本 mapping、分析摘要、成果 metadata、渲染 manifest、切片/剖面导出和前端标签均应使用该值。

### 3.2 兼容旧运行库

旧运行库可能保存以下历史值：

- `RHO 单位待来源确认`；
- 空字符串或缺失单位；
- 与电阻率变量 `RHO` 绑定的旧说明字段。

后端在组装对外 DTO 时根据明确的电阻率案例/profile/变量身份将这些旧值归一化为 `Ω·m`。归一化不得把任意用户上传的 `RHO` 字段自动认作电阻率预置案例；用户数据仍以其 mapping 为准。新建和重新物化的电阻率成果直接写入权威单位。

前端只消费 DTO 的单位，不保留“待来源确认”回退文案。既有 evidence 文件作为历史证据不回写。

### 3.3 验收

首页、电阻率案例工作台、官方成果、用户成果、分析中心、切片与剖面导出均显示 `Ω·m`；微震 `km/s`、瓦斯 `ml/g` 和用户自定义单位不受影响。

## 4. 案例工作台成果目录

### 4.1 信息结构

案例工作台“成果分析”阶段拆为两个连续区域：

- **主打成果**：正式/官方成果保持醒目，但不独占整个成果阶段；
- **实验成果**：列出当前案例各实验产生的成功候选，按实验分组，默认最近实验在前。

每个实验组显示实验名称、创建时间、验证方法和运行状态。每个候选行显示：

- 算法名称与关键参数摘要；
- RMSE、MAE、R²、Bias 中已有的指标；
- 成果状态：可查看、待生成、生成中或生成失败；
- 与状态匹配的明确动作。

### 4.2 动作规则

- 已物化且存在成果 URL：主动作“查看成果”；
- 候选成功但未物化：主动作“生成成果”；
- 运行尚未成功或成果失败：提供“查看实验”，不显示不可兑现的成果按钮；
- “模型对照”作为该数据版本的次级动作，进入对照页；
- 官方成果若同时出现在最近候选中，需按 `result_id` 去重，不显示两张重复卡。

案例工作台主动作仍遵守单一主动作原则；成果列表内部的按钮属于对象级命令，不与页面主动作竞争。

### 4.3 数据合同

优先扩展工作台 DTO 的 `recent_results`，让每个条目具备稳定的：

- `result_id`、`experiment_id`、`experiment_name`；
- `algorithm`、`parameters_summary`；
- `metrics`、`validation_summary`；
- `materialization_status`、`url`；
- `created_at`。

后端只返回当前案例所属结果，候选、Run、Experiment、DatasetVersion、Case 的归属链必须完整。前端不通过拼接 URL 或额外遍历所有实验推断成果身份。

## 5. 首页三维主舞台布局

### 5.1 桌面布局

首页仍保持“案例列表 / 三维舞台 / 关键发现”的主结构。中央舞台内部调整为：

1. 紧凑案例标题与状态操作带；
2. 三维内容区；
3. 与三维内容同高的渲染控制层。

渲染参数面板相对标题向下留出稳定间距，不贴住舞台顶边。面板顶部与实际三维画布顶部对齐，而不是与整个卡片顶部对齐。

### 5.2 高度与空白约束

- `scene-panel`、`scene-body` 和渲染组件使用连续的 flex/grid 高度链；
- 三维内容区占满网格第一行剩余高度，控制面板和 iframe/画布底部对齐；
- 移除造成固定小画布或额外底部空白的 `height`/`min-height` 冲突；
- 底部证据带保持独立第二行，只占其内容所需高度，不挤压三维区；
- 1440×900 下三维画布应成为中央区域主体，舞台底部不出现大块无功能空白。

### 5.3 响应式

桌面验收尺寸为 1440×900 和 1920×1080。390×844 沿用显式打开全屏三维的既有策略，确保无横向溢出；此次不把桌面控制面板机械压入手机首屏。

## 6. 双层模型比较

### 6.1 第一层：成果对照

满足以下条件的 2–4 个成功候选可以进入成果对照：

- 属于同一数据版本；
- 候选和所属 Run 均成功；
- 具有可识别的算法、指标和数据身份。

成果对照并排显示算法、参数、各自验证方法、RMSE/MAE/R²/Bias、网格和值域摘要，并提供“查看成果”。指标保持各自原始口径，不换算、不混排。

当验证口径不同，页面显示普通提示：

> 这些成果使用了不同的验证规则，可以查看差异，但不能据此判断谁最好。

页面继续展示内容，不再以“不兼容”错误态阻断。

### 6.2 第二层：严格排名

只有现有严格合同全部成立时才计算排名：

- 同一数据版本；
- 验证方法、折数、种子和 holdout 一致；
- fold fingerprint 一致；
- 公共有效集 fingerprint 和数量一致；
- 用于排名的指标有限；
- 其他既有公平比较约束一致。

严格排名才允许展示序号、“最佳”徽标、推荐结果、差值和相对普通克里金变化。后端继续是排名资格与结果的权威来源。

### 6.3 差异解释和纠正动作

不满足严格排名时，将机器错误码映射为用户可理解的差异，例如：

- “验证方法不同：一个使用空间 5 折，另一个使用留出验证”；
- “验证分组不同：两次实验评估的空间区域不完全一致”；
- “公共评估样本不同：直接比较误差会失真”；
- “有成果缺少完整指标，可查看模型但不能参与排名”。

提供“创建统一验证实验”次级动作，带入当前数据版本和一组明确的统一验证配置。该动作只创建实验草稿，不自动运行，也不修改已有实验。

### 6.4 API 结果形态

比较 API 将“是否可展示”和“是否可排名”分离，返回：

- `comparison_items`：可对照候选及其原始指标；
- `ranking.status`：`ranked` 或 `not_ranked`；
- `ranking.items`：仅 `ranked` 时存在；
- `compatibility.differences`：结构化差异及通俗说明；
- `unified_experiment_draft`：可选的统一验证草稿参数。

非法 ID、跨数据版本选择、失败候选和归属链损坏仍返回类型化 4xx，不降级为成果对照。

## 7. 状态与错误处理

- 工作台成果目录加载失败时只降级该区域，不阻断数据和实验阶段；
- 物化操作使用现有幂等 API，重复点击不会创建重复资产；
- 模型对照中单个候选缺少非关键字段时显示“未记录”，不让整页崩溃；
- 数据版本不一致等真正不可对照的情况用明确错误页说明如何重新选择；
- 所有接口错误不得泄漏文件路径、SQLite 内容或 Python 堆栈。

## 8. 测试与真实视觉验收

### 8.1 后端

- 电阻率新旧 metadata 单位归一化，同时证明用户自定义 `RHO` 不被误改；
- 工作台成果目录的案例归属、排序、去重、物化状态和 URL；
- 同数据版本但验证口径不同仍返回对照数据且 `not_ranked`；
- 完全一致合同返回稳定严格排名；
- 跨数据版本、失败候选和损坏归属链 fail-closed；
- 统一验证实验草稿不创建实体、不自动运行。

### 8.2 前端

- 案例工作台可直接打开用户成果并正确处理待生成/失败状态；
- 对照模式与严格排名模式的文案、徽标和动作互斥；
- 电阻率所有目标页面显示 `Ω·m`；
- 首页参数面板位置和布局类稳定；
- 390×844 无横向溢出。

### 8.3 浏览器

在 `http://127.0.0.1:8000` 复用当前演示端口，使用真实数据和当前构建验收：

- 1440×900：首页三维参数区下移、画布填满、底部无大块空白；
- 电阻率案例工作台：官方成果和至少一个用户实验成果均有直接入口，单位为 `Ω·m`；
- 模型比较：一组不同验证口径候选正常进入成果对照但不排名；一组统一口径候选生成严格排名；
- 点击工作台成果入口实际打开正确 `result_id`，体渲染非黑屏；
- 390×844：首页和案例工作台页面宽度不超过视口。

## 9. 非目标

- 不放宽或删除严格排名的科学合同；
- 不跨数据版本比较；
- 不自动重跑历史实验；
- 不把模型对照升级为新的全局成果管理页面；
- 不修改 ML、IDW、Kriging 或 DSI-like 数值实现；
- 不修改 SuperMap iframe、渲染协议和 NetCDF 数据结构；
- 不在本轮合并 PR、打标签或创建 Release。
