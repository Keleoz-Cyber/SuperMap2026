# v0.9.0 Result Discovery and Comparison Usability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make resistivity units authoritative, expose every usable experiment result from the case workspace, separate result inspection from strict ranking, and make the home 3D stage fill its available space.

**Architecture:** Keep the case workspace DTO and candidate-comparison service as server-authoritative boundaries. Add one narrowly scoped preset-unit normalization helper, enrich bounded result summaries, and evolve comparison responses compatibly so the frontend can always render result inspection while showing ranks only for a strict validation match. Reuse the existing result workbench and rendering component; only adjust the presentation layout height chain.

**Tech Stack:** Python 3.11, FastAPI, SQLAlchemy, Pydantic v2, pytest, Vue 3, TypeScript, Element Plus, Vitest, Playwright, SuperMap iClient3D SDK.
