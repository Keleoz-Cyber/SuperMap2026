# v0.9.0 Machine Learning Spatial Prediction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add leakage-safe random-forest spatial prediction and Kriging residual correction as first-class, comparable, renderable modeling candidates.

**Architecture:** Extend the existing interpolator/candidate pipeline rather than create an AI subsystem. Plain random forest conforms to the existing interpolator protocol; residual correction uses a dedicated composite fitter with deterministic inner spatial folds. Materialization writes a primary field plus atomic ML auxiliary fields, and render assets address each field explicitly.

**Tech Stack:** Python 3.12, NumPy, pandas, SciPy, scikit-learn, Pydantic, FastAPI, SQLAlchemy, Vue 3, TypeScript, Element Plus, ECharts, Vitest, Playwright, SuperMap3D NetCDF rendering.

---

## File Structure

Backend additions:

- `src/geomodeling/modeling/spatial_features.py`: deterministic coordinate-only feature transformer.
- `src/geomodeling/modeling/random_forest.py`: RF parameter contract, fit/predict, tree dispersion.
- `src/geomodeling/modeling/kriging_rf_residual.py`: inner-fold OOF residual training and composite prediction.
- `src/geomodeling/platform/ml_capability.py`: dataset suitability rules and public explanation.
- `src/geomodeling/platform/ml_artifacts.py`: atomic auxiliary-field package and verification.

Existing backend integration points:

- `pyproject.toml`: scikit-learn dependency.
- `src/geomodeling/platform/schemas.py`: algorithms and capability DTOs.
- `src/geomodeling/platform/experiments.py`: parameter expansion and suitability enforcement.
- `src/geomodeling/modeling/runner.py`: algorithm registry and residual-specific outer-fold evaluation.
- `src/geomodeling/platform/results.py`: final ML fitting and atomic multi-field materialization.
- `src/geomodeling/platform/render_assets.py`, `render_contracts.py`, `netcdf_volume.py`: field-aware source identity and NetCDF creation.
- `src/geomodeling/api/routes/experiments.py`, `rendering.py`, `result_analysis.py`: capability and field APIs.

Frontend additions/integration:

- `web/src/components/experiments/MLCapabilityNotice.vue`: supported/experimental/not-recommended state.
- `web/src/components/results/MLFieldSelector.vue`: prediction/dispersion/baseline/correction segmented control.
- `web/src/components/results/MLModelEvidence.vue`: baseline change, dispersion, and limitations.
- `web/src/components/experiments/ParameterEditor.vue`: grouped algorithm selection and ML parameters.
- `web/src/views/ExperimentView.vue`: capability loading and experimental confirmation.
- `web/src/views/ResultWorkbenchView.vue`: field state, render identity, and evidence integration.
- `web/src/api/types.ts`, `client.ts`: contracts.
