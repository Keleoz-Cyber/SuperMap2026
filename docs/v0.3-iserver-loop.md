# v0.3 iServer 纵向闭环运行说明

> 适用分支：`feat/v0.3-iserver-vertical-slice`。本文是复现“iServer 发布 → FastAPI 状态接口 → 浏览器三维展示”闭环的唯一操作手册。环境事实以 [supermap-integration.md](supermap-integration.md) 为准。

## 1. 前置条件

- Python ≥ 3.12，Node ≥ 20，本机 iServer 2026（12.1.0.0）已部署；
- 相邻只读资料目录 `../超图杯资料` 存在（点云数据源）；
- `../Project/WorkSpace.smwu`（电阻率工作空间，含 expore1 数据源与 4 个三维场景）；
- iClient3D SDK：通过 `python scripts/fetch_iclient3d.py` 获取（官方 npm 包 `@supermap/iclient3d-vue-for-webgl@1.2.2` 内嵌的 Cesium 1.67 + SuperMap 插件，44MB，不入库）。

## 2. 启动顺序

```powershell
# 1) 安装（含 API 与测试依赖）
python -m pip install -e ".[api,test]"

# 2) 获取 iClient3D SDK（已存在会跳过）
python scripts/fetch_iclient3d.py

# 3) 启动 iServer（注意第 3.1 节的环境变量坑）
& "D:\supermap\supermap-iserver-2026-windows-x64-deploy\supermap-iserver-2026-windows-x64-deploy\bin\startup.bat"

# 4) 生成指标与登记产物（排行榜数据源）
geomodeling run-all -o outputs/release_verify

# 5) 构建前端
cd web; npm install; npm run build; cd ..

# 6) 单进程启动（API + 前端托管）
python -m uvicorn geomodeling.api.app:app --host 127.0.0.1 --port 8000
```

浏览器打开 <http://127.0.0.1:8000/>。首页 →「进入三维工作台」。

开发模式（前端热更新）：`cd web && npm run dev`（Vite 5173 端口，`/api` 已代理到 8000）。

### 3.4 体元数据的服务形态（关键实验结论）

- 数据服务元信息确认 `RHO_KRIG_FINAL_20M_40`：`type=VOLUME`、7×23（×42 波段）、值域 1.418283–133.146194、平面坐标 `PCS_NON_EARTH`，与平台登记一致（`service_metadata_verified` 即据此判定）。
- 但体元**单元值无法经 REST 读取**：`features.rjson` 对 VOLUME 数据集返回 500（服务端 DatasetGridInfo/DatasetVectorInfo 强转异常）；点数据集的批量读取（features/featureResults/KML）在当前版本也受限。
- 三维场景中的体元图层以 `ImageFileLayer`（二维影像瓦片缓存）发布，**不是** S3M 体渲染：旧版 iClient3D 可 `scene.open` 成功（1 图层），但请求不到瓦片、无体渲染效果。
- **体元缓存（VoxelGridCacheBuilder，S3M 2.0）**：iDesktopX「体元栅格生成缓存」的直接产物是**点云瓦片**（`dataType: BIM / PointCloudFile`、`vol: []` 为正常形态），属性值经 VertexWeight 携带，值域在 SCP 的 `wDescript`（1.418283–133.146194，与登记一致）。注意 SCP 会把平面米制坐标写成 `epsg:4326 / Degree`（锚点 (-100,440,0) 非法），且旧版 iClient3D（1.67 系）下载 4 个根瓦片后**不再请求子瓦片、图层无包围盒**——瓦片树遍历失败，无法渲染；手工改 scp（epsg:0 / WKT 平面 / epsg:3857）均不可行，客户端内改 lon/lat + refresh 也无效。
- **落地方案（已实现）**：FastAPI 经 iServer REST 逐个获取全部 s3mb 瓦片（26 个、53,487 B），用自研解析器（`geomodeling.publishing.s3mb`，zlib 头 + float32 顶点/权重块）还原 7,056 个加权体元格点，浏览器以自定义渲染（颜色表/阈值/Z 夸张与测点同一套交互）显示。**S3M 缓存是 SuperMap 的体渲染采样（自适应节点，非逐格导出），缓存值域 2.29–127.28；单元精确值域仍以数据服务 VOLUME 元数据（1.418–133.146）为准**，界面与接口均显式区分。

## 4. 证据链口径

`/api/cases/resistivity/publish-status` 实时合成六级证据（与 [supermap-integration.md](supermap-integration.md) §5 一致）：

| 状态 | 来源 | 2026-07-22 实测 |
|---|---|---|
| model_succeeded | 登记 | ✓ |
| artifact_exported | 登记（UDBX 文件级） | ✓ |
| iserver_published | 实时探测（data/3D 服务可达） | ✓ |
| service_metadata_verified | 实时探测（VOLUME 元数据比对零 mismatch） | ✓ |
| browser_loaded | 浏览器回执（**按 render_kind 严格校验**，见下） | ✓（s3m_voxel_cache，7,056 单元） |
| manual_visual_checked | 人工（iDesktopX 验证记录） | ✓ |

browser_loaded 回执的严格规则（前后端同则）：

- `iserver_scene`：`layer_count > 0`，`validated_count` 必须等于实际图层数，`service_url` 必须指向 `3D-WorkSpace` 场景服务且 `scene_name` 严格等于 `RHO_三维全值域`；
- `s3m_voxel_cache`：`validated_count > 0`，`service_url` 必须指向 `3D-local3DCache-RHO_KRIG_FINAL_20M_40_VOL_S3M2` 且缓存数据名严格一致；
- 通用：`success=true`、`result_id` 严格等于正式成果；证据时间统一为**服务器接收时间**；
- 场景失败或 `fallback_points`（仅点云）只作诊断，**不会**让 browser_loaded 变绿；种类与服务交叉伪造（场景种类指体元服务、体元种类指场景服务）一律拒绝。

iServer 离线时后两项 iServer 侧状态转 False，建模状态不受影响；浏览器回执写入 `outputs/api_evidence/browser_loads.jsonl`（不入库）。

## 4.1 体元浏览器渲染的落地架构

```text
iDesktopX 体元栅格生成缓存（S3M 2.0，26 个 s3mb）
  → iServer 三维瓦片服务（3D-local3DCache-..._VOL_S3M2）
  → FastAPI /api/cases/resistivity/voxel-cells
      （经 iServer REST 逐瓦片获取字节流 → s3mb 解析 → LOD 去重 → 紧凑 JSON）
  → 浏览器自定义渲染（点元渲染 + 色带/阈值/Z 夸张，与测点同一套交互）
```

设计要点：

- 旧版 iClient3D（1.67 系）无法遍历 S3M 瓦片树（根瓦片可下载、子瓦片不请求、图层无包围盒）；不声称 `scene.open` 成功即渲染成功，渲染证据 = 画面 + 有效包围盒 + 值域。
- 体元格点由 SuperMap 采样生成，值域 2.29–127.28 为采样平滑结果；单元精确值域 1.418283–133.146194 由数据服务 VOLUME 元数据独立验证并在界面同时展示。
- iServer 不可用时端点返回 503（可恢复），不影响测点点云与模型证据。

## 4.2 解析器契约与缓存刷新语义

**适用范围**：`geomodeling.publishing.s3mb` 是**针对性解析器**，仅保证兼容本机 iDesktopX 2026「体元栅格生成缓存」产出的 S3M 2.0 点云瓦片（本缓存的头部魔数、zlib 块、float32 顶点/权重块布局），**不宣称通用 S3MB 解析**，不支持其他数据类型/S3M 版本/编码。

**fail-closed 契约校验**（任一失败 → API 503 + 明确诊断，绝不返回可疑数据）。所有期望值来自唯一 `CacheContract`（由正式登记构建：值域取正式成果，期望数量取 行×列×波段，Z 包络取正式模型切片参数，X/Y 包络取登记标准化数据集）：

| 校验 | 内容 |
|---|---|
| 瓦片头部 | 魔数 `00 00 00 40`；`compressed_length` 必须等于实际负载长度（截断/尾随即失败）；zlib 流必须完整 EOF、无多余字节；声明与实际解压长度一致；解压大小 ≤ 契约上限（默认 64 MiB） |
| 远程瓦片清单 | 取数路径**只认 `manifest.tiles`**（本地缓存目录仅作诊断、不参与取数）；`manifest.cache_data_name` 必须严格等于当前缓存数据名；逐瓦片 sha256 组成的 manifest digest 必须与固定值一致；不符时报错并给出实际 digest 以便有意更新后重新固定 |
| scp 版本 | 仅接受 `2.0` |
| 文件类型 | `extensions.s3m:FileType == PointCloudFile` |
| wDescript | 存在、有限数值、min ≤ max，且与契约值域一致（容差 1e-3）；不符即报错并同时给出两组值域 |
| 格点 | 非空、数量 ≤ 契约上限且在期望网格的契约比例区间、坐标/权重全有限、权重在契约值域内 |
| 包围盒 | 有限且不超出契约包络（容差 5 m） |
| 成果身份 | 校验结果携带 `result_id`；浏览器回执另有独立的 result/service 身份过滤 |
| 重复格点 | 瓦片命名不可靠编码 LOD 层级，已删除“最深 LOD 优先”；相同 (x,y,z) 权重冲突即报错 |

响应体 `contract` 字段携带全部校验结果（版本、文件类型、wDescript 两组值域、格点数量与包围盒、manifest digest），`parser_scope` 字段显式声明适用范围。

**缓存刷新语义**（缓存重新生成或服务重新发布后）：

1. **iServer 侧**：`.scp` 在服务启动时读入内存，磁盘修改**必须重启服务**才生效（2026-07-22 实测：编辑后重启服务方生效）；s3mb 瓦片字节按请求从磁盘读取。重新生成整个缓存目录后，正确顺序是：重启该三维服务（或删除后重新发布）→ 再调用平台接口。
2. **清单（manifest）**：缓存内容变化会使 digest 校验失败（503 并给出实际 digest）；确认为有意更新后，用与 `geomodeling.publishing.cache_manifest.compute_manifest_digest` 相同算法重算并更新 `config/s3m_cache_manifest.json`。
3. **FastAPI 侧**：解析结果按进程内 LRU 缓存；用 `GET /api/cases/resistivity/voxel-cells?refresh=true` 强制重新拉取解析（同时清除瓦片解析缓存与点数据缓存），或重启后端进程。
4. **浏览器侧**：体元数据在进入工作台时加载一次；刷新页面即重新请求（展示即时生效）。
