# v0.5 微震第二案例建模闭环运行手册（Windows）

> 适用分支：`feat/v0.5-microseismic-second-case`（发布候选，版本 0.5.0）。数据事实以 [data/microseismic.md](data/microseismic.md) 与 [data/contracts.md](data/contracts.md) 为准；本文只描述怎么跑。微震闭环不依赖 iServer。

## 1. 闭环含义与边界

v0.5 把微震从“外部人工派生”移入代码化闭环：

```text
22 个正式 DAT（只读）
  → v0.2a 审计（清单/解析/契约）
  → 局部三维派生（W16 原点局部工程坐标，depth_m = WL/2(km) × 1000 向下为正，z_local_m = -depth_m）
  → 一次全局 3σ 筛选（样本标准差 ddof=1）
  → 黄金门禁（canonical CSV 哈希 + 计数，fail-closed）
  → 精确 XYZ 分组算术平均聚合
  → 平台数据集（1,911 建模节点）
  → IDW / 普通克里金调参与空间验证（复用 v0.4 平台）
  → 成果工作台（三层诊断图层）→ 证据 ZIP 导出 → 发布登记 manual_required
```

必须保持的边界：

- 只有**局部工程坐标**（`local_engineering_m`，非 EPSG）：原点 W16（即 L2/L3 交点），X 正向沿 L3 指向 W24，Y 正向沿 L2 指向 W20。不得描述为绝对地理坐标，不得与电阻率/瓦斯跨案例叠加。
- 三个计数层次不得混报：**2,006 源记录**（含 1 条 W8 `1.#QNAN0` 无效值）→ 2,005 有限记录 → **1,925 候选**（3σ 保留）→ **1,911 聚合建模节点**。插值输入只用 1,911 节点；1,925 候选与 80 剔除只作诊断与证据。
- `z_scale` 是距离计算实验参数（`0 < z_scale ≤ 20`），不代表已确认的地质各向异性。
- 发布登记保持 `manual_required`：iServer 发布是人工步骤，平台不自动发布。
- 原始 DAT 只读：处理前后 22 个文件 SHA-256 不变；原始资料继续保存在相邻只读目录 `../超图杯资料`，不在代码项目中复制或修改。

## 2. 预检清单

上台或演示前逐项确认：

1. Python 3.12+ 环境已安装依赖：`python -m pip install -e ".[api,test]"`。
2. 前端已构建：`npm --prefix web ci && npm --prefix web run build`（未构建时首页不可达，`demo-check` 会阻断）。
3. 通用预检通过：`geomodeling demo-check`（阻断项退出码 1；iServer/S3M/凭据缺失仅警告，微震流程不受影响）。
4. DAT 源目录就绪：含**恰好 22 个正式 DAT**（W1—W9、W12—W20、W24—W27），合计 66,880 字节，ASCII 空白分隔文本，表头 `WL/2(km)  Vx`，每个文件末尾 1 个 NUL 终止伪行。目录只读即可，程序绝不修改源文件。
5. 数据目录可写：浏览器/API 流程使用 `GEOMODELING_DATA_DIR`（默认 `var/geomodeling`，被 Git 忽略）；CLI `import-case` 用 `--data-dir` 显式指定。
6. 端口可用：默认 8000（或自选端口），被未知进程占用时 `demo-check` 阻断。

| 无效记录（W8 `1.#QNAN0`） | 1 | 0 | 0 | **1** |

## 4. CLI 路线

### 4.1 派生（不建案例，只产出全部派生层与门禁结论）

```powershell
geomodeling microseismic derive --source-dir <DAT目录> -o outputs/microseismic_v05_verify
```

预期输出（计数行）：

```text
source_records=2006 finite=2005 invalid=1 rejected_3sigma=80 accepted_modeling=1925 modeling_nodes=1911
golden_passed=True
downstream_gates={'geometry_blocked': False, 'cleaning_blocked': False, 'interpolation_blocked': False}
validation_passed=True failed_checks=0
```

输出目录包含：`source_records_2006.csv`、`invalid_records_1.csv`、`rejected_3sigma_80.csv`、`accepted_modeling_1925.csv`、`aggregated_nodes_1911.csv`、`modeling_provenance.parquet`、`derivation_report.json` 及 v0.2a 审计报告族。即使门禁失败也会写出诊断层，便于排查。

### 4.2 导入为平台案例（原子）

```powershell
geomodeling microseismic import-case --source-dir <DAT目录> --data-dir var/geomodeling
# 可选：--case-name "微震速度（第二案例）"  --config config/microseismic.yaml
```

预期输出 `validation_passed=True status=ready` 与 `case_id`/`dataset_id`；之后即可在浏览器中打开该案例调参。导入是原子操作：派生合同或黄金门禁任一失败，或写入中途失败，补偿事务会清理数据库行、正式目录和临时目录，不留半成品。

### 4.3 v0.2a 旧命令保持兼容

`inventory/parse/validate/export-reports/run-audit` 语义不变，只复现审计底座，不含 v0.5 派生。退出码语义：契约检查或黄金门禁失败（`validation_passed=False`）返回 1，且仍尽量输出诊断；通过返回 0。

## 5. 浏览器路线

```powershell
python -m uvicorn geomodeling.api.app:app --host 127.0.0.1 --port 8000 --workers 1
# 浏览器打开 http://127.0.0.1:8000/
```

1. 首页点微震案例卡的「**导入微震 DAT**」，进入 `/cases/new?preset=microseismic` 四步向导。
2. **第 1 步 选择来源**：选择含 22 个正式 DAT 的文件夹（或一次多选 22 个 DAT 文件）上传；服务端原子完成审计、派生、黄金门禁与聚合。
3. **第 2 步 原始数据核验**：核对登记的文件身份（文件名 / 测点 / 测线 / 记录数 / 哈希）。若服务端阻断（派生合同或黄金门禁失败），页面只展示公开诊断，没有可绕过的继续入口。
4. **第 3 步 派生结果确认**：核对各层计数（对照本文 §3）后确认。
5. **第 4 步 质量校验与建模入口**：对 1,911 个标准化建模节点执行平台质量校验；`passed` 或警告经显式确认后进入调参实验室。
6. 调参、排行榜、正式选择与 v0.4 通用流程一致（见 [v0.4-generic-modeling-loop.md](v0.4-generic-modeling-loop.md)）。
7. **成果工作台**：三维点场 + X/Y/Z 切片；三层诊断图层——1,911 聚合节点（默认开）、1,925 候选（默认关）、80 剔除（默认关）；数据血统页可查派生报告与哈希。

浏览器与 CLI 共用同一派生内核，计数、哈希、门禁结论一致（浏览器/CLI  parity）。

## 6. 调参试跑建议

预设 `config/presets/microseismic.json` 已登记搜索网格：IDW 36 组合（power 1/2/3 × neighbor 8/16/24/32 × z_scale 0.5/1/2），普通克里金 27 组合（spherical/exponential/gaussian × neighbor 12/24/36 × z_scale 0.5/1/2），均在 50 组合硬上限内。

建议先试跑单组手动参数再上网格搜索：

| 算法 | 建议首发参数 |
|---|---|
| IDW | `power=2`、`neighbor_count=16`、`z_scale=1` |
| 普通克里金 | `variogram_model=spherical`、`neighbor_count=24`、`z_scale=1`（块金/基台/变程自动拟合） |

`z_scale` 只参与距离、邻域与变异函数拟合（按 `(x, y, z × z_scale)` 计算）：0.5 弱化垂直距离、2 强化；成果物理坐标不写回。它是实验参数，由空间验证的公共有效指标来比较，不得解释为已确认的地质各向异性。

默认网格：50 m 分辨率，范围 X[-750,960]、Y[-995,1310]、Z[-4086.538,-37.5]，约 134,890 单元，低于 100 万单元硬上限。

## 7. 空间验证

微震三维数据按**整根 XY 采样柱**折分：同一 `(x, y)` 柱的所有深度记录要么全在训练、要么全在验证，杜绝同柱相邻深度泄漏。排行榜在公共有效掩膜上比较（指标定义见 [data/contracts.md](data/contracts.md) §9）。按测线/测点的分组诊断可供查看，但不改变公共排名。

## 8. 导出核验与发布登记

成果页「导出 ZIP」对微震案例包含 14 个文件，全部带 SHA-256 清单：

- 标准七文件（与 v0.4 通用成果一致：参数、指标、网格 CSV、切片、清单等）；
- `domain_evidence/` 七文件：`source_manifest.json`、`derivation_report.json`、五个分层 CSV（源记录 / 无效 / 剔除 / 候选 / 聚合节点，文件名嵌本次实际行数）。

核验要点：ZIP 内 `manifest` 的每个哈希与文件实算一致；`domain_evidence/` 文件缺失或哈希不符会让导出整体失败（不静默省略）。发布登记解析为 `manual_required`：只登记“需要人工发布”，不声称 iServer 成功。

## 9. 失败诊断

| 现象 | 含义 | 处理 |
|---|---|---|
| `golden_passed=False` / 导入被阻断 | 文件集合错误（缺/多文件、记录数不符）或派生结果与黄金口径不符 | 按输出的 `FAILED golden_*` 逐项核对：文件清单、2,006/2,005 计数、两张表哈希、冲突组计数；修正源目录后重跑 |
| 契约检查失败（退出码 1） | 22 DAT 集合、NUL 终止、计数分层、W28 等审计契约未过 | 诊断层已写出到输出目录；核对 `derivation_report.json` 的 `failed_checks` |
| 导入中途失败（写盘/DB） | 补偿事务已清理半成品 | 修复原因后直接重跑，无残留状态 |
| 质量门禁 `blocked` | 建模节点存在阻断级质量问题 | 查看质量报告明细；警告项需显式确认才可继续 |
| 端口被占用 | `demo-check` 阻断项 | 换端口或释放占用后重启 |
| 首页 404 / 前端未构建 | `web/dist` 缺失 | `npm --prefix web run build` 后重启后端 |

## 10. 重启恢复

- 案例、数据集、实验、运行与成果全部持久化在 SQLite（`GEOMODELING_DATA_DIR` 布局）；杀掉 uvicorn 进程重启后原样恢复。
- 重启时在途运行被标记 `interrupted + PROCESS_RESTARTED`，不会自动重排；在实验页显式重试。
- 已完成的派生工件按确定性目录存放，重启后派生证据、诊断图层与导出仍可解析。

## 11. 演示降级

- 微震闭环与 iServer 无关：iServer 离线不影响导入、派生、调参、成果与导出。
- 无真实 DAT 时：不得伪造计数演示。可用便携测试夹具（`tests/microseismic_fixtures.py` 的人工小样本树，计数随夹具不同）验证链路，或改走 v0.4.1 通用演示路线（`demo/platform_demo_3d.csv`，见 [v0.4.1-demo-runbook.md](v0.4.1-demo-runbook.md)）；黄金门禁只对真实 22 DAT 集合通过。
