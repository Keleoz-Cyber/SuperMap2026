# v0.4 通用建模闭环运行说明

> 适用版本：v0.4.0。本文是通用建模平台（上传 → 质量门禁 → 调参 → 成果 → 导出）的唯一操作入口；v0.3.1 内置电阻率闭环见 [v0.3-iserver-loop.md](v0.3-iserver-loop.md)，答辩演示执行手册见 [v0.4.1-demo-runbook.md](v0.4.1-demo-runbook.md)，当前状态见 [status/current-status.md](status/current-status.md)。

## 1. 安装与启动

```powershell
python -m pip install -e ".[api,test]"
cd web; npm ci; npm run build; cd ..
python -m uvicorn geomodeling.api.app:app --host 127.0.0.1 --port 8000 --workers 1
# 浏览器打开 http://127.0.0.1:8000/
```

必须 `--workers 1`（或默认单进程）：后台 Worker 是进程内单线程执行器，多进程会各自持有任务队列。开发前端可用 `npm --prefix web run dev`（Vite 代理 `/api` 到 8000）。

## 2. 环境变量

全部可选，默认值面向本机演示；示例见 [.env.example](../.env.example)。

| 变量 | 默认 | 说明 |
|---|---|---|
| `GEOMODELING_DATA_DIR` | `var/geomodeling` | SQLite + 上传/网格/导出工件根目录（已 gitignore） |
| `GEOMODELING_FRONTEND_DIST` | `web/dist` | 存在 `index.html` 才由 FastAPI 静态托管 |
| `GEOMODELING_CONFIG` | `config/default.yaml` | 内置电阻率案例配置 |
| `GEOMODELING_EVIDENCE_DIR` | `outputs/api_evidence` | 浏览器回执证据目录 |
| `GEOMODELING_VOXEL_CACHE_DIR` | （未设） | iDesktopX 体元缓存本地诊断目录（不作为取数来源） |
| `GEOMODELING_ISERVER_URL` | `http://localhost:8090/iserver` | iServer 地址 |
| `GEOMODELING_ISERVER_ADMIN_USER` / `..._PASSWORD` | （未设） | iServer 管理员凭据，只走环境变量 |

## 3. 上传数据契约

- 格式：CSV / XLSX（多工作表可选表）；硬上限 **50 MiB、500,000 行**（`PlatformSettings` 可调）。
- 语义列：2D 需 `x,y,value`；3D 需 `x,y,z,value`；四角色不得同列；另需属性名（`value_name`）与可选单位。
- 坐标类型：`local_linear` / `projected` 可建模；`geographic`（经纬度）必须先投影，服务端硬拒绝（`GEOGRAPHIC_NOT_PROJECTED`）。
- NoData 哨兵：`-9999`；`1.#QNAN0` 等旧式 NaN token 记为数值无效行，不改 0、不填补。
- 例（3D）：`x,y,z,rho` 四列，144 行见 `demo/platform_demo_3d.csv`（唯一权威演示样例，SHA-256 固定，说明见 `demo/README.md`）。

## 4. 质量门禁与警告确认

`POST /api/datasets/{id}/validate` 产出 `passed | warnings | blocked`：

- **阻断（不可建模）**：`MISSING_NUMERIC`、`NON_FINITE`、`NODATA_VALUE`、`CONFLICTING_COORDINATE`（同坐标不同值）、`INSUFFICIENT_VALID_POINTS`（2D<10 / 3D<20）、`DEGENERATE_EXTENT`。
- **警告（须显式确认）**：`DUPLICATE_ROWS`、`EXTREME_VALUES`（MAD k=6）、`SPARSE_DISTRIBUTION`、`SUSPICIOUS_MAGNITUDE`、`HIGH_INVALID_RATIO`（>5%）。
- 确认语义：`POST .../quality/confirm-warnings` 的 `issue_codes` 必须与当前未决警告代码**完全一致**（409 `WARNING_CONFIRMATION_MISMATCH`）；确认落盘在数据集 profile 中。重新映射会使既有报告与确认全部失效。
- 实验创建被质量门禁拦截（409 `QUALITY_GATE_FAILED`）：blocked 或未确认警告都不放行。

## 5. 算法参数

**IDW**（`algorithm=idw`）：`power`（0<p≤8，默认 2）、`neighbor_count`（1–128，默认 16）、`search_radius`（>0，可选）、`min_neighbors`（1–32，默认 3）。

**普通克里金**（`algorithm=ordinary_kriging`）：`variogram_model` ∈ spherical/exponential/gaussian；`variogram_mode=auto`（仅训练折内自动拟合，防泄漏）或 `manual`（须给 `nugget≥0`、`sill>nugget`、`range>0`）；`neighbor_count`（4–128，默认 24）；`search_radius`、`min_neighbors`（3–32，默认 4）。当前技术门与已知边界见[验收标准](acceptance.md)。

网格搜索：参数值为离散列表，笛卡尔积展开，**硬上限 50 组合**（409 `SEARCH_TOO_LARGE`）；UI 在 30 组合即预警。Kriging 网格搜索固定 auto 变异函数。

## 6. 空间验证与公共有效排名

- 折分：`spatial_kfold`（3–10 折，默认 5）或 `spatial_holdout`（留出 0.1–0.4，默认 0.2）；空间柱划分，同一 `(x,y[,z])` 柱不跨训练/验证；`seed` 决定可复现性。
- 排名：所有成功候选在**同一公共有效掩膜**上复算 MAE/RMSE/R²/Bias；覆盖率按候选自身有效点单独呈现，报 NoData 不能换取排名优势。失败候选永远保留在排行榜（含错误码），不丢弃。

## 7. 任务持久化：取消、重试与重启恢复

- 任务先落库再入队（SQLite WAL）；状态机 `queued → running → succeeded/failed/canceled/interrupted`。
- 取消：queued 立即转 canceled；running 在候选边界协作退出（单线程 Worker，候选间检查取消旗标）。
- 重试：canceled/interrupted/failed 可重试，产生新 run（`retry_of_run_id` 指回原 run）。
- 进程重启：启动时把残留 queued/running 一律标 `interrupted + PROCESS_RESTARTED`，不自动重跑；重试是显式用户动作。
- 同一实验同时只允许一个在途 run（409 `RUN_ALREADY_ACTIVE`）。

## 8. 成果展示：2D、完整 3D 与 X/Y/Z 切片

- 成果工件：`POST /api/results/{id}/materialize` 幂等生成规则网格（默认按数据范围每轴约 11 节点，可在实验高级设置自定义边界+节点数）。
- 2D 成果：整场热力图（合成 z=0 切片）+ 实测点叠加（`GET /api/datasets/{id}/points`）。
- 3D 成果：`preview` 抽稀完整场点云（≤5 万单元）；`slices?axis=z|x|y&index=i` 三方向正交切片，滑块按索引定位，标签显示服务端返回的真实坐标（如 `Z = -420 m`）。NoData 单元保持透明。任意斜切不提供。
- 浏览器三维用 Cesium 点元渲染；可见性切换一律 `removeAll()`+内存重建（本机 Cesium 1.67 的 `.show` 无效的实证结论），不依赖 `.show`。

## 9. 证据导出与发布状态

`POST /api/results/{id}/exports` 生成 ZIP：`manifest.json`（source/grid SHA-256 + 文件清单）、`metadata.json`（算法/参数/网格/验证折数）、`metrics.json`（公共指标+候选指标）、`quality.json`、`formal_selections.json`、`failed_evidence.json`（失败候选证据）、`grid.csv`（全网格）。导出记录落库，`GET /api/exports/{id}/download` 下载。

状态分离：建模成功、导出成功、iServer 发布、服务验证、浏览器加载是**独立状态**。当前通用流程的发布请求一律登记为 `manual_required`（本机 iServer 程序化发布不可用），附手动发布指引；不伪造已发布。内置电阻率案例仍按六级证据链独立验证。

## 10. iServer 离线行为

通用建模全流程（上传→调参→成果→导出）**不依赖 iServer**；iServer 不可达只影响内置电阻率案例的实时探测与体元瓦片获取，相应状态降级为 unknown/失败诊断，绝不影响建模证据。

## 11. 备份与恢复

备份：停止服务后复制整个 `GEOMODELING_DATA_DIR`（默认 `var/geomodeling/`，含 `platform.sqlite3` 与全部工件）。恢复：放回原路径启动即可；启动时自动恢复语义见 §7。在线备份请先 `PRAGMA wal_checkpoint`，或直接停服复制。

## 12. v0.3.1 兼容与当前限制

- 内置电阻率案例只读保留：`/api/cases/resistivity*` 全部路由、S3M fail-closed 契约、浏览器回执严格身份规则不变。
- 统一错误封套 `{"error": {code, message, details}}`，本机路径不回传浏览器。
- 限制：任意斜切不提供；Kriging 网格搜索仅 auto 变异函数；微震派生表尚未代码化（M5 边界）；瓦斯案例暂缓；经纬度须先投影。
