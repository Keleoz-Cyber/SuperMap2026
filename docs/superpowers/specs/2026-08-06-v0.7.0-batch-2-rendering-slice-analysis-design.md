# v0.7.0 第二批：NetCDF 渲染交互与正交剖面分析

**状态：设计已获用户确认，等待用户复核本文档后进入实施计划。**

## 1. 目标与范围

本批在 v0.7.0 第一批统一案例工作台之上，完善 NetCDF 原生体渲染控制，并把 X/Y/Z 正交切片扩展为可查看、可统计、可导出的剖面分析功能。

完成后，电阻率内置案例、微震 CSV 预置案例和用户上传数据产生的三维成果都应在同一个 `NativeVolumePanel` 中获得相同能力：

- 体积、单轴切片、等值面三种渲染模式。
- X/Y/Z 轴选择、真实网格索引和真实坐标切片。
- 色带、线性/对数标度、数值过滤、不透明度、光照、渐变透明度和包围盒控制。
- 当前切片的 ECharts 二维热力图、鼠标取值、原始值统计和分析包下载。

本批只分析已经处于 `ready` 状态的 `RenderAsset` 及其权威规则网格。它不重新插值、不修改实验或正式选择，也不把浏览器渲染画面当作数值来源。

## 2. 不变原则

1. 浏览器中的连续体渲染器仍只有 SuperMap3D `VoxelGridLayer3D + NetCDF`。点层只能是辅助证据，不能在体渲染失败时充当成功结果。
2. 三类来源必须共用 RenderAsset 入口、剖面服务、Vue 组件、统计口径和 ZIP 格式；禁止为电阻率或微震复制专用实现。
3. X/Y/Z 切片使用权威网格的索引和坐标。只有向 SuperMap iframe 发送状态时才转换为 SDK 相对位置。
4. 统计、CSV 和 manifest 由后端从权威网格重算。不得从截图、画布像素、前端矩阵或经过滤后的颜色值反推。
5. 色带、对数、光照、透明度和显示过滤只影响视觉表达，不改变原始值、统计或导出 CSV。
6. 任一 SDK 能力缺失都必须显式失败；不增加 Three.js、自研 WebGL、点云或旧渲染器回退。

## 3. 方案选择

### 3.1 资产中心的统一服务（采用）

新功能以 `RenderAsset` 为公共入口：

```text
candidate_result / builtin_legacy
              ↓
       ready RenderAsset
              ↓
  权威规则网格 + NetCDF manifest
              ↓
     通用剖面分析服务
       ├─ 剖面矩阵与统计
       ├─ Slice ZIP 导出
       └─ SDK 相对切片位置
              ↓
       NativeVolumePanel
       ├─ SuperMap 单轴切片
       ├─ ECharts 二维剖面
       └─ 当前剖面下载
```

该方案能同时覆盖候选成果和 legacy 电阻率，且不会把通用 API 绑到 `result_id`。既有 `/api/results/{result_id}/slices` 保持兼容，但内部复用相同的切片抽取核心。

### 3.2 继续只使用候选结果切片 API（不采用）

该方案改动较小，但 `builtin_legacy` 没有候选结果身份，会迫使电阻率继续走专有接口，破坏第一批建立的统一产品模型。

### 3.3 在浏览器读取 NetCDF 并计算统计（不采用）

该方案可减少 API 请求，但会让浏览器、后端和导出产生三套数值口径，也难以保证 NoData、分位数和资产哈希一致。因此浏览器只负责交互和 PNG 展示工件。

## 4. 统一渲染元数据

每个可渲染来源在适配为 `RenderAsset` 时形成一个公开 `render_profile`：

| 字段 | 含义 |
| --- | --- |
| `property_name` | 属性名，例如 `RHO` 或 `Vx` |
| `unit` | 原始值单位；未知时明确为 `unknown` |
| `default_scale` | `linear` 或 `log` |
| `default_palette` | 稳定色带 ID |
| `log_available` | 权威有效值是否全部大于 0 |
| `value_range` | 权威有限、非 NoData 值域 |
| `filter_range` | 初始显示过滤范围，默认等于 `value_range` |
| `lighting` | 初始光照开关 |
| `gradient_opacity` | 初始渐变透明度开关 |
| `bounding_box` | 初始包围盒开关 |
| `opacity` | 初始整体不透明度 |

默认值由来源元数据提供，不由前端判断 case ID：

- 电阻率登记元数据声明 `default_scale=log`。
- 微震预置数据声明 `default_scale=linear`。
- 普通用户上传成果默认 `linear`，以后可由数据集 profile 显式覆盖。
- `log_available=false` 时前端禁用对数选项；不得丢弃或平移 `<=0` 的原始值来强行开启。

`render_profile` 必须同时出现在现有 candidate/legacy capability 或 asset status DTO 中，使页面在进入切片模式前就能初始化体渲染；`slice-analysis` 再原样携带它用于身份核对。它是根据来源登记信息和权威网格摘要计算的公开 DTO，不要求给 `render_assets` 表新增一份可漂移的 JSON 副本。

色带采用固定、版本化的前端定义，至少提供保持当前视觉连续性的 `native-spectrum`、感知均匀的 `viridis`、高对比 `turbo`、有符号数据适用的 `coolwarm` 和 `grayscale`。色带选择器显示真实色带 swatch。后端只指定稳定 ID，不重复保存颜色节点。

后端 schema 将 `default_palette` 限制为上述 ID；来源配置出现未知 ID 时 capability 明确失败，不能由前端静默选择另一个色带。渐变透明度本批只开放布尔开关，继续使用经真实 SDK 验证的内部默认梯度范围，不公开四个难以解释的底层梯度参数。

线性与对数只改变颜色传递函数。对数模式按原始正值生成几何间隔的颜色节点；SuperMap 和 ECharts 必须调用同一个纯函数生成颜色映射。过滤上下限仍使用原始值。

## 5. 剖面分析 API

### 5.1 读取当前剖面

```http
GET /api/render-assets/{asset_id}/slice-analysis?axis=x&index=10
```

仅允许 `ready` 资产。服务从 RenderAsset 身份解析并校验权威网格，不从 NetCDF 浏览器响应或截图读取数据。响应至少包含：

```json
{
  "asset_identity": {
    "asset_id": "...",
    "source_kind": "candidate_result",
    "source_id": "...",
    "grid_sha256": "...",
    "netcdf_sha256": "..."
  },
  "property": {"name": "Vx", "unit": "km/s"},
  "axes": {
    "x": {"length": 35, "coordinates": [], "unit": "m"},
    "y": {"length": 47, "coordinates": [], "unit": "m"},
    "z": {"length": 82, "coordinates": [], "unit": "m"}
  },
  "slice": {
    "fixed_axis": "x",
    "index": 10,
    "coordinate": 120.0,
    "sdk_relative_position": 0.2941176471,
    "row_axis": "z",
    "column_axis": "y",
    "row_coordinates": [],
    "column_coordinates": [],
    "values": [],
    "nodata_mask": []
  },
  "statistics": {
    "total_count": 3854,
    "valid_count": 3800,
    "nodata_count": 54,
    "min": 0.2,
    "max": 3.1,
    "mean": 1.7,
    "std_population": 0.4,
    "p10": 1.0,
    "p50": 1.7,
    "p90": 2.4
  },
  "render_profile": {}
}
```

示例中的数值仅说明字段形态，不是冻结测试值。正式测试使用小型确定性网格逐位断言。

### 5.2 矩阵方向

新 API 使用面向图表的明确方向，`values[row][column]` 与 `nodata_mask[row][column]` 同形：

| 固定轴 | 横轴 `column_axis` | 纵轴 `row_axis` |
| --- | --- | --- |
| X | Y | Z |
| Y | X | Z |
| Z | X | Y |

坐标数组允许升序或降序，返回顺序必须与矩阵一致，前端不得自行排序而不同时重排矩阵。SDK 相对位置由后端根据该资产实际 NetCDF 轴方向和边界计算并限制在 `[0,1]`；前端不依据 case 类型推算。

既有 `/api/results/{result_id}/slices` 的字段、矩阵方向和错误状态保持不变。它改为调用公共抽取服务后通过兼容 adapter 产生旧响应，避免破坏已有客户端和测试。

### 5.3 NoData 与统计

有效值定义为：`is_nodata=false` 且数值有限。响应前统一把显式 NoData 和 `NaN/Inf` 合并为有效 NoData 掩膜；JSON `values` 对这些单元返回 `null`，不得输出非标准 JSON 的 `NaN` 或 `Infinity`。

统计只使用有效原始值：

- 标准差采用总体标准差 `ddof=0`。
- P10/P50/P90 使用 NumPy 线性插值定义，即 `quantile(..., method="linear")`。
- `nodata_count = total_count - valid_count`。
- 全 NoData 剖面正常返回 HTTP 200，计数为 0，min/max/mean/std/P10/P50/P90 均为 `null`。
- 统计完全不受当前色带、标度、过滤、不透明度、光照和渐变透明度影响。

### 5.4 错误合同

| 条件 | HTTP | 稳定错误码 |
| --- | --- | --- |
| 资产不存在 | 404 | `RENDER_ASSET_NOT_FOUND` |
| 资产不是 ready | 409 | `RENDER_ASSET_NOT_READY` |
| 资产文件或哈希不一致 | 409 | 沿用既有资产完整性错误码 |
| 轴不是 x/y/z | 422 | `SLICE_AXIS_INVALID` |
| 索引越界 | 422 | `SLICE_INDEX_OUT_OF_RANGE` |

公共错误 detail 只含 ID、轴、索引和允许公开的长度，不返回本机路径。

## 6. 当前剖面导出

### 6.1 HTTP 流程

```http
POST /api/render-assets/{asset_id}/slice-exports
Content-Type: multipart/form-data

axis=x
index=10
image=<ECharts PNG>
```

服务端不接受客户端提交的矩阵、统计或 manifest。它重新读取同一资产的权威网格并生成：

```text
slice-analysis.zip
├─ slice.csv
├─ statistics.json
├─ slice.png
└─ manifest.json
```

创建成功返回既有 Export DTO 和 `/api/exports/{export_id}/download`。下载端点继续复用，不增加第二套文件服务。

### 6.2 文件合同

`slice.csv` 使用 UTF-8、LF 和稳定列序：

```text
x,y,z,value,is_nodata
```

每个剖面单元一行，顺序为矩阵行优先：外层遍历 `row_coordinates`，内层遍历 `column_coordinates`。固定轴坐标在每行重复。NoData 行的 `value` 留空、`is_nodata=true`，其余值使用可往返的十进制表示。

`statistics.json` 使用与 API 完全相同的统计字段和原始数值。`manifest.json` 至少记录：

- `format_version=slice-analysis/v1`。
- RenderAsset、source、grid 和 NetCDF 身份。
- 属性名、单位、三轴长度、固定轴、索引、真实坐标。
- CSV、statistics 和 PNG 的 SHA-256。
- 统计口径与分位数方法。
- `image_provenance=client_echarts_canvas`，明确 PNG 是展示工件而非权威数值来源。

PNG 仅允许 `image/png`，最大 5 MiB，IHDR 宽高均须为 `1..4096`。服务校验 PNG 签名和结构边界；失败返回 `SLICE_EXPORT_IMAGE_INVALID`。文件先写入同一导出目录的临时文件，完整校验并封包后原子改名；数据库写入失败或任一步骤异常都清理临时目录。

现有 `Export` 生命周期继续使用。`manifest_json` 记录 `export_kind=slice_analysis`；候选结果资产填写现有 `candidate_result_id`，legacy 资产为 `null` 并保留稳定 `case_id` 和 RenderAsset 身份。本批不把剖面包送入 iServer publication 流程。

## 7. 前端交互与组件边界

### 7.1 页面结构

`NativeVolumePanel` 保持统一编排入口，但将新增职责拆分为：

- `VolumeRenderToolbar`：模式、色带、标度、过滤、不透明度、光照、渐变透明度、包围盒和视角命令。
- `OrthogonalSliceControls`：X/Y/Z 轴、索引滑块、前后层、索引和真实坐标。
- `SliceAnalysisPanel`：请求状态、统计、导出和响应竞态控制。
- `SliceHeatmap`：ECharts 生命周期、热力图、tooltip 和 PNG 捕获。
- `renderTransferFunctions.ts`：SuperMap/ECharts 共用的线性/对数色带纯函数。

不为三类案例创建分支组件。来源差异只通过 RenderAsset、`render_profile` 和属性单位驱动。

### 7.2 可见性规则

- 模式使用“体积 / 切片 / 等值面”分段控件。
- X/Y/Z、切片索引、前后层和真实坐标只在切片模式显示。
- 二维剖面、统计和导出也只在切片模式显示。
- 等值面值只在等值面模式显示。
- 色带、标度、过滤、不透明度、光照、渐变透明度、包围盒和重置视角保持常驻，状态跨模式保留。
- 光照或渐变透明度在某一 SDK 模式下视觉无效时仍保存用户状态，并在进入适用模式后生效；不得伪报已产生像素变化。
- 辅助点层控制保留并继续明确标注为辅助，不参与剖面统计。

三维视图下方使用无嵌套卡片的分析区。桌面宽度下热力图与统计左右排列，窄屏上下排列。热力图使用固定最小高度和响应式宽度，避免加载文字或 tooltip 改变页面布局。

### 7.3 取值与加载

热力图 tooltip 显示两个平面坐标、固定轴坐标、原始值和单位；NoData 单元显示 `NoData`，不显示伪造的 0。坐标标签来自 API，不依据数组下标估算。

滑块操作采用以下节奏：

1. 索引和真实坐标标签立即变化。
2. iframe 状态更新节流到最高约 10 Hz，避免连续重绘堵塞。
3. 剖面 API 请求防抖约 150 ms；松开或键盘提交时立即请求最终索引。
4. 每个请求捕获 asset/axis/index 和单调序号。成功、失败和 finally 都只能更新仍为当前目标的状态。
5. 导出按钮仅在已加载剖面身份与当前 asset/axis/index 完全一致时可用。

“前一层/后一层”每次只改变一个真实索引，到达轴首尾时对应按钮禁用，不循环跳转。初次进入切片模式时，每个轴默认选择 `floor((length - 1) / 2)`。等值面初值沿用原始有效值域的算术中点；线性/对数切换不改变这个物理阈值。

切换资产时取消旧请求、清空剖面和错误状态，并恢复新资产的后端默认渲染状态。全 NoData 剖面显示空热力图和计数统计，但不是错误页。

## 8. iframe v2 协议

协议升级为 `gmp-supermap-volume/v2`。父页面发送完整渲染状态，而不是让多个独立控件命令在 iframe 内拼接状态。

### 8.1 父页面到 iframe

```ts
type RenderStateV2 = {
  revision: number
  mode: 'volume' | 'slice' | 'contour'
  filter: { min: number; max: number }
  opacity: number
  colorTransferFunction: Array<{ value: number; color: string }>
  lighting: boolean
  gradientOpacity: boolean
  boundingBox: boolean
  slice?: {
    axis: 'x' | 'y' | 'z'
    index: number
    coordinate: number
    relativePosition: number
  }
  contourValue?: number
}

type ParentMessageV2 =
  | { type: 'INIT'; requestId: string; asset: RenderAssetRecord | null; displayTransform: DisplayTransform; state: RenderStateV2 }
  | { type: 'APPLY_RENDER_STATE'; requestId: string; commandId: string; state: RenderStateV2 }
  | { type: 'SET_POINT_LAYER'; requestId: string; commandId: string; layer: PointLayerPayload }
  | { type: 'RESET_VIEW'; requestId: string; commandId: string }
```

所有消息还必须携带精确的 `protocol='gmp-supermap-volume/v2'`。`revision` 在当前 iframe 会话内单调递增；iframe 忽略小于或等于最后已应用 revision 的状态。

### 8.2 iframe 到父页面

```ts
type ChildMessageV2 =
  | { type: 'FRAME_READY'; requestId: string; sdkVersion: string; contextType: number; capabilities: FrameCapabilities }
  | { type: 'RENDER_STATE'; requestId: string; phase: RenderPhase; identity: RenderIdentity | null }
  | { type: 'STATE_APPLIED'; requestId: string; commandId: string; revision: number; appliedState: RenderStateV2 }
  | { type: 'COMMAND_APPLIED'; requestId: string; commandId: string; commandType: 'SET_POINT_LAYER' | 'RESET_VIEW' }
  | { type: 'ERROR'; requestId: string; commandId?: string; revision?: number; code: string; message: string }
```

`FrameCapabilities` 显式报告 `singleAxisSlice`、`lighting`、`gradientOpacity`、`boundingBox` 和 `transferFunction`。能力字段来自已验证的 SDK 表面检查；它不能取代真实 GPU 单轴探针。

父子双方继续执行 origin、source window、protocol、requestId 四重校验，`postMessage` 目标永远是 `window.location.origin`。v2 由同一构建中的父页面和 iframe 原子升级，不长期双栈支持 v1；协议测试必须证明 v1 和未知消息会被忽略。

### 8.3 状态应用语义

- iframe 先完整校验状态和值域，再改变任何 SDK 属性。
- 色带节点、过滤范围、不透明度、相对位置和等值面值必须有限并在合同范围内。
- `STATE_APPLIED` 只能在属性设置完成且至少经过一个后续渲染帧后返回。
- 父页面只接受当前最新 revision 的回执；旧回执不得把 UI 标成已应用。
- 应用异常时 iframe 尝试恢复上一份已确认状态；恢复失败则进入 `failed`，不得继续显示“已渲染”。
- `RESET_VIEW` 只恢复相机，不重置用户样式。

单轴切片的协议语义固定为“只显示所选 axis 的一个平面”。iframe 如何映射到 SDK 属性由第一个探针任务确定，不能在设计中假定把另外两个坐标设为某个值一定有效。

## 9. 单轴 SDK 硬门

第二批的第一个实施 Task 只建立真实 SuperMap SDK 单轴切片能力证据，不先接入产品 UI。

探针使用非对称合成 NetCDF，在 X/Y/Z 三个方向布置可通过颜色区分的标志层，并使用固定相机和传递函数。每个轴至少测试两个非中心位置：

- 所选切片产生超过背景和 Logo 排除区阈值的有效像素。
- 所选轴的颜色/空间签名存在。
- 另外两轴的签名低于实测静帧噪声阈值，证明不是三正交切片。
- 从 X→Y→Z→X 连续切换后仍满足相同判据。

证据包含原始 PNG、裁剪区域、像素分类 JSON、SDK 版本、浏览器、GPU、运行 ID、测试代码提交和实现方式说明。人工目测只能作为补充，不能代替机器判据。

若 SDK 无法稳定独立隐藏另外两个切面，立即停止第二批并报告候选实现与失败证据。不得以三切面同时显示、裁剪相机、点云、Three.js 或自研 shader 冒充完成。

## 10. 测试与验收

### 10.1 后端便携测试

- candidate_result、builtin_preset 对应的 candidate_result、builtin_legacy 三种来源都通过同一 asset API 获取剖面。
- 小型非对称网格逐位验证 X/Y/Z 的 row/column 方向、升降序坐标、真实坐标和 SDK 相对位置。
- 显式 NoData、NaN、Inf、全 NoData、单有效值和轴边界均有确定断言。
- 总体标准差和线性插值 P10/P50/P90 与固定期望值一致。
- 非正有效值使 `log_available=false`，但原始值和统计不改变。
- 旧 result slices URL 的响应兼容测试继续通过。
- ZIP 逐文件验证列序、行序、统计、身份哈希、PNG provenance、下载响应和零绝对路径。
- 非 ready、哈希损坏、非法轴、越界索引、非法/超限 PNG 和中途失败清理均返回稳定结果。

### 10.2 前端与 Mock E2E

- 三种模式只显示各自相关控件；X/Y/Z 和剖面分析不得出现在体积或等值面模式。
- 三类来源挂载同一个 `NativeVolumePanel`，不存在 case ID 条件分支。
- 默认标度来自 `render_profile`；不可用对数保持禁用。
- SuperMap 与 ECharts 使用同一色带映射，tooltip 和统计保持原始值。
- 快速拖动、切轴、切资产以及旧请求最后成功/失败/finally 都不能污染当前状态。
- v2 的 revision、回执、非法消息、错误恢复和 v1 拒绝有独立协议测试。
- 导出只能使用当前已加载剖面；PNG 上传、成功下载和错误重试走真实 HTTP mock 流程。
- 窄屏下热力图、统计和工具栏不重叠、不溢出。

### 10.3 真实 SDK Live 门

先通过第 9 节单轴探针，再在真实 RTX 4070 + Chromium + 本机 SuperMap SDK 环境运行产品门。电阻率、微震预置和通过公开上传/实验流程产生的用户成果分别验证：

- 资产、grid、NetCDF 和页面渲染身份一致。
- Volume、X Slice、Y Slice、Z Slice、Contour 各自产生有效内容，不依靠背景、Logo 或仅包围盒过门。
- 每轴至少两个索引有超过静帧噪声的像素差，且单轴不可见判据成立。
- 色带、过滤、不透明度、光照、渐变透明度和包围盒分别产生与其语义一致的像素响应；无效果不能只凭协议回执判成功。
- 电阻率默认对数，微震和普通上传默认线性；用户切换后图例和颜色变化，但同一剖面的统计与 CSV 不变。
- 滑块交互的最新 revision 在 0.5 秒内获得 `STATE_APPLIED`，连续操作后无协议错误、资源失败或画面空白。

测试代码先在干净提交运行，再以独立 evidence-only 提交保存证据。证据提交与测试代码提交之间不得包含功能代码差异。

## 11. 失败与恢复

- 剖面 API 失败只影响分析区，不把已有体渲染改成成功或失败；用户可重试当前剖面。
- iframe 核心状态应用失败时显示类型化错误并停止接受依赖该状态的导出，不切换渲染器。
- 前端只信任最新 asset/axis/index/revision；旧网络响应和旧 iframe 回执静默丢弃。
- 导出失败不留下 Export 行、半成品 ZIP 或临时 PNG。
- 全 NoData 是有效分析结果，不显示系统错误。
- 页面刷新或切换资产恢复来源默认样式；本批不持久化个人渲染设置。

## 12. 非目标

本批不实现：

- 任意方向或倾斜剖面、多切面同时显示、剖面测线和距离量测。
- 体积统计、区域框选统计、多个剖面对比或跨成果差值分析。
- 用户案例删除和运行时文件级联回收。
- 专业诊断从实验创建流程解耦。
- 用户样式预设保存、分享或作为正式成果版本。
- iServer 发布、真实 EPSG 配准或服务端生成权威 PNG。
- Three.js、自研 WebGL、点云或旧渲染器回退。
- v0.7.0 标签和 Release；发行在后续批次与整体复审完成后决定。

## 13. 交付顺序

1. 建立单轴 SDK 探针和真实像素硬门；不通过则停止。
2. 定义 RenderAsset 剖面与 render profile 合同，抽取通用后端服务并保持旧 slices 兼容。
3. 实现统计与三轴 API，再实现原子 ZIP 导出。
4. 升级 iframe v2，以完整状态、revision 和回执接通单轴切片及所有渲染属性。
5. 拆分 Vue 控件，接入 ECharts 剖面、竞态保护和导出。
6. 运行三类来源的便携、Mock E2E 和真实 SDK 门，最后提交身份清晰的证据和文档。

每个逻辑任务采用测试先行和独立提交。不得修改运行时 SQLite 行或复制私有数据来制造通过状态。

## 14. 完成定义

第二批完成必须同时满足：

- 三类 NetCDF 来源在同一结果工作台拥有一致渲染控制和剖面分析界面。
- X/Y/Z 均为真实单轴单切面，索引、真实坐标、二维矩阵和三维画面一致。
- 光照、渐变透明度及其余已承诺控制可运行时调整，并有真实 GPU 像素证据。
- 剖面 tooltip、统计、CSV 和 manifest 来自同一权威原始数据口径。
- 当前剖面 ZIP 可下载、可追溯、无绝对路径，PNG 明确标为 ECharts 展示工件。
- 旧结果切片 API 和 v0.7.0 第一批统一工作台不回归。
- 任何能力失败都显式呈现，系统中仍不存在体渲染回退。
