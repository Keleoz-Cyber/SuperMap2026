# 微震 v0.2b 数据确认文档设计

## 1. 目标

创建一份面向项目负责人自用的中文 Markdown 文档：

`docs/microseismic_v0.2b_data_confirmation.md`

文档要让缺少地球物理专业背景的使用者也能理解当前四项数据阻断、独立查找证据、登记判断过程，并明确哪些条件满足后才允许进入 v0.2b 开发。

这份文档不是新的研究结论，也不替代论文、原始数据或资料提供者的正式说明。没有直接证据时必须保留“未确认”，不得凭图形观感或常识补全坐标、深度、单位和清洗规则。

## 2. 使用者与使用方式

主要使用者是项目负责人本人。使用者可能不熟悉微震、坐标参考系统、测线几何和数据清洗，因此文档必须：

- 先用日常语言解释问题，再给专业名称；
- 将“已知事实”“来源陈述”“推断”和“最终决定”分开；
- 给出可复制填写的 Markdown 表格和勾选项；
- 告诉使用者应去哪里找证据，以及什么证据才足够可靠；
- 允许填写“未找到”或“仍有冲突”，而不是强迫选择一个答案；
- 能在确认完成后直接交给后续开发者或 Kimi 作为输入依据。

## 3. 交付形式

采用单一 Markdown 文件，不另外创建 CSV、表格工作簿或数据库。

单文件结构按使用顺序排列：

1. 使用说明和安全边界；
2. 已确认事实；
3. 当前阻断总览；
4. 四张确认卡；
5. 统一证据登记表；
6. 决策状态与 v0.2b 启动判定；
7. 术语小词典。

这样可以减少文件切换，同时保留足够结构供人工阅读和后续程序提取。

## 4. 已确认事实区

文档开头固定列出 v0.2a 已验证且不应再次猜测的事实：

- 22 个正式 DAT 文件和 22 个正式测点；
- 2,006 条真实源记录、2,005 条有限数值记录和 1 条无效数值记录；
- W8 特殊 token `1.#QNAN0` 保留原文，不改为 0、不删除、不自动插值；
- L1/L2/L3 文件记录数为 823/819/364；
- W28 仅作冲突登记，不属于正式 L3，不参与累计距离、清洗和模型；
- 现阶段只有一维沿线累计距离，没有可信 X/Y/Z；
- 原始资料保持只读。

每项事实应注明它来自 v0.2a 审计，而不是重新包装为地球物理解释。

## 5. 四张确认卡

### 5.1 `WL/2(km)` 物理含义与 Z 换算

确认卡需解释：字段名称只说明源文件写了 `WL/2(km)`，并不能自动证明它是深度、半波长、传播距离或其他量。即使单位是 km，也不能在没有符号、基准面和换算公式的情况下直接生成 Z。

需要登记：

- 字段的完整中文或英文定义；
- 数值正方向；
- 是否等于深度；
- 如果能转换，原始量到深度/Z 的完整公式；
- 单位换算；
- Z=0 的参考面；
- 直接证据的位置。

只有定义、方向、公式和参考面均有可靠证据时，才允许解除深度/Z 阻断。

### 5.2 测线原点、方位角和坐标系

确认卡需解释：点间距只能说明同一条线上的相对距离，不能告诉计算机整条线在平面中的位置和朝向。示意图可帮助理解相交关系，但不能作为精确坐标来源。

需要登记：

- 每条测线的起点或至少一个控制点坐标；
- 点序对应的前进方向；
- 方位角的定义和数值；
- 坐标单位；
- CRS/EPSG 或明确的本地坐标系定义；
- 三条测线交点及其对应点号关系；
- 高程或 Z 基准。

文档应说明方位角通常以正北为 0°、顺时针增加，但项目只能采用来源明确规定的定义，不能把通用习惯当作本项目证据。

### 5.3 异常值和缺失值清洗规则

确认卡需区分：

- 无效数值：例如无法解析的 `1.#QNAN0`；
- 异常值：虽然是数值，但根据规则判断不可信；
- 缺失值填补：决定是否以及如何补值。

需要登记：

- “80 条异常值”对应的点号和源行，或可复现的检测规则；
- 分母和比例口径；
- 采用线性插值、邻近 5 点 IDW 或其他方法的权威依据；
- 邻域是在同一测点曲线上、同一测线上，还是三维空间中定义；
- 边界位置无法取得足够邻点时的处理；
- 是否保留原始值和清洗标记；
- 清洗版本及批准人。

正式清洗必须生成新数据，不覆盖原始数据，并保留每条记录的处理原因与方法。

### 5.4 论文与原始文件计数冲突

确认卡需并列保留：

- 论文表格：823/818/364 = 2,005；
- 文件事实：823/819/364 = 2,006 条源记录；
- 有限数值事实：822/819/364 = 2,005 条。

需要调查论文中的 2,005 是否指有限记录总数，以及 L1/L2 的 823/818 是否存在分线排版、统计或录入错误。没有权威说明前，不得移动记录以迎合论文。

解除冲突需要论文作者、原始处理说明、计算脚本或逐记录清单中的至少一种可核验依据。

## 6. 证据规则

所有证据使用统一编号，例如 `MS-E001`。登记字段包括：

- 证据编号；
- 对应问题；
- 来源文件或人员；
- 页码、表号、图号、工作表、单元格或源行；
- 原文或事实摘要；
- 支持的结论；
- 证据等级；
- 是否与其他证据冲突；
- 备注。

证据等级定义为：

1. **A级：直接权威证据**——原始数据字典、采集说明、坐标成果表、作者书面确认、可复现原始脚本。
2. **B级：直接但不完整**——论文正文或表格明确陈述，但缺少公式、单位、坐标基准或逐记录明细。
3. **C级：间接证据**——示意图、文件命名、数值形态或一般专业习惯，只能帮助提出假设。
4. **D级：个人推测**——没有可核验来源，不得用于解除阻断。

同一结论存在冲突时，状态保持“存在冲突”，即使其中一条证据等级较高，也应记录为什么采纳或拒绝另一条证据。

## 7. 决策状态

每项问题只允许使用以下状态：

- `未确认`：没有足够证据；
- `部分确认`：确认了一部分，但仍缺公式、方向、基准或适用范围；
- `存在冲突`：不同来源不能同时成立；
- `已确认`：证据足以形成可执行、可复现的规则；
- `不适用`：经证据证明本项目不需要该项。

不得使用“应该是”“大概”“看起来像”作为最终状态。

## 8. v0.2b 启动门槛

文档将开发门槛拆为三类，防止一个问题阻断所有工作：

### 8.1 可以立即开展

- 完善证据登记和资料索引；
- 继续保持源文件哈希、原始 token 和行号追踪；
- 编写不生成几何、不执行清洗的接口和验证测试。

### 8.2 开始正式清洗前必须满足

- 清洗对象或检测规则已确认；
- 比例口径已确认；
- 填补方法和邻域定义已确认；
- 原值保留与版本规则已确认。

### 8.3 开始二维/三维重建或插值前必须满足

- `WL/2(km)` 含义已确认；
- 深度/Z 换算和基准已确认；
- 测线原点、点序方向和方位角已确认；
- CRS 或完整本地坐标定义已确认；
- 计数冲突已有处理结论，且输入记录集合可复现。

如果任何必需项仍为“未确认”“部分确认”或“存在冲突”，系统必须继续显示相应 downstream gate，不能把审计通过解释为可插值。

## 9. 术语解释原则

术语小词典至少解释：

- 测线；
- 测点；
- 沿线累计距离；
- 原点；
- 方位角；
- CRS/EPSG；
- 高程、深度与 Z；
- 异常值、无效值与缺失值；
- 线性插值；
- IDW；
- 阻断条件；
- 可追溯性。

每个解释控制在一到三句话，并附与本项目直接相关的例子，避免百科式定义。

## 10. 验收标准

正式文档完成时应满足：

- 单一 Markdown 文件，可直接阅读和填写；
- 四项阻断均有通俗解释、证据要求、填写区和解除条件；
- 已确认事实与待确认推断严格分开；
- 证据登记表字段完整；
- 决策状态使用固定枚举；
- 包含明确的 v0.2b 开发门槛；
- 包含面向非专业读者的术语解释；
- 不写入未经证实的坐标、单位、深度公式或清洗结论；
- 不引用绝对本机路径；
- 不修改原始资料、现有数据契约或代码；
- Markdown 无占位符、内部矛盾和行尾空格；
- `git diff --check` 通过。

## 11. 非目标

本次不执行：

- 原始论文和 DAT 的新一轮全面研究；
- 联系论文作者或资料提供者；
- 生成 XY/Z；
- 清洗或填补速度数据；
- 微震二维/三维插值；
- SuperMap 导入；
- v0.2b 代码开发；
- 标签或 Release 发布。
