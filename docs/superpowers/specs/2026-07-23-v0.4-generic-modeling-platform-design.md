# GeoModelingPlatform v0.4 通用建模闭环设计

> 状态：已确认设计，等待实施计划。  
> 目标版本：v0.4.0。  
> 基线：`v0.3.1`，不得削弱现有电阻率演示、iServer 证据链或 157 项测试。

## 1. 目标

v0.4 将现有“固定电阻率成果展示系统”扩展为可现场操作的通用建模平台，同时保留稳定的内置电阻率演示作为答辩兜底。

必须形成两条可演示路径：

1. **内置案例路径**：直接打开电阻率案例，查看既有排行榜、三维点云、S3M 体元缓存和证据链；
2. **新数据路径**：创建案例，上传 CSV/XLSX，完成字段映射、质量校验、IDW/Kriging 调参、空间验证、模型比较、正式选择、二维/三维展示、三维切片和成果导出。

新数据先由 Python 建模并在浏览器预览。只有用户选定正式模型后，才允许进入 SuperMap 交换与 iServer 发布阶段。iServer 离线不得阻断上传、建模、比较、切片或导出。

## 2. 已确认范围

### 2.1 v0.4 核心范围

- CSV、XLSX 上传及工作表选择；
- 二维 `X/Y/value` 与三维 `X/Y/Z/value`；
- 字段映射、属性单位、坐标类型、线性单位和 Z 正方向声明；
- IDW 与普通 Kriging；
- 单组手动参数和有限网格搜索；
- 二维空间网格分块验证、三维完整 XY 空间柱验证；
- FastAPI 后台任务与 SQLite 持久化；
- 公共有效验证集合上的候选模型排行榜；
- 二维栅格和三维规则网格展示；
- 水平切片、固定 X 垂直切片、固定 Y 垂直切片；
- 正式模型选择、完整血统、成果包导出和独立发布状态；
- 内置电阻率案例回归。

### 2.2 非核心第二案例

通用闭环稳定后，使用现有微震 3σ 派生 CSV 接入第二案例，以证明平台能够处理不同属性和局部坐标数据。微震接入失败不得阻塞 v0.4.0 核心发布，也不得把仓库外派生表误报为仓库内可复现处理结果。

### 2.3 明确不做

- 用户账户、多人协作、云部署、计费和生产级高可用；
- Redis、Celery、分布式任务集群；
- 任意角度斜切面；
- 原生 GPU 体光线渲染、原生等值面；
- DSI-like/GOCAD 插值后端；
- 瓦斯正式三维接入及 iDesktopX 原生崩溃修复；
- 未经运行时验证的 iServer 全自动导入和发布承诺；
- 自动地质解释、储量计算或灾害结论。

## 3. 总体架构

采用**纵向切片式模块化单体**：浏览器、单个 FastAPI 服务、单个本地 Worker、SQLite 和受控数据目录共同完成闭环。内部模块通过明确契约交互，但不拆微服务。

```text
Vue 浏览器
  案例首页 → 上传向导 → 调参实验室 → 排行榜 → 成果与切片 → 证据/导出
        │ HTTP + 任务轮询（必要时再增加 SSE；v0.4 不要求 WebSocket）
FastAPI
  cases / datasets / quality / experiments / jobs / results / publications
        │
本地 Worker（并发 1）
  IDW / Ordinary Kriging / spatial validation / grid generation / slice generation
        │
SQLite 元数据 + 受控文件目录
        │
正式成果 → SuperMap 交换包 → 可选 iServer 发布适配器
```

### 3.1 模块职责

- `cases`：案例身份、维度、坐标声明、当前数据版本和正式模型；
- `datasets`：上传、文件解析、字段映射、标准化数据版本和 SHA-256；
- `quality`：行级有效性、排除记录、重复坐标、范围和算法前置门禁；
- `experiments`：算法、参数空间、验证配置和候选集合；
- `jobs`：入队、进度、取消、失败、重试和重启恢复；
- `interpolation`：统一插值接口及 IDW/Kriging 适配器；
- `validation`：空间折分、公共有效集合和指标复算；
- `results`：规则网格、预览抽稀、切片、指标、正式选择和成果包；
- `publications`：SuperMap 交换、iServer 探测和分级发布证据。

浏览器不得实现插值公式。发布失败不得改写建模成功状态。

## 4. 持久化模型

SQLite 保存对象关系、参数、状态和小型 JSON 元数据；原始文件与大成果保存在受控数据目录。默认目录由 `GEOMODELING_DATA_DIR` 指定，未设置时使用仓库外或被 Git 忽略的 `var/geomodeling/`。

### 4.1 核心实体

| 实体 | 关键字段 | 语义 |
|---|---|---|
| `Case` | id、name、dimension、coordinate_type、status | 独立研究案例，不与其他案例自动叠加 |
| `DatasetVersion` | case_id、source_sha256、format、sheet、mapping、units、row_counts | 一次不可变上传及其标准化版本 |
| `QualityReport` | blockers、warnings、exclusions、statistics、passed | 质量事实；通过不等于可以发布 |
| `Experiment` | dataset_version_id、algorithm、search_mode、validation_config | 一次手动或网格搜索定义 |
| `Run` | experiment_id、state、progress、timestamps、error | 后台执行实例 |
| `CandidateResult` | params、fold_metrics、common_mask_metrics、artifacts | 一个候选模型结果 |
| `FormalSelection` | result_id、reason、selected_at、supersedes | 用户正式选择；旧版本不删除 |
| `Publication` | result_id、state、service_url、evidence | 与建模状态分离的发布记录 |

### 4.2 文件布局

```text
var/geomodeling/
  platform.db
  cases/<case_id>/
    datasets/<dataset_version_id>/
      source/<original-file>
      standardized/data.parquet
      mapping.json
      quality.json
      exclusions.csv
    experiments/<experiment_id>/
      definition.json
      runs/<run_id>/logs/
      candidates/<candidate_id>/
        parameters.json
        metrics.json
        validation_predictions.parquet
        grid.npz
    exports/<result_id>/<bundle-files>
```

原始上传副本只读，永不覆盖。排除、聚合、投影和 Z 符号变化必须形成派生版本并保留来源关系。

## 5. 上传与字段映射

上传向导固定为五步：

1. 文件与工作表：CSV 编码/分隔符或 XLSX 工作表；
2. 预览与类型推断：前 50 行、全表行数和字段统计；
3. 字段角色映射：X、Y、可选 Z、属性值、可选标识字段；
4. 空间与单位声明：二维/三维、局部工程坐标/投影 CRS/经纬度、XY/Z/属性单位、Z 正方向；
5. 质量确认：阻断项、警告、排除记录、处理选择和数据指纹。

默认上传上限为 50 MiB、500,000 行。限制必须在配置中可调整，前端显示服务端实际限制。服务器根据文件内容检测格式，不只信任扩展名；文件名需要安全化，存储路径由服务端生成，禁止客户端控制目录。

### 5.1 坐标规则

- 局部工程坐标允许建模，但必须声明线性单位，界面持续显示“无绝对 CRS”；
- 投影坐标保存 CRS 标识和线性单位；
- 经纬度可以上传和预览，但不得直接以角度执行距离插值；启动实验前必须转换到用户明确选择的投影坐标，转换形成新数据版本；
- 三维数据必须声明 Z 是高程还是深度、正方向和单位；分析坐标和显示坐标的符号变换必须显式保存。

## 6. 质量门禁

### 6.1 阻止插值

- 文件无法安全解析或必填字段未映射；
- 属性值全部无效；
- 坐标无法解析为有限数值、坐标范围退化；
- 有效样本不足以满足所选算法的前置条件；
- 同一坐标存在冲突属性值且用户未选择处理方式；
- 经纬度尚未投影到线性坐标；
- 估算网格单元数超过服务端硬上限。

### 6.2 警告但允许确认后继续

- 部分行为空、特殊值或非有限值：隔离并写入排除清单；
- 属性单位未知、局部坐标无 EPSG：保留待确认标签；
- 统计离群值：只报告，不自动删除；
- 精确重复记录：用户选择保留一条、均值聚合或拒绝；
- 数据稀疏或凸包外预测风险较高。

所有处理选择写入 `DatasetVersion` 血统。禁止静默改 0、静默插补或静默删除。

## 7. 插值器与参数契约

统一接口至少包含：

```text
fit(training_points, parameters)
predict(target_points) -> values + is_nodata
validate_parameters(dataset_summary)
describe_parameters() -> defaults, bounds, units, explanations
```

前端从 `describe_parameters()` 生成表单，不重复硬编码算法参数范围。

### 7.1 IDW

首批参数：幂指数、邻点数、搜索半径、最少邻点数、X/Y/可选 Z 网格分辨率、输出范围和 NoData 规则。邻域查询必须基于线性坐标和可验证的空间索引；目标点邻居不足时输出 NoData，不得伪造值。

### 7.2 普通 Kriging

首批参数：球状、指数、高斯变异函数；自动拟合或高级手动块金值/基台值/变程；邻点数、搜索半径、网格分辨率和输出范围。

实施时必须先通过一个技术验证门：选定的 Kriging 实现需要在二维和三维合成数据上证明普通 Kriging、三种变异函数、局部邻域、NoData 和固定随机种子的结果可复算。若第三方库不能同时满足邻点数与搜索半径契约，不能通过前端暴露虚假的可调项；应更换适配器或实现受测的局部求解器。

## 8. 空间验证与排行榜

- 二维先把样本归入空间网格分组；三维按完整 XY 空间柱分组，同一 XY 柱的相邻 Z 不得跨训练/验证；
- 正式验证提供 `spatial_kfold` 和 `spatial_holdout` 两种模式：前者默认 5 折并可调整折数，后者可调整空间组留出比例；两者都保存随机种子；
- 普通随机拆点不作为正式模型验证选项；
- 同一实验的所有候选复用同一折分定义。

候选全部结束后，在所有成功候选都有效的**公共有效验证集合**上统一复算：MAE、RMSE、R²、Bias、覆盖率、NoData 数量和运行时间。候选失败保留错误信息。系统可给出综合推荐及理由，但用户选择正式模型时必须填写选择理由。

## 9. 调参与后台任务

### 9.1 搜索模式

- 手动：运行一套参数，成功后加入候选列表；
- 网格搜索：用户选择离散候选值，界面实时计算组合数量；默认最多 30 组，硬上限 50 组。

运行前显示估算网格尺寸、单元数和组合数。规则网格默认硬上限 1,000,000 单元；浏览器可以抽稀预览，但原始网格成果不得因预览抽稀而丢失。

### 9.2 任务状态

```text
queued → running → succeeded
                 ↘ failed
                 ↘ canceled
                 ↘ interrupted
```

FastAPI 负责入队和查询。单个本地 Worker 顺序运行 CPU 密集任务，避免多个 Kriging 同时耗尽答辩机内存。任务记录当前阶段、候选序号、总候选数、进度、耗时和诊断。

- 取消会阻止后续候选；当前不能安全中断的数值步骤结束后退出；
- 服务启动时遗留的 `running` 状态转为 `interrupted`，用户可重试；
- 重试创建新的 `Run` 并引用原定义，不覆盖原失败记录；
- 单个候选失败不删除已完成候选。

前端第一版使用轮询读取进度。只有实际需要更高频更新时才增加 SSE，不引入 WebSocket 作为 v0.4 前置条件。

## 10. 成果契约与切片

二维成果为规则 X/Y 网格；三维成果为规则 X/Y/Z 网格。标准成果保存坐标轴、值数组、NoData 掩膜、完整参数和数据指纹。内部可使用 NPZ/Parquet，浏览器通过 API 读取预览和切片，不直接读取服务器文件路径。

### 10.1 展示

- 二维：栅格热力图、统一色标、测点叠加、阈值和透明度；
- 三维：规则格点/体元、测点叠加、阈值、透明度、点大小、Z 夸张和视角复位；
- 大网格完整视图按确定性规则抽稀，界面显示原始单元数和预览单元数。

### 10.2 三维切片

- 水平：固定 Z，横纵轴为 X/Y；
- X 垂直：固定 X，横纵轴为 Y/Z；
- Y 垂直：固定 Y，横纵轴为 X/Z；
- 滑块同时显示网格索引和真实坐标；不在网格面时吸附最近网格面并明确标注；
- 默认沿用完整成果的全局色标；局部增强仅为临时显示，截图或导出必须标注；
- 切片从原分辨率规则网格读取，不从浏览器截图或抽稀预览反推。

任意角度斜切面不进入 v0.4。

## 11. 正式选择、导出与发布

只有状态成功且通过质量门禁的候选可以设为正式模型。用户必须填写选择理由；新选择创建版本并通过 `supersedes` 指向旧版本，不删除历史成果。

成果包至少包含：

- 标准网格；
- 标准测点和验证预测 CSV/Parquet；
- `metadata.json`（输入哈希、映射、单位、坐标、算法、参数、版本）；
- 指标 JSON/CSV；
- 质量报告、排除清单、失败记录和 Markdown 报告；
- SuperMap 可交换文件及人工/自动发布说明。

发布状态独立分级：

```text
export_ready
→ publish_pending 或 manual_required
→ published
→ metadata_verified
→ browser_loaded
```

只有真实服务可达且身份/元数据匹配时才进入相应状态。程序化发布在本机不受支持时必须返回 `manual_required`，不得伪装成功。

## 12. 前端页面

1. **案例首页**：内置案例、新案例、数据与任务状态；
2. **上传向导**：文件、预览、映射、空间声明、质量确认；
3. **调参实验室**：算法、参数解释、空间验证、组合计数、任务进度；
4. **模型对比**：公共有效排行榜、折指标、覆盖率、参数快照和失败候选；
5. **成果工作台**：二维/三维完整场、测点叠加、水平/X/Y 切片；
6. **证据与导出**：血统、状态链、正式选择、成果包和发布证据。

页面不得把“校验通过”“插值成功”“导出成功”“iServer 发布成功”“浏览器加载成功”合并成单一成功状态。

## 13. API 轮廓

首批路由按资源组织：

```text

GET    /api/cases/{case_id}
POST   /api/cases/{case_id}/datasets/uploads
POST   /api/datasets/{dataset_id}/mapping
GET    /api/datasets/{dataset_id}/quality
POST   /api/experiments
POST   /api/experiments/{experiment_id}/runs
GET    /api/runs/{run_id}
POST   /api/runs/{run_id}/cancel
POST   /api/runs/{run_id}/retry
GET    /api/experiments/{experiment_id}/candidates
GET    /api/results/{result_id}
GET    /api/results/{result_id}/preview
GET    /api/results/{result_id}/slices?axis=x|y|z&index=N
POST   /api/results/{result_id}/select-formal
POST   /api/results/{result_id}/exports
POST   /api/results/{result_id}/publications
```

具体请求/响应模型在实施计划中拆分，但必须复用同一 Pydantic 领域契约，禁止 API、Worker 和前端各自定义不同字段含义。

## 14. 错误、安全与恢复

- 上传、映射、校验、建模、选择、导出、发布分别记状态；
- 错误响应包含稳定错误码、用户可读说明和诊断详情，不回传本机敏感路径；
- 上传文件名安全化，服务端生成目录，阻止路径穿越和覆盖；
- ZIP/压缩上传不在 v0.4 范围，避免压缩炸弹；
- 解析 XLSX 时限制大小、工作表和行数；
- 数值参数在 API 层与算法层双重校验；
- 数据文件与 SQLite 的提交采用先写临时文件、校验后原子替换，避免半成品被登记成功；
- 删除案例不进入 v0.4 核心；避免误删原始上传和成果。

## 15. 测试策略

- **单元测试**：字段映射、质量门禁、IDW/Kriging、空间折分、网格、切片、指标；
- **契约测试**：状态机、公共有效集合、NoData、正式选择和发布证据；
- **API 集成测试**：临时 SQLite 与临时数据目录，走上传、映射、校验、实验、任务、结果和导出；
- **前端测试**：上传向导状态、组合数、进度恢复、排行榜和切片状态；
- **浏览器冒烟**：使用 Mock API 完成固定流程；本机 iServer 单独作为 live 验证；
- **回归测试**：现有 157 项不得减少或失败，v0.3.1 电阻率页面和显示模式必须保留。

Portable CI 不依赖真实资料、UDBX 或本机 iServer。本地真实数据与 live iServer 测试继续使用独立标记和明确证据。

## 16. 实施里程碑

1. **M1 数据接入**：案例、SQLite、受控目录、CSV/XLSX、映射与质量报告；
2. **M2 计算底座**：2D/3D IDW、Kriging 技术验证门、空间验证、公共指标和 Worker；
3. **M3 调参前端**：上传向导、手动参数、网格搜索、进度和排行榜；
4. **M4 成果闭环**：二维/三维预览、水平/X/Y 切片、正式选择、成果包和发布状态；
5. **M5 加固与第二案例**：电阻率回归、答辩预设、微震派生 CSV 接入。

每个里程碑单独提交、测试和审查。M1-M4 是 v0.4.0 核心；M5 的微震部分不阻塞核心发布。

## 17. v0.4.0 验收标准

- 内置电阻率 v0.3.1 演示、S3M 自定义渲染和三模式切换不回退；
- 能创建案例并上传 CSV 或 XLSX；二维和三维字段映射均能完成；
- 错误坐标、无效值、重复冲突和未投影经纬度得到正确门禁；
- IDW 与普通 Kriging 均能运行手动参数；
- 有限网格搜索能显示进度、失败候选和公共有效排行榜；
- 刷新页面后任务与成果仍存在；取消、失败、`interrupted` 和重试行为可验证；
- 成功结果可设为正式模型并保存理由；
- 二维和三维结果能够显示，三维支持水平/X/Y 切片；
- 成果包可下载，包含完整血统、参数、指标和失败证据；
- iServer 离线不影响建模，发布状态不与建模状态混报；
- Portable CI、真实数据回归和 live iServer 验证继续分层登记。

## 18. 迁移与兼容

v0.4 不强制把 v0.1-v0.3 的所有文件改造成新数据库记录。内置电阻率案例通过只读适配器暴露为 `Case`/`Result` 视图，新上传案例使用新持久化模型。待新流程稳定后再决定是否迁移历史数据，避免为迁移破坏已发布的 v0.3.1 演示。
