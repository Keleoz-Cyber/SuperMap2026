# v0.6.1 NetCDF 原生体渲染运行手册

> 适用版本：v0.6.1（`feat/v0.6.1-netcdf-native-rendering` 分支）。本文是 NetCDF
> 原生体渲染的安装、运行、验收与故障诊断唯一入口。所有命令在仓库根目录执行；
> 文档不含本机绝对路径与凭据，SDK 与运行时数据均为本机不入库资产。

## 0. 事实口径（先读）

- 唯一连续体渲染器是 SuperMap3D 12.1 `VoxelGridLayer3D` + NetCDF classic/v3 体包；
  点元只是显式标注的 auxiliary points（辅助/证据层），绝不把失败的体渲染变成成功。
- 坐标是 `wgs84_display_anchor_v1` 显示锚点（120°E / 30°N）的显示变换，页面必须
  显示 `display_anchor_only`；不宣称真实地理配准。
- 资产经 `render_assets` 表（SQLite v6）管理：POST 是唯一创建路径，GET 纯查询；
  manifest/grid/NetCDF 哈希双向核验；损坏资产原子隔离、绝不自动删除。
- 失败语义是 no silent fallback：能力不满足、哈希不符、SDK 缺失都显式报错，
  不存在任何形式的回退渲染器。
- 性能事实（Task 14 参考机实测，RTX 4070 Laptop）：32^3 与 64^3 真实渲染
  rendered <2s、交互稳定 <0.5s，远低于 30s/5s 发布门；filter/opacity/Slice/
  Contour 四命令像素响应均超静帧噪声。

## 2. SuperMap3D SDK 安装与预检

SDK 是本地不入库资产，安装目标是 `web/public/SuperMap3D-2026`（git-ignored），
`SuperMap3D.js` 的 SHA-256 被钉死，预检 fail-closed：

```powershell
# 首次安装（--source 指向本机 SuperMap3D 产品包的 Build/SuperMap3D 目录）
python scripts/install_supermap3d.py --source <本机SDK源目录> --destination web/public/SuperMap3D-2026 --expected-sha256 d69dadab01fc452a79f1fa88a46aced3cf29885df7bf4febbd6f24ce5b578120

# 预检（不复制任何文件，只核验钉住的哈希与完整资源树）
python scripts/install_supermap3d.py --destination web/public/SuperMap3D-2026 --verify-only --expected-sha256 d69dadab01fc452a79f1fa88a46aced3cf29885df7bf4febbd6f24ce5b578120
```

前端构建会把 `web/public` 拷入 `web/dist`，live 验收加载的是
`web/dist/SuperMap3D-2026/SuperMap3D.js`，因此装/换 SDK 后必须重新 build。

## 4. 通用候选：显式物化与渲染资产 POST

POST 是唯一变异路径。候选必须先显式物化网格，再显式创建渲染资产：

```powershell
# 显式物化候选网格（唯一物化入口）
curl -X POST http://127.0.0.1:8000/api/results/<候选成果id>/materialize

# 能力查询（纯查询：supported / not_applicable + 稳定原因码）
curl http://127.0.0.1:8000/api/results/<候选成果id>/render-capability

# 显式创建 NetCDF 渲染资产：首个成功 201；ready 幂等复用 200；
# creating 409 RENDER_ASSET_IN_PROGRESS；failed/interrupted 不带 retry 返回持久化失败 409
curl -X POST http://127.0.0.1:8000/api/results/<候选成果id>/render-assets/netcdf -H "Content-Type: application/json" -d "{}"

# 资产状态（纯查询）
curl http://127.0.0.1:8000/api/results/<候选成果id>/render-assets/netcdf
```

## 5. legacy 电阻率：权威规则网格导入

内置电阻率案例不自散点重建正式网格；唯一桥梁是把权威 CSV 原子登记为
legacy 渲染源（绝不重跑 Kriging）：

```powershell
python -m geomodeling.render_cli import-csv --source-id resistivity --csv <权威网格CSV> --x X --y Y --z Z --value RHO --property-name RHO --units unknown --data-dir var/geomodeling
```

同一命令组也挂在主 CLI（`python -m geomodeling.cli render-grid import-csv`）。
未登记时能力查询返回 `LEGACY_RENDER_SOURCE_NOT_REGISTERED`，页面只显示
auxiliary points 测点辅助层，不宣称体渲染能力。登记后：

```powershell
curl http://127.0.0.1:8000/api/cases/resistivity/render-capability
curl -X POST http://127.0.0.1:8000/api/cases/resistivity/render-assets/netcdf -H "Content-Type: application/json" -d "{}"
```

## 6. 资产状态与哈希检查

每个不可变资产（`nc-<32位小写十六进制>` 内容寻址）可双向核验：

```powershell
# manifest v2：身份 + 形状 + 统计 + manifest/grid/NetCDF 哈希 + 显示契约
curl http://127.0.0.1:8000/api/render-assets/<资产id>/manifest

# 下载 NetCDF 体包并核验 SHA-256 与 manifest 一致
curl -o outputs/volume-check.nc http://127.0.0.1:8000/api/render-assets/<资产id>/volume.nc
python -c "import hashlib,pathlib;print(hashlib.sha256(pathlib.Path('outputs/volume-check.nc').read_bytes()).hexdigest())"
```

文件端点只服务 ready 行：服务端先重算当前文件哈希并与登记身份比对，不符即
`RENDER_ASSET_CORRUPT`（JSON 错误体，绝不下发字节），损坏目录原子隔离、不自动
删除。哈希不符 = 资产身份事故，按 §9 `asset_identity` 处理。

## 8. live 32^3/64^3 浏览器门（隔离运行时）

真实 SDK 门是本地发布门：Playwright 自起 uvicorn（端口 5201）+ 临时 SQLite，
调用环境必须提供唯一的隔离 `GEOMODELING_DATA_DIR`（绝不指向默认运行时目录）：

```powershell
$env:GEOMODELING_DATA_DIR = "$PWD/var/geomodeling-e2e-live"
python scripts/install_supermap3d.py --destination web/public/SuperMap3D-2026 --verify-only --expected-sha256 d69dadab01fc452a79f1fa88a46aced3cf29885df7bf4febbd6f24ce5b578120
npm --prefix web run build
npm --prefix web run test:e2e:live -- e2e-live/supermap-volume-frame-live.spec.ts e2e-live/supermap-native-volume-live.spec.ts
Remove-Item Env:GEOMODELING_DATA_DIR
```

判定：32^3 与 64^3 确定性基准网格各自走完 产品页 → 显式 POST 资产 →
iframe 握手 → rendered（30s 门，实测记录）→ 中央画布非背景体积像素 →
filter/opacity/Slice/Contour 像素响应超静帧噪声 → 64^3 每条命令 5s 内像素
稳定；证据（同一 run ID、commit、SDK 哈希、GPU、视口、双哈希）写入
`docs/evidence/v0.6.1-netcdf-native/<run-id>/`。

## 9. 诊断（七类，按症状定位）

| 类别 | 症状 | 检查 |
|---|---|---|
| `source_contract` | 能力查询 `not_applicable`（2D/不规则轴/无源/全 NoData）或稳定错误码 | 数据契约与网格规则性；legacy 是否已登记权威网格 |
| `netcdf_export` | 资产转 `failed`，导出/回读校验失败 | NetCDF classic/v3 三文件写盘与回读哈希；shape/NoData 语义 |
| `asset_identity` | `RENDER_ASSET_CORRUPT`，manifest/grid/NetCDF 哈希双向核验不符 | 重算文件哈希比对登记身份；损坏目录已原子隔离，修复后显式重试 |
| `sdk_runtime` | iframe 白屏且握手超时，或预检失败 | §2 `--verify-only`；`web/dist/SuperMap3D-2026/SuperMap3D.js` 是否存在且哈希钉住 |
| `camera_or_bounds` | 握手成功但画布无体积像素 | 显示锚点包围盒与相机定位；`display_anchor_only` 变换是否正确应用 |
| `browser_or_gpu` | WebGL 上下文创建失败/渲染异常 | 浏览器与 GPU（参考机 RTX 4070 Laptop）；证据中的 GPU renderer 标识 |
| `message_protocol` | iframe 握手/命令无响应 | postMessage 协议 `gmp-supermap-volume/v1` 握手序列与命令回执 |

## 10. creating → interrupted 恢复与显式重试

进程重启时，SQLite 启动迁移把在途 `creating` 行原子转 `interrupted`（绝不
重排队）。恢复流程：

```powershell
# 1. 重启后查询资产状态，确认 interrupted（或 failed）与持久化错误码
curl http://127.0.0.1:8000/api/results/<候选成果id>/render-assets/netcdf

# 2. 直接 POST 不带 retry 会返回持久化失败 409；必须显式重试
curl -X POST http://127.0.0.1:8000/api/results/<候选成果id>/render-assets/netcdf -H "Content-Type: application/json" -d "{\"retry_failed\": true}"
```

显式重试重新走隐藏 stage 写齐 + fsync + `os.replace` 单点改名 + `mark_ready`；
任何异常清理 stage 并 `mark_failed`，绝不留下半拷贝的 ready 行。

## 11. 明确不做

- 真实 CRS 配准（无控制点证据）；WebGPU；128^3 生产支持；
- iServer/S3M 分发、iDesktopX `DatasetVolume`；移动端浏览器；
- 从散点自动重建内置电阻率正式网格；任何形式的回退渲染器。
