# v0.6.1 `VoxelGridLayer3D + NetCDF` 最小验证开发说明

> 面向对象：实现和验收本 POC 的开发 agent。  
> 基线：`v0.6.0`，提交 `a9ffaf9`。  
> 目标运行时：本机 iClient3D for WebGL/WebGPU 2026，`SuperMap3D 12.1.0`，首轮固定 WebGL2。  
> 目标成果：`35348bb3-be03-4862-b764-ee165ae0c7dc`。  
> 本文是开发任务书，不代表该路线已经渲染成功。

## 1. 结论和验证目标

本 POC 只回答一个问题：

> 项目物化的三维规则网格能否不经过 iDesktopX、iServer、S3M 和载体模型，转换为 NetCDF v3 后，由 SuperMap3D 12.1 的 `VoxelGridLayer3D` 在浏览器中直接完成彩色连续体渲染？

验证链路固定为：

```text
指定 result_id 的 grid.npz
  -> 确定性 NetCDF classic/v3 导出
  -> 独立 SuperMap3D 12.1 页面
  -> scene.addVoxelGridLayer(volume.nc, layerName)
  -> VoxelGridLayer3D.startRender(...)
  -> VolumeRendering
  -> 色带、透明度、阈值和模式变化
  -> 浏览器截图与像素差证据
```

只要该链路通过，就证明 SuperMap 现有组件具备本项目需要的浏览器原生体素渲染能力。它不会自动证明大数据性能、真实地理配准、iServer 发布或 S3M 生产部署已经完成。

### 1.1 本 POC 不使用的组件

以下内容一律不进入首轮验证：

- iDesktopX、`DatasetVolume` 和人工导入切片；
- iServer 工作空间、数据服务和三维服务发布；
- S3M、SCP、S3MB、`.vol`、模型缓存和载体模型；
- 现有 `/volume-demo` 自研光线步进实现；
- Three.js；
- 旧 Cesium/iClient3D 1.67 页面；
- 点云或 `PointPrimitiveCollection` 降级。

禁止在 `VoxelGridLayer3D` 失败后自动显示点云并将 POC 标记为成功。失败必须保留明确的错误码和原始异常。

### 1.2 与现有两条路线的区别

| 路线 | 数据送入方式 | 渲染器 | 首轮人工步骤 | 本 POC 是否使用 |
| --- | --- | --- | --- | --- |
| `/volume-demo` | 项目自定义纹理/数组 | 自研 WebGL2 光线步进 | 无 | 否，只作效果对照 |
| `DatasetVolume + iServer` | GeoTIFF 切片，经 iDesktopX 建体数据集 | SuperMap 动态 Volume | 多 | 否 |
| `S3M + .vol` | 模型缓存叠加体数据 | S3M 图层 | 多，且已遇到坐标契约问题 | 否 |
| 本 POC | 浏览器直接读取 `.nc` | `VoxelGridLayer3D` | 无 | 是 |

本 POC 的价值是减少排障变量。它不依赖已发布服务、缓存类型或载体模型是否正确。

### 2.1 必须规避的文档参数错误

本机生成的 `VoxelGridLayer3D.html` 把变量名参数写成了：

```text
options.setDataBounds
```

但实际 12.1 构建包读取的是：

```js
layer.startRender({
  variableName: "rho",
  xDimName: "x",
  yDimName: "y",
  zDimName: "z",
});
```

因此实现必须使用 `variableName`，不能照抄 HTML 文档中的 `setDataBounds`。如果 `startRender` 没有成功，首先在浏览器断点或日志中验证传入对象和实际构建包，不能把参数名改回 `setDataBounds`。

### 2.2 首轮运行时固定项

```js
contextOptions: { contextType: 2 } // WebGL2
```

`contextType: 3` 是 WebGPU，本 POC 首轮不使用。只有 WebGL2 已通过全部验收后，才能把 WebGPU 作为第二组兼容性实验；不得用 WebGPU 结果替代 WebGL2 基准结果。

页面只使用全局 `SuperMap3D` API，不直接调用独立 Cesium API，也不能在同一页面加载旧版 Cesium 1.67。

## 4. NetCDF v3 文件契约

### 4.1 文件和变量结构

首轮只输出 NetCDF classic/v3，不使用 NetCDF4/HDF5、压缩、chunk 或 group。

```text
dimensions:
  x = 11
  y = 11
  z = 11

coordinate variables:
  x(x): float32
  y(y): float32
  z(z): float32

scalar variable:
  rho(x, y, z): float32
```

固定命名：

```text
xDimName = "x"
yDimName = "y"
zDimName = "z"
variableName = "rho"
```

本 POC 不添加 time 维度。后续确有时序成果时，再独立验证 `timeDimName`，不能提前扩大首轮变量。

### 4.2 轴顺序和扁平化

源网格契约为：

```text
values[i, j, k] <=> x[i], y[j], z[k]
```

NetCDF 标量变量维度固定写成 `("x", "y", "z")`，并将 NumPy 的 `values[x, y, z]` 按 C-order 原样写入。禁止进行 GeoTIFF 使用的转置或 Y 轴翻转：

```python
rho[:] = encoded_values.astype(np.float32, copy=False)
```

必须增加一个非对称方向测试，以防 `x/y/z` 互换后仍能显示一个“看似正常”的长方体。测试数据至少在 X、Y、Z 三个方向使用不同变化率，并验证导出后读回的角点和内部点。

### 4.3 数据类型和 NoData

实际 12.1 NetCDF 读取链路按单精度浮点读取标量数据，因此：

- `rho` 必须是 NetCDF `float`，即 IEEE Float32；
- 坐标变量首轮也统一为 Float32；
- Float64、整数和复合变量不属于本 POC；
- 有效数据转换为 Float32 后，数值误差按显式容差验收。

当前 GeoTIFF manifest 中的 NoData 是：

```text
5.284669896754732
```

不得把它沿用到本 POC。实际体素编码链路把 `-9999` 识别为无效/透明体元，因此 NetCDF 必须同时满足：

```text
rho._FillValue = -9999.0f
rho.missing_value = -9999.0f
所有无效或非有限体元的实际存储值 = -9999.0f
```

不能只写 `_FillValue` 属性而保留 `NaN`，也不能用 0、最小值、均值或 GeoTIFF NoData 替代。

### 4.4 建议属性

NetCDF 全局属性至少包含：

```text
Conventions = "CF-1.8"
title = "RACE v0.6.1 SuperMap VoxelGridLayer3D POC"
candidate_result_id = 固定 result_id
grid_sha256 = 固定 SHA-256
coordinate_contract = "wgs84_display_anchor_v1"
geolocation_status = "display_anchor_only"
generator = 稳定的导出器名称和版本
```

坐标变量属性：

```text
x.standard_name = "longitude"
x.units = "degrees_east"
y.standard_name = "latitude"
y.units = "degrees_north"
z.standard_name = "height"
z.units = "m"
z.positive = "up"
```

`rho` 属性：

```text
rho.long_name = "resistivity"
rho.units = 当前成果真实单位；若源元数据无单位则写 "unknown"，不得猜测
rho.valid_min = Float32 有效最小值
rho.valid_max = Float32 有效最大值
```

这些属性用于审计，不可假设 SuperMap3D 会根据 CF 属性自动设置地理范围。渲染范围仍由页面显式赋值。

### 4.5 确定性输出

相同 `result_id + grid_sha256 + exporter_version` 必须产生相同的：

- NetCDF 变量、维度、属性和值；
- `manifest.json`；
- `volume.nc` SHA-256；
- 导出逻辑 ID。

不要把当前时间写入 `volume.nc`，否则无法得到稳定哈希。生成时间可以写在 API/操作日志中，但不能进入参与内容寻址的文件。

建议导出 ID：

```text
<result_id>-<grid_sha256前16位>-voxelgrid-netcdf-v1
```

## 7. 后端实现任务

### 7.1 导出器

使用项目已有 SciPy 依赖：

```python
from scipy.io import netcdf_file
```

不要为 POC 新增 `netCDF4`、`xarray` 或 HDF5 依赖。

实现入口建议为：

```python
def export_supermap_voxel_netcdf(
    runtime: PlatformRuntime,
    result_id: str,
) -> dict[str, Any]:
    ...
```

实现顺序：

1. 使用现有安全规则验证 `result_id`。
2. 调用 `materialize(runtime, result_id)`，要求成果维度为 `3d`。
3. 读取只读 `grid.npz`，取出 `axes`、`values`、`is_nodata`。
4. 校验三轴严格递增、有限、近似等间距，且 `values.shape == is_nodata.shape == (len(x), len(y), len(z))`。
5. 计算 `grid.npz` SHA-256，并将其作为导出身份的一部分。
6. 复用现有固定显示锚点规则生成 WGS84 的 render X/Y；Z 使用源高度加固定 anchor height。
7. 将 `is_nodata | ~isfinite(values)` 的位置写为 Float32 `-9999.0`。
8. 用临时目录写 `volume.nc`，关闭文件后重新读回验证。
9. 写 manifest 和 checksums。
10. 用临时文件加原子替换发布结果，禁止请求中途留下半个 `.nc`。
11. 若相同身份的完整产物已经存在且哈希一致，返回已有产物。

建议写入骨架：

```python
with netcdf_file(nc_path, mode="w", version=1) as nc:
    nc.createDimension("x", len(render_x))
    nc.createDimension("y", len(render_y))
    nc.createDimension("z", len(render_z))

    x_var = nc.createVariable("x", "f", ("x",))
    y_var = nc.createVariable("y", "f", ("y",))
    z_var = nc.createVariable("z", "f", ("z",))
    rho_var = nc.createVariable("rho", "f", ("x", "y", "z"))

    x_var[:] = np.asarray(render_x, dtype=np.float32)
    y_var[:] = np.asarray(render_y, dtype=np.float32)
    z_var[:] = np.asarray(render_z, dtype=np.float32)

    encoded = np.where(
        is_nodata | ~np.isfinite(values),
        np.float32(-9999.0),
        values,
    ).astype(np.float32)
    rho_var[:] = encoded
```

属性应在写值前完整设置。SciPy `netcdf_file` 的属性类型需要通过读回测试确认，尤其是 `_FillValue` 必须为 Float32，不得意外写成字符串或 Float64。

### 7.2 API

建议增加：

- 不返回本机绝对路径；
- 不暴露 token、cookie、管理员密码或存储目录；
- 不允许 `export_id` 路径穿越；
- 每次返回的 manifest 必须与 `.nc` SHA-256 对应。

开发服务器通过 Vite `/api` 代理访问 FastAPI。首轮不经 iServer，因此不增加 `/iserver` 请求。

### 7.3 后端单元测试

至少覆盖：

1. 固定 11³ 成果成功导出；
2. 维度名、变量名、变量维度顺序和 dtype 正确；
3. Float32 读回值与源有效值在 `rtol=1e-6, atol=1e-5` 内一致；
4. 无效值读回后全部严格等于 `-9999.0`；
5. 三个坐标轴读回后单调递增；
6. 经度、纬度、Z 包围盒与 manifest 在 Float32 表示容差内一致；
7. 非对称方向夹具证明没有转置和翻转；
8. SHA-256、result ID 和 manifest 身份一致；
9. 重复导出字节确定；
10. 2D、退化轴、非单调轴、不规则轴、形状不一致和全 NoData 均明确失败；
11. 下载 API 拒绝非法 `export_id`；
12. API 返回正确 MIME，且不泄露本机路径。

### 8.1 初始化顺序

```js
const viewer = new SuperMap3D.Viewer("container", {
  contextOptions: { contextType: 2 },

const scene = await viewer.scenePromise;
const manifest = await fetch(manifestUrl).then(checkResponse).then((r) => r.json());

layer.zBounds = new SuperMap3D.Cartesian2(
```

### 8.3 相机

相机目标使用 manifest 的经纬度中心和 Z 中心计算。禁止把局部工程坐标 `(-160..-40, 220..660)` 传入 `fromDegrees`。

由于水平范围约 120 m、垂直范围约 813 m，初始相机距离应根据三轴最大跨度计算，并给出足够余量。不要写死只适合某台显示器的相机高度。页面提供“缩放至体数据”按钮以便重复归位。

### 8.4 最小控制和诊断信息

页面只需要以下功能性控件：

- 渲染模式：`VolumeRendering`、`Slice`、`ContourValue`；
- 最小过滤值；
- 最大过滤值；
- 总体不透明度；
- 梯度不透明度开关；
- 光照开关；
- 恢复默认参数；
- 缩放至体数据。

状态区必须显示：

```text
SDK version
WebGL/WebGPU context type
result_id
grid_sha256
NetCDF URL
NetCDF SHA-256
layer constructor/type
current render mode
current thresholds
load/render state
last error code and message
```

这些是诊断信息，不是成功判据。出现 layer 对象或 HTTP 200 仍可能没有有效体绘制。

全局收集：

```js
window.addEventListener("error", ...);
window.addEventListener("unhandledrejection", ...);
```

并把测试状态暴露为只读对象：

```js
window.__VOXEL_POC__ = {
  phase: "ready | loading | rendered | failed",
  identity: { resultId, gridSha256, netcdfSha256 },
  layerType: "VoxelGridLayer3D",
  renderMode: "VolumeRendering",
  errors: [],
};
```

不要把整个 layer、viewer 或凭据挂到该对象。

## 9. 浏览器验收和证据

仅凭肉眼看到“有东西”不能通过。必须同时保存机器可读数据和截图。

### 9.1 Playwright 用例

建议单独运行真实浏览器规格，不放入 jsdom/Vitest。

用例步骤：

1. 打开独立页面，等待 `window.__VOXEL_POC__.phase === "rendered"`，总超时明确设置。
2. 断言 NetCDF、SDK、Worker、Assets 请求无 4xx/5xx。
3. 断言无 `pageerror`、`unhandledrejection` 和 WebGL program error。
4. 断言 layer 类型为 `VoxelGridLayer3D`。
5. 断言当前模式为 `VolumeRendering`。
6. 截取基准画布并统计非背景像素。
7. 将最小阈值提高到中位区间，再截图并计算像素差。
8. 修改不透明度，再截图并计算像素差。
9. 切换到 `Slice`，截图并计算像素差。
10. 切换到 `ContourValue`，截图并计算像素差。
11. 输出 `evidence.json`。

像素检查不能只使用文件大小。至少读取 canvas 截图 RGBA，排除：

- 纯透明画布；
- 单一背景色；
- 只有底图或天空盒；
- 只有 UI 控件；
- 改变阈值后画面完全不变。

为避免底图造成假阳性，建议测试模式关闭天空、底图和不必要的 UI，并只裁剪 3D canvas 的中央有效区域。

### 9.2 证据目录

```text
docs/evidence/v0.6.1-voxelgrid-netcdf-poc/
├── environment.json
├── export-manifest.json
├── netcdf-inspection.json
├── network.json
├── console.json
├── evidence.json
├── 01-volume-default.png
├── 02-volume-threshold.png
├── 03-volume-opacity.png
├── 04-slice.png
└── 05-contour.png
```

`environment.json` 至少记录：

```text
UTC 时间
git commit
dirty worktree true/false
SuperMap3D 版本和 SDK 文件 SHA-256
浏览器版本
GPU renderer
WebGL context type
viewport
devicePixelRatio
result_id
grid_sha256
netcdf_sha256
```

不记录本机管理员凭据、token、cookie 或用户目录下的绝对缓存路径。

### 9.3 通过条件

以下条件必须全部成立：

1. NetCDF 身份与指定 `result_id + grid_sha256` 一致。
2. 维度严格为 `11 × 11 × 11`，变量为 Float32 `rho(x,y,z)`。
3. 有效值、NoData 数量和有效 min/max 与源网格在声明容差内一致。
4. 浏览器获得真实 `VoxelGridLayer3D`。
5. 初始模式为 `VolumeRendering`。
6. canvas 中存在可归因于体数据的非背景像素。
7. 修改阈值和不透明度会产生超过噪声阈值的像素变化。
8. 切换 `Slice` 或 `ContourValue` 会产生超过噪声阈值的像素变化。
9. 无页面异常、Promise rejection、着色器错误或失败的 NetCDF/SDK 资源请求。
10. 截图、网络记录、控制台记录和机器可读证据全部落盘。
11. 失败时没有点云或自研渲染器降级冒充成功。

第 7、8 项的像素差阈值应先在同一静止画面连续截图中测量背景噪声，再设为明显高于该噪声的固定值，并写入 `evidence.json`。禁止使用“任意一个像素变化”这种不稳定判据。

## 10. 失败码和停止条件

建议错误码：

```text
VOXEL_NC_RESULT_INVALID
VOXEL_NC_REQUIRES_3D
VOXEL_NC_GRID_MISSING
VOXEL_NC_GRID_INVALID
VOXEL_NC_AXIS_INVALID
VOXEL_NC_AXIS_NOT_MONOTONIC
VOXEL_NC_GRID_IRREGULAR
VOXEL_NC_SHAPE_MISMATCH
VOXEL_NC_NO_VALID_VALUES
VOXEL_NC_FLOAT32_RANGE
VOXEL_NC_WRITE_FAILED
VOXEL_NC_READBACK_FAILED
VOXEL_NC_IDENTITY_MISMATCH
VOXEL_NC_CHECKSUM_MISMATCH
VOXEL_NC_NOT_FOUND
VOXEL_LAYER_LOAD_FAILED
VOXEL_LAYER_START_RENDER_FAILED
VOXEL_LAYER_BLANK_CANVAS
VOXEL_LAYER_NO_PIXEL_RESPONSE
VOXEL_LAYER_RESOURCE_FAILED
```

遇到以下任一情况立即停止，不继续调色冒充排障：

- 生成的文件不是 NetCDF classic/v3；
- `rho` 不是 Float32 或维度顺序不是 `x,y,z`；
- `-9999` 与有效值发生碰撞；
- 导出读回出现轴交换、翻转或值数量变化；
- manifest、grid 或 NetCDF 哈希身份不一致；
- NetCDF 请求失败或响应成了 HTML/JSON 错误页；
- `addVoxelGridLayer` 返回的不是目标图层；
- 使用 `variableName` 仍无法初始化时没有保存原始错误；
- canvas 空白；
- 参数变化没有像素响应；
- 浏览器使用了旧版 SDK 或混合了两套 Assets/Workers；
- GPU/WebGL2 不满足运行要求。

只有在上述证据保存后，才能判断问题属于：

```text
export_contract
sdk_loader
render_configuration
camera_or_bounds
browser_or_gpu
```

不要在同一轮同时改变 NetCDF 轴顺序、坐标包围盒、色带和相机，否则无法归因。

## 11. 推荐实施顺序

### 阶段 A：格式探针

先用一个程序生成的 `4 × 5 × 6` 非对称小 NetCDF，不接业务 API：

- X/Y/Z 三方向使用不同长度和数值梯度；
- 含少量 `-9999`；
- 使用固定经纬度和高度包围盒；
- 在独立页面验证 `VoxelGridLayer3D` 能加载、着色和响应参数。

阶段 A 失败时，不接入 `grid.npz`，直接根据控制台、网络和像素证据定位 SDK 格式契约。

### 阶段 B：固定成果导出

格式探针通过后，实现 `grid.npz -> volume.nc` 和读回测试，固定使用本文件第 3 节成果。

### 阶段 C：API 和页面联通

页面从 API 获取 manifest 和 `.nc`，不得访问开发者手工放置的磁盘文件。

### 阶段 D：自动化证据

完成像素响应测试和证据目录。只有阶段 D 全部通过，才允许将结论写为：

```text
voxelgrid_netcdf_poc_verified
```

否则状态必须是：

```text
voxelgrid_netcdf_poc_failed
```

并附失败阶段和错误码。
