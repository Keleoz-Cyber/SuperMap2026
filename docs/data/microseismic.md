# 微震数据审计与标准化

> 数据契约通用规则见 [contracts.md](contracts.md)。本文区分两层事实：v0.2a 代码已经验证的审计事实；v0.5 已代码化、并以黄金表 SHA-256 锁定的局部三维派生与聚合规则（其人工来源证据仍保留在相邻只读资料目录）。

## 1. 当前结论

微震 v0.2a 已合并到 `main`（PR #2），完成数据审计与标准化底座：22 个 DAT 全部可读取、可追溯，2,006 条源记录进入标准表，三张标准表、一维累计距离、契约验证、问题清单和审计报告均可复现。

v0.5 已把第二案例派生闭环代码化：领域适配器从 22 个正式 DAT 重新派生局部三维样本，2,005 条有限记录经一次全局 3σ（样本标准差 `ddof=1`）剔除 80 条（深度 72、速度 8），保留 1,925 条候选；三 float 完全相等分组、算术平均聚合把 13 个冲突组（27 条组内记录）坍缩 14 条，得到 1,911 个唯一建模节点。派生结果与仓库外人工黄金表逐字节回归，黄金门禁未通过即阻断导入。当前浏览器产品使用内置的 1,911 节点 CSV 预置案例；DAT 派生服务和 `geomodeling microseismic derive` / `import-case` 作为维护与复现入口保留，不在普通用户主导航中暴露。微震随机森林仅为实验性选项；绝对地理配准仍未知，不能与电阻率或瓦斯空间叠加，发布登记保持 `manual_required`。

## 2. 原始文件读取

- 22 个正式 DAT 文件，共 **66,880 字节**，ASCII 空白分隔文本，表头为 `WL/2(km)  Vx`。
- 每个文件末尾含有 1 个 **NUL 终止伪行**，共 22 个；通用文本读取器因此可能误判为二进制。解析器显式识别 NUL 伪行且不计入样本，并在 `source_manifest.json` 中逐文件登记。
- 处理前后 22 个原始文件 SHA-256 完全一致；原始目录只读，不修改、不移动、不清洗。

## 4. W8 特殊值

`W8.dat` 源文件第 2 行 Vx 为旧式 Windows/MSVC NaN token `1.#QNAN0`。处理规则：

- 原 token 原样保留在 `velocity_samples.csv`，并保留原始 `WL/2(km)` token、文件名和源行号；
- `is_numeric_valid=false`，标准化数值字段为空，不进入 2,005 条有限统计；
- **不改 0、不静默删除、不自动插值覆盖**；
- 与论文所述“删除 80 条异常值”是两回事，不得混淆；
- 问题代码 `SOURCE_SPECIAL_NAN_TOKEN`。

## 8. 已确认的局部三维规则（v0.5 已代码化）

### 8.1 来源优先级

1. `三条测线 (压缩).jpg`：确定测线相交、平行关系和点序方向；
2. `点间距.xlsx`：确定测点间距离；
3. 论文：只作低置信背景参考，不能覆盖图片、DAT、Excel及本次明确确认的规则。

### 8.2 局部坐标约定

- 原点：W16，即L2/L3交点；
- X正向：沿L3由交点指向W24；
- Y正向：沿L2由W16指向W20；
- L1与L3平行；
- L1/L2交点为W5；
- W16到W17为110 m，W17到W5也为110 m，因此W17是两个交点的中点，W5坐标为 `(0, 220)`；
- W16位于W25/W26之间的中点，两点间距320 m。

由以上关系和Excel点间距得到的建模坐标如下，单位均为米：

| 测线 | 测点坐标 `(x_local_m, y_local_m)` |
|---|---|
| L1 | W1 `(400,220)`；W2 `(250,220)`；W3 `(150,220)`；W4 `(50,220)`；W5 `(0,220)`；W6 `(-50,220)`；W7 `(-200,220)`；W8 `(-450,220)`；W9 `(-750,220)` |
| L2 | W12 `(0,-995)`；W13 `(0,-720)`；W14 `(0,-445)`；W15 `(0,-195)`；W16 `(0,0)`；W17 `(0,110)`；W18 `(0,710)`；W19 `(0,1010)`；W20 `(0,1310)` |
| L3 | W24 `(960,0)`；W25 `(160,0)`；W26 `(-160,0)`；W27 `(-495,0)` |

这些是独立微震案例的局部工程坐标，不是EPSG坐标。将来如获得绝对控制点和方位角，应通过单独的配准变换生成绝对坐标，不覆盖这里的局部坐标。

### 8.3 Z、Vx、无效值和3σ筛选

- `WL/2(km)`直接按深度使用：`depth_m = WL_half_km × 1000`；
- 分析字段 `depth_m` 向下为正；若浏览器和SuperMap场景采用Z向上为正，另生成 `z_local_m = -depth_m`，必须保留字段名称和符号说明；
- Vx单位为 `km/s`，如派生 `m/s` 则乘1000且保留原始字段；
- W8中的 `1.#QNAN0` 不进入插值，不改0、不填补，保留原token、源文件和行号；
- 除这一条无效值外，其余2,005条有限数值进入3σ筛选输入集合；
- 对深度和Vx分别计算标准分数，任一绝对标准分数大于3时剔除；当前外部派生结果共剔除80条，其中深度原因72条、速度原因8条，保留1,925条；
- 被剔除记录单独保留`DEPTH_ZSCORE`、`VX_ZSCORE`、`FILTER_STATUS`和`FILTER_REASON`，不删除源记录、不修改DAT、不进行线性或5点IDW填补；
- 论文的“80条”数量与当前派生结果一致，但其“3.59%”与文件事实不一致：80/2,005约为3.99%；本项目采用实际计数，不照抄比例；
- W28以及没有正式DAT的点不进入建模。

当前外部派生文件（位于相邻只读资料目录，不提交Git）：

| 文件 | 记录数 | SHA-256 | 含义 |
|---|---:|---|---|
| `微震局部三维点_3Sigma_1925.csv` | 1,925 | `4F7A0886B54BB1776E9D7CA98299F8F86E67897BA19236FB151C3FC9E2AE1513` | 当前候选建模集合，L1/L2/L3 = 792/783/350 |
| `微震3Sigma剔除记录_80.csv` | 80 | `3752B2F62DE4E56121B7AF66C205CCF3984270D332636335E559E7E2745872B1` | 3σ剔除记录及原因，深度72、速度8 |

这些文件存在和iDesktopX人工复现曾经是唯一证据；v0.5 代码已用原始DAT和本节确认规则重新生成这两张表，并把上表 SHA-256 作为黄金门禁锁定（canonical UTF-8 BOM + CRLF，字节级一致）。哈希、计数或溯源字段不符即阻断导入；人工文件与 iDesktopX 复现保留为黄金回归的来源证据。

## 9. 来源冲突与当前处理

以下冲突并列保留，不得私自消解：

- **论文计数冲突**（`LINE_COUNT_CONFLICT`）：论文表格 `823/818/364=2,005` 与文件事实（源记录 `823/819/364=2,006`，有限数值 `822/819/364=2,005`）不一致；不得移动记录以迎合论文。
- **清洗比例冲突**（`CLEANING_RATE_CONFLICT`）：论文称删除80条异常值、占3.59%，但80/2,005≈3.99%；当前采用实际80条和3.99%口径，保留论文比例为冲突证据。
- **清洗方法冲突**（`CLEANING_METHOD_CONFLICT`）：材料分别出现线性插值与邻近5点IDW；本项目当前规则是3σ剔除但不填补，剔除记录单独保存。
- **W28 冲突**（`L3_W28_SOURCE_CONFLICT`、`L3_W28_INTERVAL_EXCLUDED`）：见第 5 节。

## 12. 复现命令

v0.2a 审计底座（保持兼容）：

```powershell
geomodeling microseismic inventory --config config/microseismic.yaml -o outputs/microseismic_verify
geomodeling microseismic parse --config config/microseismic.yaml -o outputs/microseismic_verify
geomodeling microseismic validate --config config/microseismic.yaml -o outputs/microseismic_verify
geomodeling microseismic run-audit --config config/microseismic.yaml -o outputs/microseismic_verify
python -m pytest -q -m local_data
```

v0.5 派生与导入（`--source-dir` 指向含 22 个正式 DAT 的目录）：

```powershell
geomodeling microseismic derive --source-dir <DAT目录> -o outputs/microseismic_v05_verify
geomodeling microseismic import-case --source-dir <DAT目录> --data-dir var/geomodeling
```

审计预期：22 个 DAT、22 个 NUL 终止符、2,006 源记录（823/819/364）、2,005 有效数值（822/819/364）、1 条无效数值（W8 `1.#QNAN0` 可追溯）、W28 不在正式集合、15 项契约检查通过、源文件 SHA-256 不变、无伪造 XY/Z，`validation_passed=True`。

派生预期：`rejected_3sigma=80`（深度 72、速度 8）、`accepted_modeling=1925`（792/783/350）、`modeling_nodes=1911`（13 冲突组、27 组内记录、坍缩 14）、accepted/rejected 两张 canonical CSV 的 SHA-256 与黄金表一致、`golden_passed=True`、`downstream_gates` 全部解除。

退出码语义：只有契约检查或黄金门禁失败（`validation_passed=False`）时CLI返回1，且仍尽量输出诊断报告；`validation_passed=True`时返回0。
