# GeoModelingPlatform 产品与开发蓝图

> 状态：2026-07-22 已确认的下一阶段设计。本文描述目标形态，除“当前已有能力”外，不代表功能已经实现。

## 1. 一句话定位

GeoModelingPlatform 是一个面向超图杯答辩的浏览器建模平台：用户上传 CSV、Excel 或受支持的专业文本数据，完成字段映射、质量校验、二维/三维插值调参、空间验证、成果展示和报告导出。

平台服务于多个**相互独立的案例**。电阻率、微震、瓦斯以及老师后续提供的属性数据可以复用同一套流程，但没有共同坐标依据时不得叠加，也不得描述为同一研究区的多源融合成果。

## 2. 已确认的产品边界

- 主要界面：独立浏览器系统，面向现场演示，不以命令行为最终交互入口。
- 核心闭环：上传 → 字段映射 → 校验 → 调参 → 空间验证 → 正式插值 → 二维/三维展示 → 导出。
- 计算与发布：Python 是可复现的主建模内核；SuperMap iServer 用于 GIS 服务发布；浏览器优先采用 SuperMap Web 技术展示。
- 插值方法：第一阶段实现 IDW 和普通 Kriging；DSI-like/GOCAD 只保留外部适配接口，不作为 MVP 前置条件。
- 调参方式：同时提供手动调参和一键批量搜索。第一版自动调参采用可解释、可复现的网格搜索。
- 坐标规则：每个案例独立登记坐标类型、单位和参考系。局部工程坐标可以建模和展示，但不能伪装成绝对地理坐标。
- 部署边界：优先保证单机答辩环境稳定；不做账户体系、多人协作、云端计费或生产级高可用。

## 3. 推荐架构

```text
浏览器前端
  ├─ 案例管理与数据上传
  ├─ 字段映射和数据质量面板
  ├─ 手动调参与自动搜索
  ├─ 候选模型排行榜
  └─ 二维地图 / 三维体元 / 切片 / 异常区展示
             │ HTTP / WebSocket
Python FastAPI 后端
  ├─ 复用现有 geomodeling 数据契约、审计和指标模块
  ├─ 二维/三维统一数据集服务
  ├─ 插值与调参任务引擎
  ├─ 空间交叉验证和成果登记
  └─ 报告、网格和交换文件导出
             │ adapter
SuperMap iServer
  ├─ 工作空间与数据服务发布
  ├─ 地图/三维服务发布
  └─ 浏览器 SuperMap Web 客户端访问
```

浏览器只调用平台后端，不直接耦合某一种插值实现。后端通过统一接口调用 Python 插值器，后续可以增加 iServer/GPA 或其他外部引擎适配器。即使 iServer 暂时不可用，数据校验、调参、模型评价和标准成果导出仍应能够完成；iServer 恢复后再发布已有成果。

## 4. 通用数据接入

上传向导不要求字段名必须为 `RHO`、`Vx` 或其他固定名称。用户需要完成以下映射：

| 角色 | 二维 | 三维 | 说明 |
|---|---|---|---|
| X | 必填 | 必填 | 数值坐标 |
| Y | 必填 | 必填 | 数值坐标 |
| Z/深度 | 不使用 | 必填 | 必须声明正方向和单位 |
| 属性值 | 必填 | 必填 | 本次待插值字段 |
| 属性单位 | 建议填写 | 建议填写 | 未知时显示“单位待确认” |
| 坐标类型 | 必填 | 必填 | 绝对 CRS 或局部工程坐标 |

首批格式：CSV、XLSX；DAT 由案例适配器转换成统一 `X/Y/Z/value` 表。上传后必须先生成预览、字段类型推断、空值与特殊值统计、重复坐标检查、范围检查和数据指纹，用户确认后才能启动插值。

老师后续提供的新属性数据原则上只新增字段映射和案例配置，不重写平台主流程。若其格式无法映射到二维 `X/Y/value` 或三维 `X/Y/Z/value`，再单独增加适配器。

## 5. 插值调参

### 5.1 手动调参

| 方法 | 第一阶段可调参数 |
|---|---|
| IDW | 幂指数、邻点数、搜索半径、最少邻点数、XY/Z 网格分辨率 |
| 普通 Kriging | 变异函数模型、邻点数、搜索半径、块金值/基台值/变程的自动拟合或手动值、XY/Z 网格分辨率 |
| 通用 | 输出范围、二维/三维模式、验证划分、随机种子、NoData规则 |

参数表单必须给出单位、推荐范围和影响说明，禁止只有参数名而没有解释。手动修改后可运行单组试验并加入候选列表。

### 5.2 自动调参

用户选择参数候选值或范围后，系统使用网格搜索批量运行。每个组合保存输入数据指纹、算法、参数、验证划分、运行时间、覆盖率、NoData数量和误差指标。任务可取消；单个组合失败不能抹掉已经完成的组合。

模型排行榜至少显示：MAE、RMSE、R²、Bias、覆盖率、NoData数量和运行时间。不同模型必须在同一个公共有效验证集合上比较，不能因某个模型少预测困难点而虚假提高精度。

### 5.3 空间验证

空间数据不能默认随机拆点验证。平台根据数据形态提供：

- 二维散点：空间网格分块留出；
- 三维规则/柱状数据：完整 XY 空间柱留出；
- 测线数据：按测点或整段测线留出，避免同一测点的相邻深度同时进入训练和验证。

系统给出“综合推荐”，但不宣称存在适用于所有业务目标的唯一最优模型。用户仍可基于精度、覆盖率、平滑程度和运行时间选择正式模型，选择理由写入成果元数据。

## 6. 首批独立案例

### 6.1 电阻率

- 数据形态：局部工程坐标中的三维 `X/Y/Z/RHO`。
- 已有基础：数据契约、空间柱验证、五组候选模型指标、SuperMap 正式体元成果。
- 第一批页面：模型排行榜、参数对比、体元展示、水平/垂直切片、阈值过滤。
- 边界：RHO单位和绝对 CRS 未确认；不得与另外两个案例直接叠加。

### 6.2 微震速度

- 数据形态：局部测线坐标中的三维 `X/Y/Z/Vx`。
- `W16` 为 L2/L3 交点和局部原点；X正向沿L3指向W24，Y正向沿L2指向W20；L1与L3平行，L1/L2交点为W5，W5的Y坐标为220 m。
- 点间距以 `点间距.xlsx` 为准；`WL/2(km)` 按深度换算 `depth_m = WL_half_km × 1000`；分析字段深度向下为正，三维显示可另生成 `z_local_m = -depth_m`，不得静默改符号。
- Vx单位为 km/s。W8的 `1.#QNAN0` 不进入模型、不改0、不填补，但保留源文件和行号。2,005条有限值再按已确认的3σ规则剔除80条（深度72、速度8），形成1,925条当前建模候选，再经三 float 完全相等分组的算术平均聚合得到1,911个唯一建模节点；**该流程已在 v0.5 进入仓库代码**（领域适配器 + 黄金门禁 + 浏览器向导与 CLI 双入口），原始人工派生表保留为黄金回归来源。
- W28及没有正式DAT的点不进入建模。
- 边界：只有局部坐标，不得与电阻率或瓦斯空间叠加。

### 6.3 瓦斯

- 当前试验数据形态：西安1980、6°分带、第20带、中央经线117°的三维候选点，带号坐标按EPSG:2334工作。
- 现有派生表保留58条合格样本、28个位置；`Z = SURF_Z - (END_DEPTH - THICKNESS/2)`，其中`SURF_Z`来自现有DEM派生表。
- 该Z把钻孔近似为竖直孔，只能作为当前实验假设，不能冒充已经核实的钻孔轨迹或严格地质高程。
- 三维点已在iDesktopX平面场景显示；IDW体元能够生成，但加入三维场景会触发iDesktopX原生崩溃。因此瓦斯保留数据和接口，待平台主干完成后再排查，不作为首个答辩闭环。
- 完整口径见[data/gas.md](data/gas.md)。

## 7. 浏览器主要页面

1. **案例首页**：电阻率、微震、瓦斯和新建案例入口，各自显示坐标类型和数据状态。
2. **上传向导**：文件选择、工作表选择、字段映射、单位/坐标声明、质量预览。
3. **调参实验室**：算法、参数范围、验证方式、运行队列和失败信息。
4. **模型对比**：排行榜、指标解释、覆盖率、参数快照和正式模型选择。
5. **成果场景**：二维地图或三维体元、切片、透明度、颜色表、阈值过滤和测点叠加。
6. **证据与导出**：输入哈希、处理记录、参数、指标、失败证据以及 CSV/JSON/Markdown/PDF 成果。

```text

```

目录包含 `bin/startup.bat`、`bin/shutdown.bat`、内置JRE和`webapps/iserver`。根目录构建标识为 `BUILD-12.1.0.0-260626-9297-130896`，对应iServer 2026（12.1.0.0）。产品包中的`iClient/for3D/webgl/examples/examples.html`只是“不包含iClient”的占位提示，不能当成可用SDK。

- 最新官方中文帮助入口：<https://help.supermap.com/iServer/1201/zh/>
- 本机启动脚本：`<iServer目录>\bin\startup.bat`
- 本机停止脚本：`<iServer目录>\bin\shutdown.bat`
- 默认管理入口：<http://localhost:8090/iserver/admin-ui/home/>

网址路径中的`1201`不作为帮助文档过期或版本不匹配的判据。开发和接口联调以该最新官方帮助及本机实际REST能力为准。iServer版本、许可模块、管理员初始化和可用三维/空间分析服务必须通过运行时探测登记，不能只根据安装目录推断。

2026-07-22核对时8090端口未监听，当前尚无“已启动、已许可、已发布”的运行证据。REST、OpenAPI、三维缓存发布和iClient3D的具体阅读顺序见[SuperMap集成说明](supermap-integration.md)。

项目代码不得硬编码本机绝对路径。后续使用环境变量（建议 `SUPERMAP_ISERVER_HOME`）或本地不入库配置指定该目录；仓库文档中的绝对路径仅记录当前答辩开发机环境。

## 9. 失败处理与证据

- 原始资料只读；派生文件写入项目的 `outputs/`、`artifacts/`、`logs/`。
- 上传、解析、校验、插值、发布是独立状态；校验通过不等于插值成功，插值成功不等于iServer发布成功。
- 特殊值、NoData、失败参数组合和空SuperMap数据集必须显式登记。
- 失败任务保留错误信息和可重试参数，不覆盖已有正式成果。
- 所有正式成果保存数据哈希、字段映射、单位、坐标声明、算法参数、软件版本、指标和人工选择理由。

## 11. MVP验收标准

- 能上传一份新的CSV或XLSX，并将其映射为二维或三维属性数据；
- 错误字段、无效数值、重复坐标和未知单位有清楚提示；
- 能手动运行至少一组IDW和Kriging参数；
- 能对候选参数执行网格搜索和空间验证，输出可解释排行榜；
- 能选择正式模型并生成二维或三维可视成果；
- 能记录并显示完整证据链；
- 能将至少一个电阻率正式成果发布到本机iServer并由浏览器访问；
- 电阻率、微震、瓦斯保持独立案例，不出现无依据的空间融合。
